# geo-case-archive · 微信群一键归档（案例生产过渡方案）

> 融合自 WorkBuddy 讨论产出（2026-08-29）。
> 背景：小程序冻结新功能，但案例生产不能停；多数门店用微信群记录维修过程。
> 方案：不替代微信群，做它的「沉淀出口」——师傅只做「转发/复制」，结构化、核验、归档由盈简完成。

## 文件

| 文件 | 用途 |
|---|---|
| `archiver.html` | 本地解析器：粘贴微信复制的群聊文本 → 自动识别发言人/内容/[图片] 计数 → 生成六字段案例草稿。浏览器直接打开，数据不出本机 |
| `微信群归档操作手册.md` | 三条合规路径（复制粘贴 / 截图投递 / 逐条转发）、合并转发坑、六字段标准、三级信源标签、归档节奏 |
| `案例页模板.html` | 案例页示范（六字段事实卡 + 时间线 + 照片墙 + 车主确认 + 免责声明 + JSON-LD），与 `h5/case/` 结构对照参考 |

## 与仓库现有能力的关系

- 六字段（车型/症状/方案/工期/价格区间/照片）与 `h5/fixtures/case_*.json` 案例结构对齐；
- 三级信源标签（商家提供/实地核验/车主确认）对应 §2.1「车主确认留痕」；
- 归档产物 → 经审核 → 进 `geo.simplewin.cn` 案例站（现有 H5 发布链路）。

## 红线

- 禁用微信群自动化插件/机器人（封号风险）；
- 禁用「合并转发」（折叠卡片内容拿不出来），用「逐条转发」；
- 案例必须真实发生，证据链完整才发布；宁缺毋滥。
