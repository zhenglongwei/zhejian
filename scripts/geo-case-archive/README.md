# geo-case-archive · 微信群归档转案例

> 融合自 WorkBuddy 讨论产出（2026-08-29），v0.2 于 2026-08-31 按《22_微信群归档转案例目标定义》重写，
> 2026-09-02 按「内部版退役」决策改为公开版单版本口径。
> 背景：小程序冻结新功能，但案例生产不能停；多数门店用微信群记录维修过程。
> 定位：**不替代**微信群，做它的「沉淀出口」——师傅本来就在群里说话，说话即记录，商家零额外填写。

## 怎么用

只有一个版本：**公开页** `brand-web/archive.html`（官网 `/archive.html`）。

- 门店老板、任何访客：不用密钥，按 IP 限次。
- 我们自己：页面右上角「⚙ 接口设置」填一次归档密钥（`WECHAT_ARCHIVE_TOKEN`），
  请求头带 `x-archive-token` 即完全免扣配额（不限次），存本机浏览器。

| 打开方式 | 地址 | 说明 |
|---|---|---|
| 线上 | `https://simplewin.cn/archive.html` | 页面在官网，接口走 `geo.simplewin.cn` |
| 本地预览 | `cd backend && npm run archive:local` | 8848 端口，页面和接口同源，最省事 |

公开页是获客钩子：自动脱敏（含手动补充打码词）、生成九段式案例、带草稿箱；
跑完给出「这篇案例已经合格了，但它现在还只是一段文字」的转化卡，引到体检和榜单。

## 三步流程

```text
① 粘贴群聊（纯文本，含 [图片]/[语音] 占位）——认错发言人、并错行在框里直接改；
   可补充手动打码词
        ↓
② 生成案例：网站自动打码（手机号/车牌/身份证/VIN/发动机号/住址/昵称等）
   → 大模型理解整合 → 直接产出九段式案例（内部仍走事实层闸门，页面不展示）
        ↓
③ 直接改案例正文：留白处会提示「群里没提」，存疑项折叠轻提示（仅作者可见）
```

- 脱敏由网站提供，**不是**让用户在自己电脑先脱敏（2026-09-02 老板定）。
- 中间的解析/事实层不再单独做成表单步骤——页面直接从粘贴跳到案例。
- 案例来源标签固定为：**微信群沟通记录转化 · 已自动脱敏**。
  平台只标注来源、不背书真实性，可信度由读者或 AI 自行判断。

## 文件

| 文件 | 用途 |
|---|---|
| `backend/src/services/wechat-archive.service.js` | 解析 / 脱敏 / 事实提取 / 案例生成（generateCase 一步串联）/ 风控扫描 |
| `backend/src/routes/public-wechat-archive.js` | `/api/v1/public/wechat-archive/*`，不要密钥按 IP 限次 + 全局总闸；`/generate` 一次扣 2 个主配额；带 `x-archive-token` 密钥头则免扣 |
| `brand-web/archive.html` + `brand-web/js/archive.js` | 公开页（三步流程 + 草稿箱，浏览器本地留存） |
| `backend/scripts/smoke-wechat-archive.js` | 服务层冒烟（默认不联网，大模型用桩） |
| `backend/scripts/smoke-archive-page.js` | 公开页冒烟：node 里跑一遍页面，防「一打开就报错」 |
| `backend/scripts/serve-archive-local.js` | 本地预览服务（8848） |
| `微信群归档操作手册.md` | 三条取图路径（截图投递 / 逐条转发 / 电脑另存）、命名规范 |
| `案例页模板.html` | 案例页示范（与 `h5/case/` 结构对照参考） |

## 硬限制（页面顶部已明示，不能只写手册）

| 内容 | 能否拿到 | 处理 |
|---|---|---|
| 文字 | ✅ | 直接解析 |
| 图片 | ❌ 只有 `[图片]` | 必须单独导出（操作手册三条路径） |
| 语音 | ❌ 只有 `[语音]` | 手机长按 → 转文字 → 把文字补进对应消息 |
| 视频/文件 | ❌ 只有占位符 | 同图片 |
| 发言人昵称 | ✅ 含隐私 | 自动脱敏为 发言人A/B/C |

## 红线

- **自动脱敏再送大模型**：页面自动打码 + 手动补充打码词，接口侧再兜一遍；
- **不许编造**（07 §1.3）：群里没说的一律留空，推断的必须进存疑项——这是**转换忠实度**，
  不是平台背书真实性——平台只标注来源（2026-09-02 老板定）；
- **公域藏价**（07 §4.3）：金额可提取留档，绝不进公开文案，生成后还有一道风控扫描；
- **不做规则匹配提取**（22 D3）：群聊没有范本，17 的检查项只是喂给模型的「事实清单」；
- 禁用微信群自动化插件/机器人（封号风险）；禁用「合并转发」（折叠卡片取不出内容）。

## 自测

```bash
cd backend
node scripts/smoke-wechat-archive.js                       # 解析/脱敏/限额/前后端规则是否漂移
node scripts/smoke-archive-page.js                         # 公开页在 node 里真跑一遍
WECHAT_ARCHIVE_SMOKE_LLM=1 node scripts/smoke-wechat-archive.js   # 真调一次大模型
npm run archive:local                                      # 起本地预览，8848
```

**改了脱敏规则要同时改两处**：`backend/src/services/wechat-archive.service.js` 的 `MASK_RULES`
和 `brand-web/js/archive.js` 里的同名数组。`smoke-wechat-archive.js` 会逐条比对，
漂移了直接失败——浏览器那份是「原文不出本机」的唯一保障，少一条规则就是明文外泄。

## 公开试用的三道保险

| 保险 | 行为 |
|---|---|
| 每 IP 每天 20 次主配额（`WECHAT_ARCHIVE_PUBLIC_PER_IP`） | 用完返回 429，文案引导联系我们要专属入口；`/generate` 一次扣 2 个 |
| 解析单独宽松计数（60 次/天） | 解析不调模型，不该占用主配额 |
| 全局总闸 300 次/天（`WECHAT_ARCHIVE_PUBLIC_DAILY_CAP`） | 一人公司的保险丝；总闸满了不误扣个人额度 |
| `WECHAT_ARCHIVE_PUBLIC_ENABLED=false` | 整体拉闸，接口全停（`/status` 仍可问，页面要据此显示「已关闭」） |

上游（大模型厂商）的报错原文只进服务端日志，公开接口统一回「服务暂时不可用，稍后再试」——
不能让外人知道我们用的哪家、密钥配没配对。带密钥头的请求（我们自己）照实说，方便排查。
