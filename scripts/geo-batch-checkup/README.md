> 融合自 WorkBuddy 讨论产出（2026-08-29），与 backend 两步体检互补，见

## 分工

| 场景 | 用哪个 |
|---|---|
| 单店深检 / 拜访演示 | `POST /api/v1/public/geo-check`（backend，已上线） |
| 全城批量扫描 / 榜单 / 白皮书数据 | **本目录 `checkup.py`** |

## 用法（Python 3.10+）

```bash
# 跑体检（360 搜索后端，默认每店 10 问）
python checkup.py scan  --shops 门店表.xlsx --limit 61 --backend so
# 生成榜单 + 每店一页报告
python checkup.py report --run-id <id>
# 只看门店清单
python checkup.py shops  --shops 门店表.xlsx
```

- 后端可插拔：`so`（360，默认，稳定）/ `baidu`（易触发验证码）/ `bing`（易降级，慎用）/ `mock`（离线联调）。
- 脚本内置**降级检测**（不同问题返回同批结果即告警）与**缺分自动补算**（report 时自动重算漏分门店）。
- 五维打分（0–100）：提及 30 / 位次 25 / 准确 20 / 地基 15 / 内容 10。规则即「盈简·门店 AI 可见性模型」的批量版。

## 口径红线

- 分数是**抽样检索结果**，不是全网公证；
- 结论口径：「门店活在工商档案里，死在车主提问里」——价值主张而非攻击性表述；
- 榜单规则公开、可复算；盈简自己的官网可见性也按同一套规则打分。
