# 2026-11-17 交车新增「施工时间」与托管 FAQ 施工时长

> 状态：生效
> 生效：2026-11-17

## 1. 变更

> 局部已废止：第 1 条「单位小时」的输入与展示口径，见 `docs/changes/20261118-施工时长按天与小时填写.md`；默认值、<1 小时提醒与托管引用规则继续生效。

| # | 旧口径 | 新口径 |
| --- | --- | --- |
| 1 | 交车节点只有质保、交付人、交车时间、交车里程；案例没有「施工时间」这个指标 | 交车节点新增必填 **「施工时间」**（单位小时，最多两位小数），存 `content.workDurationMinutes`（整数分钟） |
| 2 | — | 默认值 = **交车时间 − 接车时间**（`finishedAt` − `receivedAt`）；商家可改，**手改过就不再被默认值覆盖**（改交车时间也不覆盖） |
| 3 | 交车提交只做必填非空拦截 | 未填「施工时间」→ 拦截并提示「请填写施工时间」；已填但 **< 60 分钟** → 先弹「施工时间明显偏短」重点提醒（确认无误 / 去修改），确认后再走原「确认交车」弹窗 |
| 4 | 托管文案的 FAQ 覆盖角度无施工时长；提示词禁止编造时间，但无可用事实 | FAQ 覆盖角度加入「施工时长」；问「这类项目要做多久」时，先给行业通行量级并注明因车型/车况而异（非本店承诺），再落到本单用时；**只能引用 `facts.finish.workDurationText`**，无值不得编时间 |
| 5 | — | 施工时间取值顺序：`delivery_photos` 节点 > `repair_report` 节点；0 表示未填，事实包输出空串 |

## 2. 影响

- 字段：新增 `workDurationMinutes`（交车节点 / 完工确认 `content`，年/月/日无关，纯分钟数）；`mergeNodeContent` / `normalizeNodeContent` 白名单同步
- 接口：`completeFlowNode` 的 `delivery_photos` 接收并透传 `workDurationMinutes`；老客户端不带该字段时 `keepFilledDeliveryPatch` 保留已填值
- 代码：
  - `utils/service-flow-docs.js`、`backend/vendor/shared/utils/service-flow-docs.js`（`parseWorkDurationMinutes`、`workMinutesBetween`、归一/合并/交车必填、报告字段）
  - `backend/src/services/service-flow.service.js`（payload 映射、空值兜底）
  - `backend/src/utils/case-geo-factpack.js`（`facts.finish.workDurationMinutes` / `workDurationText`）
  - `backend/src/prompts/hosted-storefront-copy-v0.md`（FAQ 施工时长口径）
  - `packageMerchant/pages/album/flow/index.js`、`index.wxml`（输入、默认值、保存、<1 小时提醒）
- 文档：`04_维修过程相册/29_节点AI分析_单据结构与状态流转梳理.md`（交车节点内容与提交门槛表补「施工时间」）

## 3. 取代

无。新增字段与新增提醒，不推翻既有交付确认口径。
