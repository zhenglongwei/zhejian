# 2026-11-18 施工 AI 带车型做配件适配核对

> 状态：生效
> 生效：2026-11-18

## 1. 变更

| 旧口径 | 新口径 |
| --- | --- |
| 施工 AI 的参考材料里没有车型，判据只有留证与工序；换件型号对不对得上这台车，模型看不到也无从出声 | 参考材料新增「车辆」：品牌 / 车系 / 年款 / 完整车型 / 排量 / 发动机 / 变速箱 / 里程，以相册登记的 `album.vehicleJson` 为准（VIN 解析会填排量与变速箱），单据字段只补空；施工提示词由六步扩为七步，第 7 步「适配核对」只依据附图里真实读到的配件文字（包装标签、件体钢印、型号、OE 号、适用车型）与本车比对，按「已核对一致 / 需核对 / 疑似不符」三档输出 |

边界（都不新增数据库字段，不建配件适配库）：

- 「车辆」为空、或图上读不出任何配件文字 → 适配核对返回空数组，禁止凭项目名或品牌猜型号。
- 适配疑点不改完成判定：「已完成 / 待确认」仍只看工序与留证，型号问题单独成行。
- 只在「疑似不符」时给店员一句核对提醒；「需核对」只把读到的型号原样抄出来，不编结论。
- 意见是店员侧提示，不写进施工说明、不进车主端与公开案例。
- 最多 4 条，疑似不符优先于需核对；同一项目上「已核对一致」压掉「需核对」。
- 车牌、VIN、车架号不进提示词；图片仍按原规则先打码再送模。

## 2. 影响

- 文档：`docs/04_维修过程相册/29_节点AI分析_单据结构与状态流转梳理.md` §0.3、§1.4（任务已改写为与代码一致的七步，旧「提示词」段保留为早期示意）。
