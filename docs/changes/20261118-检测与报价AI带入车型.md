# 2026-11-18 检测与报价 AI 带入登记车型

> 状态：生效
> 生效：2026-11-18
> 续：`20261118-施工AI带车型做适配核对.md`（那一篇先把车型送进施工上下文）

## 1. 变更

| 旧口径 | 新口径 |
| --- | --- |
| 只有施工 AI 看得到车型；检测的「参考材料」只有客户诉求，报价 facts 里连登记车辆都没有 | 检测提示词的参考材料加「车辆」，报价 AI（首次与补充）的 `facts.body` 加 `vehicle`，字段与施工同一套锚点：品牌 / 车系 / 年款 / 完整车型 / 排量 / 发动机 / 变速箱 / 里程，以 `album.vehicleJson` 为准，单据字段只补空 |
| 车型进了上下文却没有用法，等于白送 | 车型**只用来收窄，不用来加戏**：检测第 1 步用它排除与这台车不相干的可能和检查项（登记 8AT 就不写 CVT 特有故障）；报价用它校验行项与油品规格是否对得上这台车，对不上就在 reason 里写「需核对」。两处都禁止凭车型新增没有本单依据的结论或价格 |

边界：

- 相册既没品牌也没车系 → 锚点为 `null`，「车辆」整块为空，模型无从按车型猜。
- 检测里参考材料仍只给第 1 步用；给照片起项目名不看车型（原「给照片归类时不要用它」不变）。
- 车牌、VIN、车架号不进任何提示词，它们只是打码对象；图片送模前的打码规则不变。
- 商家端界面本轮不改，报价行文案与检测意见的展示结构不变。
- 施工提示词再加一条硬规则 9：「车辆」也用于收窄其它各步——与这台车的排量、发动机、变速箱形式对不上的工序、油品、拍照建议一律不写，收窄只做删除。施工意见 `schema` 与指纹不升版（这条只会减少内容，不会让旧结果变得不正确），存量不额外提示刷新。

## 4. 泛化定档：车型与工艺能带多远

问：意见能不能结合车型与工艺多说一点（施工好不好不只取决于配件对不对，还取决于做法）。定档如下。

- **不新增「工艺意见」槽**。理由：施工面板已经有报价项建议、证据、填写建议、拆分、新增、提醒、适配七块，再加一块会稀释重点；更关键的是「建议描述 / 补充建议」这些口会被一键应用进施工说明，最终车主看得到——通用知识落在那里，等于让模型把没人验证过的扭矩、固化时间写进单据。
- **车型只用于收窄**：排除与这台车不相干的可能原因（检测）、不相干的行项与油品规格（报价）、与动力总成对不上的工序与拍照建议（施工）。收窄是删除动作，不引入新断言，因此不动「不编」这条线。
- **范围收在施工**：检测、报价本轮只带上下文与收窄规则，不出新意见类型。将来若要工艺提醒，先在施工单点试，呈现与「适配」合成工单项卡片同一行，且不可应用、不改完成判定。
