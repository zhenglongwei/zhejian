# 交车确认精简 + 交车节点补传图按模型判定并入施工章

## 变更

- 旧：店员点「确认交车」后，才通过提示语/文案提醒核对交车信息；交车节点（`delivery_photos`）照片完全不进入公开案例；前一版按「施工项验收」`acceptanceItems[].kind !== 'exterior'` 取图并入施工章。
- 新：
  1. 确认交车前只弹一个简短确认：「提交后将无法修改，是否确认」。质保期限、交付人、交车时间、交车里程、施工说明与图片等完整性由必填项非空校验拦截，不再写进弹窗文案。未拍外观照仍按原逻辑传 `exteriorPhotoWaived`。
  2. 交车节点没有「施工项验收」专门节点，只有一个「交车外观照」上传入口（外观行，最多 4 张）；门店可能把施工验收照片也从这个入口传上来。
  3. 托管生成时由模型逐张判断交车节点图片归属（施工证据 / 整车外观 / 其他）；只有「施工证据」且能对上施工章或报价行项目名的图，才并入施工章（同名追加、缺项补出）；整车外观照仍只留档，不进施工章。判定结果落 `hostMeta.geoDraft.deliveryPhotoRoles`，公开时随 `geoLayer` 固化。
  4. 判为施工证据的交车图进入可公示照片集合，正常参与打码与公开质检计数。
  5. 商家流程、流程节点 AI 分析规则均不改；只有托管生成/预览/公开页读取时使用该判定。

## 影响

- 小程序 `packageMerchant/pages/album/flow/index.js`：交车确认弹窗精简为「提交后将无法修改，是否确认」
- `backend/src/utils/host-delivery-photo-roles.js`：交车入口取图、判定结果归一化与读取（新增）
- `backend/src/utils/public-service-flow.js`：`mergeDeliveryWorkPhotos` 改为按 `deliveryPhotoRoles` 并入
- `backend/src/utils/flow-public-media.js`：交车节点只放行判为施工证据的图进入可公示集合
- `backend/src/services/case-hosting.service.js`：托管生成时调用识图模型判定归属，草稿/公开层落 `deliveryPhotoRoles`
- `backend/src/services/content.service.js`：公开页把 `deliveryPhotoRoles` 传入章节构建

## 取代

- 取代前一版「交车节点按施工项验收行取图」的口径（交车节点并无该节点）
- 取代旧「交车照片一律不公开」口径
- 取代「交车后才提示核对」与长文案完整性提醒
