# 交车完整性提醒前置 + 交车节点施工图并入施工章

## 变更

- 旧：店员点「确认交车」后，才通过提示语/文案提醒核对交车信息；交车节点（`delivery_photos` / `repair_report`）的照片完全不进入公开案例。
- 新：
  1. 确认交车前弹窗「确认交车信息完整」，列出施工说明与照片、质保、交付人、交车时间与里程、外观照；取消则回去补，确认后才提交。提交后 toast 固定为「交车已完成」，不再做事后核对提醒。
  2. 托管预览与公开案例读取交车节点时，把「施工项验收」照片（`acceptanceItems[].kind !== 'exterior'` 且有图）并入施工章：同名施工项追加图片，施工章缺失的项目补成新项目；整车外观照与未施工项（`unbuiltReason`）不收。
  3. 这些交车施工验收图进入可公示照片集合，正常参与打码与公开质检计数；整车外观照仍只留档。

## 影响

- 小程序 `packageMerchant/pages/album/flow/index.js`：交车确认前完整性弹窗（原外观照弹窗合并进同一确认）、交车完成 toast
- `backend/src/utils/public-service-flow.js`：`mergeDeliveryWorkPhotos`
- `backend/src/utils/flow-public-media.js`：交车节点只放行施工验收图进入可公示集合
- 公开页与托管预览共用同一份 `serviceFlow.chapters`，两端同时生效

## 取代

- 取代旧「交车照片一律不公开」口径（`flow-public-media.js` 原 `PRIVATE_FLOW_KINDS` 注释）
- 取代「交车后才提示核对」的交互
