# 2026-11-16 托管预览文案缓存与复用

> 状态：生效
> 生效：2026-11-16

## 1. 变更

| # | 旧口径 | 新口径 |
| --- | --- | --- |
| 1 | `generate-geo` 每次预览都重新找文案来源：有 `archiveCopy` 就用，没有就跑大模型 / 规则兜底 | 预览先查已有产物，按优先级复用：<br>① 已公开案例内容（`hostMeta.geoLayer`，已确认上店页那版）<br>② 上次托管的店页草稿（`hostMeta.geoDraft`，事实指纹一致）<br>③ 历史遗留的 `archiveCopy`（旧交车 AI 分析写入；现由托管生成覆盖，仅 summary + faq）<br>④ 都没有才调大模型，失败再规则兜底 |
| 2 | 生成结果只写 `archiveCopy`（仅 summary + faq），`geoDraft` 不参与下次复用，维修实录（nodeStories）在第二次预览会丢 | 生成后同时写 `hostMeta.geoDraft` 与 `archiveCopy`，并给草稿打事实指纹 `factFingerprint`；第二次预览直接整份复用（含 nodeStories） |
| 3 | 事实变化后仍可能命中旧文案（`archiveCopy` 无指纹校验） | 草稿指纹 = `buildCaseFactPack(flowNodes)` 的 SHA1；指纹不一致才重新生成。历史草稿无指纹时按可复用处理，避免一次性全量重跑 |
| 4 | 已公开相册再次调 `generate-geo` 会把 `publicPublishStage` 从 `published` 降为 `awaiting_geo_confirm` | 已公开状态不再回退；复用已公开内容时保持 `published` |
| 5 | `forceRegen` 与普通预览同一套来源 | 不变：手动「重新生成」跳过全部缓存，重新跑模型；已上线内容在再次确认公开前不受影响 |

只做复用，不改生成口径：文案模型仍只吃店员确认过的项目文本（见 `docs/changes/20261116-托管文案只用人工项目文本.md`）。
