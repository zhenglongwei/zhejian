# 2026-11-17 公开案例增加章节衔接语（把节点讲成人话）

> 状态：生效
> 生效：2026-11-17

## 1. 变更

| # | 旧口径 | 新口径 |
| --- | --- | --- |
| 1 | 公开案例按章节机械罗列证据，读者看不出「哪个环节发生了什么、为什么做」 | 每个章节增加一句大模型生成的衔接语（`chapterNarratives[]`，按 `chapter.id` 对齐），把节点顺序讲成一篇连贯的案例 |
| 2 | 托管预览的模型调用只产出 `summary` / `nodeStories` / `faq` | 同一次调用额外产出 `chapterNarratives`；模型输入新增 `chapters` 清单（章节 id、类型、标题、已确认的检测项/项目名） |
| 3 | 章节标题固定为「方案 / 施工 / 完工」等 | 标题保持简短，但补充报价按前一章节类型区分：前一章是施工→「施工中新发现」，前一章是完工→「交车时补充」，其余→「补充报价」 |
| 4 | 已冻结快照只保存 `nodeStories` | `geoLayer` 同时保存 `chapterNarratives`；公开页与预览页共用同一份快照内容 |
| 5 | 衔接语完全依赖模型逐章输出，模型漏写某章（如补充报价）时该章无导语 | 提示词要求「有项目/检测项的章节必须逐条输出」；仍缺时用已确认项目名拼一句兜底导语（`buildFallbackChapterNarrative`），不引入新事实；已有模型文案优先，不覆盖 |

约束：衔接语只允许复述已确认事实，**不得改项目名称、图片与说明文案**；校验时按当前章节 id 过滤，旧内容残留的 id 直接丢弃。
