# 2026-11-18 案例评价入口与筛选口径

> 状态：生效
> 生效：2026-11-18
> 适用：车主服务相册筛选、服务进度页评价入口、追评、商家端评价筛选、H5 案例评价区

## 1. 变更

| # | 旧口径 | 新口径 |
| --- | --- | --- |
| 1 | 车主端有独立的「我的评价」入口 / 页面 / 接口 | 取消独立入口与页面，评价历史由服务相册「已评价」筛选承载；`GET /api/v1/user/album-reviews` 下线 |
| 2 | 服务相册筛选为「已完成 / 全部」等，默认展示最近修改的 3 份；再次点击「全部」会回退成 3 份 | 筛选改为「最近 / 进行中 / 待评价 / 已评价 / 全部」；「最近」为默认且固定为最近修改的 3 份；再次点击当前项保持当前筛选，不再回退 |
| 3 | 「已完成」一个筛选项 | 拆成「待评价」（已完工未评价）与「已评价」（已完工已评价） |
| 4 | 服务进度页底部评价按钮统一为「去评价」 | 未评价显示「去评价」，已评价显示「查看评价」；两者都进入评价页，已评价时展示评价内容与追评 |
| 5 | 评价提交后不可追加 | 「已评价」列表与服务进度页支持追评（文字 + 最多 3 张图） |
| 6 | 商家端只能看状态文字，无法筛选评价、角标不可点；邀请按钮点击会冒泡跳相册详情 | 商家端新增「全部评价 / 待评价 / 已评价」筛选；评价角标可点击进入评价详情；邀请按钮用原生 `catchtap` 阻止冒泡并改版样式 |
| 7 | H5 案例评价区对纯评分评价只显示数字（如「5」） | H5 评价区增加综合评分概览（平均分 + 星级 + 条数）、分维度星级行（维修服务 / 过程相册），纯评分评价补「车主仅评分，未填写文字评价」占位文案 |

## 2. 影响

- 接口：
  - 移除 `GET /api/v1/user/album-reviews`（`backend/src/routes/user-service-albums.js`、`backend/src/services/album-review.service.js`）
  - 商家相册列表返回项新增 `reviewId`（`backend/src/services/service-album.service.js`）
- 代码：
  - `utils/owner-album-rank.js`（`recent/active/pending/reviewed/all`、`sortRecentOwnerAlbums`、`nextOwnerHubFilter` 不再回退）
  - `pages/mine/index.js`、`index.wxml`、`index.wxss`（五个筛选项、默认「最近」、空态文案）
  - `pages/album/detail/index.wxml`（底部按钮按 `pendingOwnerReview` / `hasOwnerReview` 切换）
  - `constants/mine-menu.js`、`app.json`、`services/album-review.js`（清理「我的评价」入口与页面）
  - `packageMerchant/pages/album/list/*`（评价筛选、角标跳转、邀请按钮冒泡与样式）
  - `h5/shared/case-render.js`、`h5/shared/case-page.css`、各 H5 HTML 的 `?v=` 缓存版本号
- 字段：`ServiceAlbumReview` 不变；车主端继续使用后端计算的 `reviewEligible / pendingOwnerReview / hasReview`

## 3. 取代

- 局部作废：`docs/00_设计规范/02_组件API规范.md` 中评价卡片使用场景里的「我的评价列表」；组件本身继续用于门店 / 服务 / 案例详情。
- `docs/02_用户端小程序/12_我的页面与账户体系.md`「我的评价不展示」与本次口径一致，继续生效。
