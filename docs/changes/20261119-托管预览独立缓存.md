# 2026-11-19 托管预览独立缓存

> 状态：生效
> 生效：2026-11-19

## 0. 为什么

产品预期是「除了首次，之后每次托管预览都直接吃首次的大模型结果，秒回」。实测每次预览都要十几秒，预发日志逐段计时后的结论：

- 文案缓存本身命中了，不慢；打码对账 `needLlm 0`，也不慢。
- 慢在 `generateHostedGeoDraft` 尾部的 `resolveDeliveryPhotoRoles`：复用的 `geoLayer` 是逐字段重建的，把 `deliveryPhotoRoles` 丢了 → 每次都重新让视觉模型看一遍交车补传图（13–15s）。
- 判为「全外观」的空结果从不落库，等于每次都当没判过。
- 预览页允许改摘要 / 问法，但这些人工稿从不持久化：离页再回来就丢，同意公开前那一段尤其明显。

所以这不是「补一行短路」能收的，需要把预览产物放进一张生命周期独立于托管开关的表，并给人工改动留出落点。

## 1. 变更

| # | 旧口径 | 新口径 |
| --- | --- | --- |
| 1 | 预览产物混在 `hostMeta`（`geoDraft` / `geoLayer`）里，靠 `pickReusableHostedGeoDraft` 挑 | 新增独立表 `host_preview_caches`（按 `albumId` 一份），三个分区各自失效：<br>`copyJson` + `copyFingerprint`（大模型文案）<br>`photosJson` + `photoFingerprint`（交车图归属判定）<br>`editsJson`（商家人工覆盖稿，永不过期） |
| 2 | 交车图归属每次预览都重新看图（约 15s）；空结果不落库 | 判定结果按图集合指纹落库，**空数组也是有效判定**；`resolveDeliveryPhotoRoles` 命中即直接返回，不再调模型 |
| 3 | 商家改的摘要 / 问法只在当前页面内存里，离页即丢 | 失焦、增删问法、离页时 `POST .../host/preview-edit` 落 `editsJson`；只送改过的分区，未带的分区保留 |
| 4 | 展示时人工稿与模型稿只有一份存活 | 人工稿压在模型稿之上展示（`effective`）；`faqEdited` 认「动过问法区」，删到零条也不把模型问法放回来 |
| 5 | 「AI 生成」直接覆盖，商家改过的稿子无提示消失 | 有 `geoHumanEdited` 时先弹窗确认；确认后 `forceRegen` 清 `editsJson` 并重跑模型与看图 |
| 6 | 取消托管 / 改回仅私密会带走公开侧产物 | 都不清 `host_preview_caches`——预览缓存的生命周期独立于托管开关 |
| 7 | 老单据（只有 `hostMeta`）没有缓存概念 | 首次预览一次性回填：`geoLayer`（已公开）视为商家确认过的人工稿，`geoDraft` 作模型层，判定结果一并搬入；搬完只认表 |

打码图**不进**这张表：结论只住 `flowNodes` 图槽（`maskedUrl` / `maskOutcome` / `maskSource` / `maskRegions`），读侧现建索引（`hosted-public-mask.service.js`），人工打码写回即生效。另建一份打码缓存只会造出第二真源和漂移。
