## 1. 变更

| # | 旧口径 | 新口径 |
| --- | --- | --- |
| 1 | 公开关键帧按 `nodeId` 字符串排序后取前 N 张（默认 8）：检测节点（`fn_002`）图片一多就吃满上限 | 按流程节点顺序排序，并**按节点轮转取名**：先每个有图节点取 1 张，再逐轮补到上限。多环节案例保证每个环节都有代表图 |
| 2 | `publicViewToSnapshotNodes` 只输出 `publicView.media` 里出现过的节点，无图节点直接从快照 `nodes` 消失 | 保留**全部流程节点**（标题 + 说明照旧，无图节点 `images: []`）；图片仍只从公域池按 `nodeId` 挂载，接车 / 报价等私有阶段图不外泄 |
| 3 | H5 读侧同样按 `snapshot.publicView.media` 重建 nodes，旧快照只剩检测节点 | 读侧重建立即生效：用快照里的完整 `nodes` 做兜底，按 `nodeId` 挂公域图；历史快照若本身只存了检测节点，需重建快照（见 §4） |

关键帧总量约束不变：`PUBLIC_MEDIA_KEYFRAME_DEFAULT = 8`，硬上限 `PUBLIC_MEDIA_SOFT_CAP = 30`。
