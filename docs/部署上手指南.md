# 辙见 · 部署上手指南

> 只写**日常会用到的正确命令**。首次装机、Nginx、证书等见文末「延伸阅读」。

---

## 0. 先看清：三个环境

| 环境 | 代码目录 | 数据库 | API 域名 | PM2 |
| --- | --- | --- | --- | --- |
| **本地** | 你的电脑 | 本机 `zhejian` | `http://127.0.0.1:3000` | 不用，`npm run dev` |
| **预发** | `/var/www/zhejian-staging` | `zhejian_staging` | `https://staging.geo.simplewin.cn` | `zhejian-api-staging`（`:3101`） |
| **生产** | `/var/www/zhejian` | `zhejian` | `https://geo.simplewin.cn` | `zhejian-api`（`:3100`） |

预发测过 ≠ 自动上生产。要分别在两台目录里 `git pull` + 跑迁移。

## 1. 数据库命令（最容易用错）

| 命令 | 做什么 | 用在哪 |
| --- | --- | --- |
| **`npm run db:setup:prod`** | 生成 Prisma Client + 执行未应用的迁移 | **预发 / 生产**（默认） |
| **`npm run db:migrate`** | 只跑迁移（不重新 generate） | 偶尔；日常更推荐上面那条 |
| **`npm run db:setup`** | 迁移 + **写入演示 seed 数据** | **仅本地首次建库** |

### 禁止

- 生产 / 预发 **不要** 跑 `npm run db:setup`（会 seed，污染真实数据）。
- 生产 **不要** `prisma migrate reset` / 删库重建。

## 2. 日常发版（预发 → 生产）

推荐顺序：**同一 commit 先预发验收，再上生产**。

### 2.1 预发

```bash
cd /var/www/zhejian-staging
git pull

cd backend
npm install
npm run sync:shared-utils
npm run db:setup:prod
pm2 restart zhejian-api-staging

# 若改了运营后台
cd ../admin-web && npm install && npm run build

curl -s https://staging.geo.simplewin.cn/api/v1/health
```

### 2.2 生产（预发 OK 后再做）

```bash
cd /var/www/zhejian
git pull

cd backend
npm install
npm run sync:shared-utils
npm run db:setup:prod
pm2 restart zhejian-api

cd ../admin-web && npm install && npm run build

curl -s https://geo.simplewin.cn/api/v1/health
```

H5（`/case/`）跟代码目录走，`git pull` 后即生效，一般不用单独构建。

### 2.3 发版后自检

- [ ] health 返回 `"ok": true`
- [ ] 运营台能打开：`/admin/`
- [ ] 若有库表变更：预发已测过对应功能，再生产验收一遍

## 3. 小程序连哪套 API

改一行：`services/config.js` → `ACTIVE_ENV`

| 值 | 连哪里 | 何时用 |
| --- | --- | --- |
| `local` | 本机 `:3000` | 开发者工具；勾选「不校验合法域名」 |
| `staging` | 预发 | 体验版/真机测预发；合法域名含 staging |
| `prod` | 生产 | 提审、正式版；**发版前改回这个** |
| `mock` | 不发请求 | 纯 UI 演示 |

说明：改 `ACTIVE_ENV` **只改小程序请求地址**，不会改服务器上的数据库。

**OSS 直传（`OSS_ENABLED=true`）时**，微信公众平台还需把 Bucket 外网域名加入合法域名：

| 类型 | 域名 |
| --- | --- |
| uploadFile / downloadFile | `zhejianoss.oss-cn-hangzhou.aliyuncs.com` |

Bucket CORS：允许方法 `GET, POST, HEAD, PUT`；来源可用 `*`（小程序无 Origin）或业务域名；暴露头 `ETag`。

## 5. 迁移报错怎么处理

### 5.1 正常情况

预发 / 生产发版时 `db:setup:prod` 只会应用**还没记过**的新迁移。预发成功后，生产一般同样成功。

### 5.2 P3009 / P3018（账本坏了）

典型报错：

- `P3009`：存在 **failed** 迁移，后面全部不跑  
- `P3018` + `Duplicate column`：库里**列已存在**，但账本认为还没应用过，又重跑旧迁移

含义：表结构往往已在，**迁移记录表 `_prisma_migrations` 与现实不一致**。  
这是偶发急救，**不是**每次发版都要做。

**生产急救（一条 SQL，静默对齐）：**

```bash
cd /var/www/zhejian/backend
# 确保已 git pull 到含该脚本的版本
mysql -uroot -p zhejian < scripts/prod-fix-migration-history.sql

npx prisma migrate status
# 期望：Database schema is up to date

npx prisma generate
pm2 restart zhejian-api
```

脚本会：补缺列（若没有）+ 按当前仓库重建迁移账本。  
生成器：`node scripts/gen-prod-fix-migration-history.js`（改完迁移后如需可重生成）。

**本地无重要数据时**，更快：删库重建后 `npm run db:setup`。

**单条失败且确认结构已落地时**（慎用）：

```bash
npx prisma migrate resolve --applied 迁移目录名
npm run db:setup:prod
```

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 生产误跑了 `db:setup` | 立刻停；检查是否被 seed 污染；以后只用 `db:setup:prod` |
| health 502 | `pm2 logs zhejian-api`；确认 `.env` 里 `PORT=3100` 与 Nginx 一致 |
| `/admin/` 404 | `cd admin-web && npm run build` |
| 运营台报 `Unknown argument spotCheckStatus` | 库缺列或进程未加载新 Client → 先 `db:setup:prod`（或 §5.2），再 `pm2 restart` |
| 本地 P1000 密码错误 | 改 `DATABASE_URL` 与 MySQL 用户一致 |
| 真机连不上 local | 手机访问不到 `127.0.0.1`，改用 `staging` / `prod` |
| 图片上传失败 / OSS 403 | 查 `OSS_ENABLED`、RAM/ECS 角色是否含 Bucket 读写；Bucket 是否阻止公共访问（应开着，用签名/PostObject）；微信合法域名是否含 OSS 外网域名 |
| 旧图 404 | 是否已跑 `npm run media:migrate-oss`；迁移期本地盘是否仍在 |

## 7. 阿里云 OSS（媒体）

生产建议：

```bash
# backend/.env
OSS_ENABLED=true
OSS_BUCKET=zhejianoss
OSS_REGION=cn-hangzhou
OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
OSS_INTERNAL_ENDPOINT=oss-cn-hangzhou-internal.aliyuncs.com
# 凭证：ECS 绑含 OSS 权限的实例角色，或 ALIYUN_ACCESS_KEY_*（RAM 用户）
```

存量从 ECS 本地迁入：

```bash
cd /var/www/zhejian/backend
# 先测连通（若卡住/超时，.env 加 OSS_USE_INTERNAL_ENDPOINT=false）
npm run media:migrate-oss -- --probe
npm run media:migrate-oss -- --dry-run   # 只扫本地，不连 OSS
npm run media:migrate-oss
# 确认读图正常后再：npm run media:migrate-oss -- --delete-local
```

验收：商家传图 → 相册保存 → 脱敏预览 → H5/运营台看图；新图不应再长期堆在 `data/media`。
