## **2. 公开案例定义**

> 从**服务相册**生成的 **公示案例内容**（商家确认案例稿 + 脱敏配图），经完工后脱敏与平台案例人审通过后，由车主确认「发布到公开网站」，在 H5 公开展示。

用途：用户参考、门店主页、服务/城市/车型聚合页、SEO/GEO 收录、AI 可引用摘要。

---

| 来源 | 说明 | 标签 |
| --- | --- | --- |
| **用户发布案例**（运营台可仍标「用户授权案例」过渡） | 车主确认发布服务相册脱敏内容到公开网站（须已过案例审） | 用户发布案例 |
| **商家历史案例** | 商家上传过往维修并责任确认 | 商家历史案例 |
| 平台整理案例 | 合规素材整理（少量） | 平台展示审核 |

**删除**：「订单服务相册 / 平台订单案例」。

## **4. 公开前置条件**

1. 案例已生成，有标题、服务项目、车型信息；
2. **用户发布案例**：**不要求** 必有过程图；若有图则公开 payload **仅含已脱敏** URL（脱敏失败图不进入 H5）；
3. **商家历史 / 冷启动**：须有过程图且脱敏完成（冷启动另受 GEO 证据链 block）；
4. 无车牌、VIN、手机号、人脸等敏感信息（对已公开素材）；
5. **用户发布案例**：车主已确认发布且未撤回；
6. **历史案例**：商家责任确认已完成；
7. 商家/门店状态正常；
8. 无进行中的隐私投诉、配件纠纷举报；
9. 内容合法，通过基础安全检测。

---

## **5. 审核对象**

案例标题/摘要、服务项目、车型、门店、维修过程逻辑、脱敏图片、价格（区间/影响因素）、FAQ、SEO 字段、授权状态、商家资质、风险状态。

**删除**审核维度：订单关联、退款、售后、交易评价。

---

## **6. 案例审核状态**

DRAFT → WAIT_DESENSITIZE → DESENSITIZED → WAIT_AUDIT → AUDITING → APPROVED → PUBLISHED；以及 REJECTED、NEED_MODIFY、OFFLINE、RISK_LOCKED。

## **7. 审核流程（案例审核收口 · 2026-07-27）**

```text
商家确认案例预览并完工 → pending_desensitize（商家锁定；车主仍可看相册）
→ 异步 pre-mask
→ 脱敏结束（就绪/部分失败/失败）→ pending_review
→ 运营案例人审（仅通过 / 驳回；可重试脱敏；本期无运营手工打码；不挡车主看相册）
   · 通过 → review_passed（不上线；案例稿/发布可开）
   · 驳回 → rejected（解锁商家；车主相册仍可看）
→ 车主确认「发布到公开网站」→ CaseSnapshot → 直接 public_approved 上线
→ 撤回 → offline（不解锁商家）
```

**运营后台**：唯一审核台 = **案例审核**（含「脱敏处理中」与「待审核」）。  
**操作**：仅 **通过 / 驳回** + **重试脱敏**（无「要求修改」、无运营手工打码）。  
**通过**：不上线；车主随后可查看并自行发布。  
**驳回**：解锁商家。

## **8. 审核规则（摘要）**

### **8.0 审核对象（2026-07-27）**

| | 案例审核（唯一阻塞审） |
| --- | --- |
| 时机 | 商家确认完工，且脱敏流程结束后 |
| 对象 | 公示案例稿 + 脱敏配图（不是整本私密相册） |
| 结论 | 通过 / 驳回 |
| 脱敏异常 | 仍进待审并标出；可重试或驳回商家 |
| 驳回回到 | 商家 |
| 审前车主相册 | **可查看**服务相册（案例审不挡相册） |

### **8.1 真实性**

须有可追溯的服务相册或历史上传记录；禁止拼凑、盗图、虚构价格/故障。

### **8.2 隐私脱敏**

车牌、VIN、人脸、证件、保单、单据须隐藏；不通过则退回脱敏或替换图片。

**运营审核可见范围（定稿 2026-06-01）**：

| 审核员可见 | 审核员不可见 |
| --- | --- |
| 脱敏图 | 原图 |
| OCR / 风险摘要 | 原图 URL（Admin API **不返回** `rawUrl`） |
| 脱敏状态（已脱敏 / 需人工 / 失败） | — |

审核员依据 **脱敏图 + OCR 摘要** 判断；脱敏异常时可「重试脱敏」或「驳回商家」，**不得在审核台查看原图**；本期不做运营手工打码。

### **8.2.1 确认案例稿同源审核（CASE-DRAFT-LOCK · 2026-07-24）**

闸门详情页须展示 **商家确认案例稿**（标题 + **案例摘要** + 五段正文 + 章节下脱敏配图），与车主授权预览、H5/小程序公开案例页同构：

| 端 | 展示 |
| --- | --- |
| 运营审核详情 | `confirmedCaseDraft` 只读面板（含案例摘要） |
| 小程序案例详情 | 优先确认稿；无确认稿时回落节点时间线 |
| H5 公开案例 | 优先确认稿五段 + 脱敏配图 + 案例摘要 |

**案例摘要**：商家在完工预览确认；页内首屏与搜索描述**共用同一摘要**（搜索描述 = 摘要截断派生）。运营后台**不再单独编辑 SEO 描述**；可对摘要做合规修订（去金额等），保存后自动派生搜索描述。

无确认稿时运营台提示退回商家完成「案例预览 · 确认完工」；发布链路本身已要求确认稿。

### **8.3 内容合规**

禁止违法违规、虚假宣传、外部联系方式、诱导违规导流。

### **8.4 商业宣传**

允许陈述门店与项目；禁止「全城最低」「不修包赔」「加微信报价」等。

### **8.5 价格展示**

标准项目可用区间；复杂/事故车须体现「以到店检测为准」；**不得暗示平台统一报价**。

### **8.6 SEO 字段**

title、description、H1、FAQ（≥3 条）、alt、slug、schema 须合规，不堆砌关键词。

### **8.7 快照冻结与运营编辑边界（定稿 2026-07-09 · 卷九）**

| 区域 | 公示后（`snapshotVersion ≥ 1`） | API / UI |
| --- | --- | --- |
| **快照正文**（title/body/nodes/过程图） | **只读** | `PUT` 改 snapshot 域 → `409 SNAPSHOT_FROZEN` |
| **提炼层**（aiSummary/seo/faq/topic） | 可编辑 | `PUT /admin/cases/:id/enrichment` |
| **运营 LLM 润色** | **禁止 adopt 写 snapshot** | `CaseGeoLlmReview` 在 `snapshotFrozen` 时隐藏 |
| **代商家改相册** | **禁止** | 商家授权后相册 409；B 驳回不解锁 |

**审核通过**：仅更新 `status`、`published_h5`、enrichment 发布字段；**不** rebuild snapshot。  
**合规-only**：B 闸仍只审脱敏 + 用户侧内容；不因六阶段缺项驳回（§9.3 不变）。

## **9. 用户发布规则**（修订 2026-07-18 · **案例审收口 2026-07-27**）

> 历史用语「用户授权」= 车主确认 **发布到公开网站**。口径 §4.5：用户点一下才上线；**案例审在完工后、发布前完成**；发布不再复审。

### **9.1 用户发布案例须有发布确认**

1. 维修过程图片可脱敏后展示；
2. 车辆局部图片可脱敏后展示；
3. 案例可用于 H5 与 SEO/GEO 收录；
4. **须**平台案例审已通过（`review_passed`）才可发布到公开网站；**不**因审中拦截车主查看服务相册。

**删除**：评价内容公开授权（V1.0）。

### **9.2 不可公开**

用户拒绝/撤回发布、**已展示素材**无法合规脱敏、严重事故/保险/法律纠纷、配件争议未结案、平台判断有 **合规/隐私** 风险。

**删除 / 不适用于用户发布案例**：因「六阶段不全 / 无过程图 / GEO 证据 block」 alone 驳回（留档质量归商家，车主发布用于监督与分享）。

### **9.3 案例审口径（定稿 2026-07-27）**

| 审核项 | 是否作为门槛 |
| --- | --- |
| 商家确认案例稿合法合规（禁词/导流等） | **是** |
| 已展示脱敏图的 OCR / 隐私风险 | **是**（详情标出；可重试脱敏或驳回商家） |
| 整本私密相册 / 六阶段齐全 | **否** |
| 发布确认有效、未撤回 | 发布时校验（审过后） |

**结论**：仅 **通过 / 驳回**。通过 → `review_passed`（不上线，车主可看并可发布）。驳回 → 解锁商家。本期不做运营手工打码、「要求修改」。  
**发布**：车主点发布后直接上线，**不再**进人审。

## **10. 驳回原因（示例）**

| 类型 | 示例 |
| --- | --- |
| 隐私未脱敏 | 含车牌/VIN/人脸 |
| 发布确认不足 | 用户未确认发布或已撤回 |
| 配件留痕不足 | 非原厂案例缺少确认记录（若对外宣称已告知） |
| 内容不真实 | 文案与图片不符 |
| 违规宣传 | 外部联系方式、夸大承诺 |
| 门店/资质异常 | 商家冻结 |
| 纠纷/投诉 | 隐私或配件举报进行中 |
| SEO 不合规 | 关键词堆砌 |

## **12. 审核通过后**

## **13. 已发布案例下线**

用户撤回授权、隐私泄露、商家/门店异常、配件/内容举报成立、监管要求、 SEO 质量严重不合格等 → OFFLINE，移出 sitemap。

**举报下线（2026-07-09 · CASE-OPS-06）**：仅改 `status=offline` + 清空 `published_at`；**不得**删除或改写 `content_json.snapshot` / `enrichment_json`。须写入 `case_review_log`（`review_action=report_offline`，含 `snapshotVersion` / `snapshotPreserved` 摘要）。

**删除**下线理由：「订单严重纠纷」→ 改为「配件/隐私纠纷举报成立」。

## **15. P0 验收标准**

1. 公开前必须审核；
2. 图片必须脱敏，用户未授权不得公开；
3. 配件/隐私争议中不得公开；
4. 支持通过、驳回、下线；
5. 操作留痕，H5 仅读已审核案例；
6. FAQ ≥3 条，SEO 字段可审；
7. 案例来源标签正确（用户发布 / 商家历史；过渡期可显示「用户授权」）；
8. **运营审核台仅展示脱敏图，不展示、不返回原图**。
