## **2. 模块定位**

运营对商家账号做**事后监管**，而非「审过才能干活」：

1. 抽查认证证件与门店资料；  
2. 撤销「已认证」标签；  
3. 冻结/关闭公开面或主体；  
4. 处理虚假资料与投诉。

**不做**：把人工入驻通过作为创建相册/托管的门禁。

---

## **3. 商家状态（主体）**

| 状态 | 说明 |
| --- | --- |
| DRAFT | 历史草稿（新开通不再依赖） |
| PENDING_AUDIT | 历史待审（软信任下新开通直达 ACTIVE） |
| ACTIVE | 已开通，可生产 |
| NEED_MODIFY / AUDIT_REJECTED | 历史态；可引导完善资料，不挡 ACTIVE 生产能力 |
| SUSPENDED / FROZEN | 冻结 |
| CLOSED | 已关闭 |

认证状态另字段：`none` / `pending` / `verified` / `failed`（与主体 ACTIVE 解耦）。

---

## **4. 运营动作**

| 动作 | 效果 |
| --- | --- |
| 抽查通过 | 可保持/确认认证标 |
| 撤销认证 | `authStatus` 回退；公开展示同步；**不**收回工作台 |
| 要求补资料 | 通知商家；不强制下线生产 |
| 冻结公开 | 店页/案例公开展示限制 |
| 关闭主体 | 不可继续经营 |

审核日志保留：操作人、动作、原因。

---

## **5. 列表与详情**

列表字段建议：主体名、开通时间、认证状态、完整度、公开案例数、风险标记。  
详情：证件预览、门店加分资料、操作区（摘标/冻结/关闭）。

菜单文案可由「入驻审核」改为「商家监管」或「商家账号」。
