# 微信群转案例迁入小程序

> **生效**：2026-09-03  
> **修订**：2026-09-18 · **进料口**：群聊 → 同一本相册节点草稿；一次多选照片按建议挂步骤  
> **配套**：[`14_四件套`](../01_项目总览与业务架构/14_四件套产品架构与定位.md) · [`22_微信群归档转案例目标定义.md`](./22_微信群归档转案例目标定义.md) · [`26_商家端事件节点与单据节点链流程.md`](./26_商家端事件节点与单据节点链流程.md)

## 1. 目标

- 产出：收成**同一份维修档案**（过程证据 + 可选单据骨架 + 确认过的概况/问法），不是官网「一篇文章」草稿，也不是另一种公开页。
- 入口：`packageMerchant/pages/tools/wechat-archive`（电脑微信也可在小程序内粘贴）。
- 官网首页工具区「从聊天创建」卡片正文下放直达小程序码（`GET /api/v1/public/h5/miniprogram-code?entry=wechat-archive`）。不要「打开小程序码」跳转，也不再保留 `/archive` 页。不要网页转换器。对外不写成仅限微信群聊。
- **未开通商家**：不弹「请先入驻」后丢在工作台。记下「来转群聊」，门槛写成开通后继续贴这一单；**一键开通 / 资料保存通过后送回本页**。
- **工作台再找**（2026-09-22）：新建相册页底栏左侧「从聊天创建」，与「创建相册」同排。粘贴不限于微信群聊，这一单的文字都可以。工作台页脚不再放此入口。
- **署名**：推送到案例站时登录的辙见账号决定门店还是个人（见 `15_` §7.2）。
- 对外来源：**商家上传**。禁止「沟通记录转化」「已审核」。

## 2. 流程

```text
粘贴这一单群聊文字（语音须先转成文字再贴）
  → 先打码再抽事实（群里没说的不写；推断标待确认）
  → 新建服务相册，预填接车主诉 / 发现项 / 方案行 / 施工项 / 完工说明
  → 一次选进本单照片，按群聊建议挂到检查 / 旧件·施工 / 完工；挂错可改
  → 打开现有时间线核对、补金额、再通知车主 / 托管
```

不另做九段文章页。模型抽出的问法可进档案问法，须门店确认后才公开。

## 3. 文字 → 相册怎么填

| 群聊抽出的 | 填进哪 |
| --- | --- |
| 车型、里程、主诉 | 接车与检测 |
| 检查发现、已排除 | 发现项（部位 + 检查发现；默认「需处理」，排除项用「状态良好」） |
| 方案、理由、配件、金额 | 方案确认行（金额只进私密单据，不进公开概况） |
| 施工步骤 | 施工项（先有项目名，图后挂） |
| 完工验证、交车说明 | 完工确认 / 质保注意事项 |
| 配图线索（检查 2 张、旧件 1 张…） | 选图时的建议格子，不是最终证据 |
| 脱敏后的群聊全文 | 只存商家侧自证，不公开 |

群里没提到的格子留空。节点保持草稿，不自动完成、不自动通知车主。

## 4. 图片

电脑微信复制**带不走图片文件**，只有 `[图片]` 占位。因此：

1. 文字先建册；
2. 商家**一次选进**本单相关照片（可多次补选，单次最多 9 张）；
3. 按配图线索顺序挂到检查 / 施工（含旧件、新件）/ 完工；多出来的进「未分类」，点一下可改挂到哪一步；
4. 上传走现有图片接口；公开前仍走脱敏。

不做：对着每个字段一张张传；不做群机器人/转发归档号自动收图。

## 5. 配额与鉴权

小程序内以商家登录为准。建册走商家相册接口，不计公开试用次数。

## 6. 页面

`packageMerchant/pages/tools/wechat-archive/`

可见文案只说现在做什么：粘贴、选图、去核对。不写「自动生成 / 统一入口 / 草稿 / 沟通记录转化」。
