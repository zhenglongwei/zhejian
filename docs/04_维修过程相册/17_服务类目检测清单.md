## 1. 一句话

> 每个服务类目有一份**可勾选、可挂图、可写说明**的软清单；施工/完工照片也可挂回同一清单项。  
> 清单帮中小店少漏项、帮车主看得懂；**永不因未完成清单而阻断完工**。

相对现行「阶段下一句拍摄提示」：该形式可有可无，**产品方向上取消作为主引导**，改由本清单承担「拍什么 / 挂到哪 / 怎么说」。

相对知车式智检：本清单是**旁路软引导**，不是店内检测操作系统。

## 2. 已拍板规则（2026-08-10）

### 2.1 阶段摆法（检测延伸到施工 · 无「无检查施工项」）

| 规则 | 说明 |
| --- | --- |
| **接车 / 检测** | 列出本阶段**检查/判断**项；商家在此留证并标记结果 |
| **施工 = 检测延伸** | **不**单独常驻「没经过检查」的固定清单。施工节点主界面 = **待处理队列**（检测标需处理/需更换等后自动进入） |
| **施工衍生项** | 部分检查项配置 `workFollowUpKeys`：父项检测异常后解锁子项进施工待处理；**有衍生的父项本身不出现在施工列表**（例：旧机油 → 新机油规格/机滤/液位） |
| **同 key 挂图** | 无衍生子项时，施工图继续挂回**同一检查项**（如空滤建议换 → 施工新旧件仍挂空滤） |
| **完工** | 交付类项（试车、交车说明、下次保养建议等）可出现在完工节点；仍不阻断 |
| **材料总览** | **现阶段不做**配件三列表；车主看各有证项即可 |
| **未关联图** | 允许未挂清单的过程图；车主主阅读仍以清单为主 |

### 2.2 强度（软清单）

| 允许 | 禁止 |
| --- | --- |
| 提示完整度（如「建议项还剩 N 项」） | **因清单未完成阻断完工 / 阻断进入下一阶段** |
| 空说明时用项名 + 状态兜底展示 | 强制红黄绿健康分才能交车 |
| 商家跳过任意项 | 强迫与店内工单/智检系统双录入主流程 |

### 2.3 商家侧（生产）

1. 按类目展示检查项列表（可分组：接车相关 / 检测相关 / 施工建议关联等）。  
2. 拍摄后将照片**关联**到对应项；该项可标为「已检」（或等价状态）。  
3. 为该项或该图写**简明说明**（几句描述性话即可）。  
4. 后续阶段继续往同一项补图、补说明。

### 2.4 车主侧（阅读 · 定调）

> **车主流量界面应以「检查清单 + 照片 + 照片说明」为主阅读形态**，而不是只有全屏翻图。  
> 普通人需要先看到「检了什么、结论是什么」，再点进证据图；纯相框翻页对不懂车的人不够。

| 要素 | 要求 |
| --- | --- |
| 清单项 | **仅展示有真实证据的项**（有关联图或非空说明）；指引未拍的项**不出现** |
| 状态/结果 | 含建议更换、已更换、**建议过但未更换**等（见 `18`）；不是空的「待检」目录 |
| 照片 | 挂在项下；可跨阶段多图（检测旧况 + 施工新件） |
| 说明 | 项说明或本图说明，须可读；空则用温和兜底，不留空白谜题 |
| 与翻页关系 | 清单为主路径；大图/翻页为详看，不替代清单叙事 |

（实现细则见 [`18_服务类目检测清单上线方案.md`](./18_服务类目检测清单上线方案.md)。）

### 2.5 与 §2.1 轻结构对齐自检

- 只增强留证与说清，不接管修车主流程 → ✅  
- 一次完成、不强制第二套智检作业 → ✅  
- 结构软、不阻断完工 → ✅  
- 车主看得懂优先于门店检得全 → ✅（§2.4）  
- 不用公开规则反推强检 → ✅

## 3. 检查项字段约定（填表用）

逐类填写时，每一项建议包含：

| 字段 | 含义 |
| --- | --- |
| `itemKey` | 稳定英文/拼音键（配置与关联用） |
| 检查项名称 | 商家/车主可见短名 |
| 建议首次阶段（出现阶段） | `接车` / `检测` / `完工` = 节点清单；`施工` = **仅作待处理衍生项**（不常驻施工清单，须由父检查项解锁） |
| 分组 | 可选：外观 / 油液 / 制动… |
| 说明示例 | 商家写说明时可参考的句式（非强制文案） |
| 强度 | `建议`（默认）/ `强烈建议`（仍不阻断） |
| 备注 | 类目特例、隐私注意等 |

> **「建议首次阶段」消歧**：表示该项**默认出现在哪个阶段节点**；**不等于**禁止其他阶段补图。力矩、路试、色差复查等应优先放在施工/完工节点列出。

## 5. 分类目检查项

> **保养族**：小保养 / 大保养共用关系见 **§5.0**（勿两套各写互不相干的全表）。  
> 后续若增删项：改对应节 → 更新总表与 §8；仍遵守 §2.2 软清单（不阻断完工）。

### 5.0 保养族关联规则（小保养 ↔ 大保养）

```text
小保养清单 = 包 A（基础巡检） + 包 B（小保核心：机油机滤等）
大保养清单 = 小保养清单全部继承 + 包 C（大保增量）
```

| 包 | 代号 | 含义 | 用于 |
| --- | --- | --- | --- |
| **A · 基础巡检** | `M-BASE` | 到店与常规检查项（灯光、底盘、轮胎目视+胎压等） | 小保 + 大保 |
| **B · 小保核心** | `M-CORE` | 检测：旧机油状态；其「需处理/需更换」后待处理解锁新机油规格/机滤/新机油液位；完工：下次保养建议；**空调滤按本次套餐** | 小保 + 大保 |
| **C · 大保增量** | `M-MAJOR` | 空滤、火花塞、燃油滤、多油液、正时周期提示等；完工功能抽检（空调滤继承 B；**不做**材料总览/旧件总表，新旧件挂在各单项下） | **仅大保** |

**规则**

1. 改小保养表（A/B）时，大保养自动视为已更新继承部分；大保节只维护增量 C。  
2. 大保某次未做的增量项（如本次不换火花塞）→ 保持「未检/跳过」即可，**不阻断**。  
3. 跨阶段仍可往同一 itemKey 补图；保养机油链路：检测 `old_oil` 标需处理/需更换 → 待处理自动带出 `engine_oil` / `oil_filter` / `oil_level_confirm`。  
4. 说明示例为参考句，非强制话术；避免绝对化承诺与公域金额。

> **组成**：§5.1.1 包 A + §5.1.2 包 B。

### 5.2 大保养（`major_maintenance`）· 已定稿

> **组成**：**完整继承 §5.1（包 A + 包 B）** + 下列 **包 C 增量**。  
> 车主端 / 商家端展示大保清单时，应看到「小保同款巡检与机油机滤」+「本次大保增加项」，避免只显示增量导致「机油去哪了」。  
> 对齐 `02` §6：空滤/空调滤/火花塞/油液等；材料总览/旧件总表本期不做。

#### 5.2.1 包 C · 大保增量（`M-MAJOR`）

| `air_filter` | 空气滤芯 | 检测 | 滤芯易损 | 空滤已检/已换；旧件堵塞或进灰情况简述。 | 强烈建议 | 检测打开滤盒；施工新旧对比挂本项 |
| `spark_plugs` | 火花塞 | 检测 | 点火 | 按里程检/换火花塞；电极间隙或积碳简述（如有）。 | 建议 | 施工拆下旧件特写；包装可挂 |

**大保养项数**：继承小保 17 项 + 增量 10 项 = **最多 27 项**（已去掉材料总览/旧件总表；实际按本次服务勾选/跳过）。

#### 5.2.2 与小保养对照（便于审阅）

| 维度 | 小保养 | 大保养 |
| --- | --- | --- |
| 基础巡检（A） | ✅ | ✅ 继承 |
| 机油机滤（B） | ✅ 核心 | ✅ 继承（多数大保仍做） |
