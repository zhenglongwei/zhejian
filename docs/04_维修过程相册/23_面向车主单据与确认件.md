# 面向车主的维修单据（三期产品化）

> **生效**：2026-09-03  
> **状态**：产品口径定稿 · 实现分期  
> **配套**：[`15_案例档案与托管状态机.md`](../01_项目总览与业务架构/15_案例档案与托管状态机.md) · [`14_四件套`](../01_项目总览与业务架构/14_四件套产品架构与定位.md)

---

## 1. 目标

小程序门店端在原始图文之外，产出面向车主的结构化单据；车主确认后成为**确认件**；托管公开时脱敏展示。

## 2. 单据类型（首批）

| 类型 | docType | 主要内容 | 车主确认 |
| --- | --- | --- | --- |
| 报价表 | `quote` | 项目、参考区间、说明（公域藏精确价策略另遵 07） | 可选/按店规 |
| 工单 | `work_order` | 施工项、责任技师、计划工期 | 可选 |
| 维修确认单 | `repair_confirm` | 方案与风险确认 | **建议强制** |
| 质保单 | `warranty` | 质保范围与期限 | 建议 |
| 车辆维修报告 | `repair_report` | 检查发现、处理、验证 | 建议 |

## 3. 确认件规则

- 车主确认瞬间写入 `hostMeta.confirmedDocs[]`，`immutable: true`。  
- 商家修改对应内容必须 **另存修订版**，不得覆盖确认件。  
- 平台不审修订与确认件是否一致。

## 4. 生产入口

1. 相册 **节点链** 内按步填写 / 生成（[`26_…`](./26_商家端事件节点与单据节点链流程.md)）  
2. **微信群转案例**（迁入小程序后）→ 直接生成节点链 + 单据骨架，再走托管  

## 4.1 单据与节点（DOC-FLOW）

每 **docType 对应独立单据节点**（非嵌入拍照节点）：

| docType | 节点显示名 |
| --- | --- |
| `inspection_report` | 检测报告 |
| `quote_confirm` | 报价确认单 |
| `work_order` | 工单 |
| `addon_quote_confirm` | 增项报价确认单 |
| `repair_report` | 维修报告 |
| `warranty` | 质保单 |

代确认可选上传沟通截图（1–3 张，**非必填**）。

## 5. 公开层

公开三层中的「② 脱敏单据」展示已确认件（脱敏）+ 商家最新修订（若有），并标注确认时间 / 修订时间。

## 6. 实现顺序

1. 数据模型与确认 API（`POST .../confirmed-docs` 已有骨架）  
2. 车主端确认 UI  
3. 各单据编辑页  
4. 微信工具映射到单据字段
