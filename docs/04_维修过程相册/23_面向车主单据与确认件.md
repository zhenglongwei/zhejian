## 1. 目标

门店在过程照片之外产出面向车主的结构化单据；**方案确认 / 完工确认** 经车主（或代确认）成为确认件；接车照片、检测报告与工单逐步可见，不用车主点同意。

**车主阅读心智（2026-09-08）**：进相册是为了**看报告与确认单据**，不是翻照片墙。照片只作为某张单据里的**附件证据**。

## 2. 单据类型

| 类型 | docType | 主要内容 | 车主 | 生成 |
| --- | --- | --- | --- | --- |
| 接车报告 | `intake_confirm` | 里程（读档案）、随车物品、车主诉求、入店照片。不单列油量 | 发给车主看，不用点同意。发出后商家不能改 | 点「发给车主」打开车主那一页，确认后发出。挂在接车步，不另起节点 |
| 检测报告 | `inspection_report` | 主诉 + 发现项（图 + 部位 + 结果 + **检查发现**） | 与方案同次通知后可阅 | 检测后规则生成（主诉取接车步） |
| 方案确认 | `quote_confirm` | **要做的事** + **品牌（选填）** + **真实金额** + **处理建议**（不含检测结果标签、不含检测图） | **需确认** | 商家改草稿并填价；封闭类目为套餐+附加项；事故等开口活第一张为可见项+拆检，拆后增减再确认 |
| 工单 | `work` | **施工留档单据**：施工项 + 用料 / 品牌 / 数量 + 旧件/新件证物图（工序图选留） | 只读 | 方案确认后由商家逐条填写 |
| 完工确认 | `repair_report` | 已施工项 + 交车照 + 质保 | **需确认** | 完工照后生成 |

**废止**：独立 `warranty` 节点；检测报告/工单的车主确认；**单独推送检测报告**（须与方案同次通知）；**工单由报价派生**（2026-09-28 起，工单 = 如实记录施工过程产生的单据，不再是已确认方案行的留档）。

增项：再出一张确认单。开口活与封闭类目的车主文书标题都是 **报价单**；拆检后增减靠确认条款，不再另写「先确认这些」。补充单标题仍是 **补充报价**（封闭类目为 **施工中新发现**）。完工确认再汇总全部已确认项目（见 `26` §2、§3）。施工是否另开一格，以 `26` §2 的下一步为准。商家填写页的蓝头口径仍见 `26`。  
误点：商家可 **整张作废**（未发送=无痕撤回；已发送须填原因且车主可见）。车主对待确认项可点 **不同意**（见 `26` §3.2）：施工中新发现等同取消该项，记车主未同意；首次方案与完工退回门店修改。有疑问仍可电话联系门店。

历史别名：`quote`≈方案费用部分；产品文案「报价确认单」一律改为「方案确认」；「维修报告」产品文案为「完工确认」。

## 3. 确认件规则

- 方案确认、完工确认写入确认件（`immutable`）。接车照片发出后商家不能改，但不是车主确认件。  
- 确认文案为平台**固定协议句**；商家编辑页不展示；**车主确认时展示**（进度页待确认步内）。  
- 商家代确认：仅「待车主确认」后出现，入口为次按钮「代车主确认」；须先弹窗确认仅限车主当面、电话或微信已同意但未在手机确认的情形，再选留痕方式；可选证明图（确认流程内选传）。  
- 商家改已确认内容须另存修订（二期）。

固定文案：

| 单据 | 文案 |
| --- | --- |
| 方案确认（保养、电瓶、刹车等封闭类） | 本人同意按上述项目施工，费用以本单为准。 |
| 方案确认（事故车、底盘异响、通用等开口活） | 本人同意按上述项目施工（含约定拆检）。拆检后如有增减，须再确认。费用以各次确认单为准。 |
| 完工确认 | 本人确认上述施工与交车状态，并知悉质保条款。 |

## 4. 车主逐步可见（业务顺序）

1. **接车照片**（商家保存并发送后可看，不用点同意）
2. **检测报告 + 方案确认**（报告只读，方案待确认）
3. 方案确认通过后 → 工单（只读）
4. 完工确认（待确认 → 已确认）
5. 增项时再次方案确认 → 新工单  

完工照**不**作为车主时间线独立步骤；**旧件/新件证物挂在工单单据内**（工单本身是车主时间线的一步，只读、不需确认）。  
交车照 = 商家选用的工单图引用（及通常需要补拍的整车外观），在完工确认内展示；**不**因选用而向车主重复推送整本旧件特写。

## 5. 车主端信息架构（定稿 2026-09-08）

### 5.1 命名

| 位置 | 文案 |
| --- | --- |
| 列表入口（我的） | **我的相册**（可保留「相册」叫法） |
| 详情页标题 | **服务进度**（或「车牌/车型 + 服务进度」） |
| 内部/接口 | 可继续用 `albumId` 等，不对用户强调「相册照片」 |

商家端仍可称「服务相册 / 流程」；两端不强制同名。

### 5.2 列表（我的相册）与我的首页

视觉与商家相册列表同一套卡片：左封面，右车牌、服务名、状态。进度用文字（待确认方案 / 施工中 / 已完工），不画施工百分比，不把张数当主信息。封面仍可保留。

筛选项：**全部 / 进行中 / 待确认 / 已完工**。待确认 = 有单据等车主点确认。进行中、已完工仍以相册是否完工为界。可评时卡片上保留评价。

**我的**首页：小标题「服务相册 · 车主」+ 称呼。主句写清有几份待确认或进行中。列表默认只放需要车主处理的，最多 3 本：待确认的报价、其它待确认、待评价。不用处理的不占这三格，首页可以少于 3 本。点全部、进行中或待评价后，才列出这一档的其余相册。再点一次当前这项，回到默认的最多 3 本。待确认的车在「进行中」里，靠排序排到前面。排序先看要不要处理：待确认的报价单在最前，然后是接车、检测、交车等其它待确认，再是待评价，不用处理的在最后；同一档按节点更新时间，近的在前。还没看过的更新在卡片上打红点。菜单只留设置。待评价用上面的筛选项。车辆在个人资料里。帮助、联系客服、切换为商家在设置里。不放分享、公开、建相册。

### 5.3 详情（服务进度）

版式对齐商家相册详情，内容仍是车主文书链：

- 抬头：车牌；小标题「服务进度」。
- 车型、里程、店名、状态。
- 横排文书：接车报告、检测报告、报价单、维修工单、交车报告（增项报价插在对应位置）。还没到的灰显且不可点；已送达的可点。
- 竖向时间线只列这些文书，每步一个状态和一句摘要。点已到达的一步，打开与商家预览相同的文书纸。
- 待确认时，协议句在纸外；底栏为「确认」「不同意」，有号码时同时「电话联系门店」。

不放健康分、施工百分比、试车里程、英文小标题、添加留证、联系车主。不逐步镜像商家拍照步。工单摘要与正文不出现金额。  

建议车主标准链：

```
接车报告 → 检测报告 → 报价单 → 维修工单 → 交车报告
```

（增项「施工中新发现」插入在施工期对应位置；质保内容挂在完工确认内，不单独节点。）

- **去掉独立看图入口**（无照片流 / 按节点看图 Tab）。照片仅在单据内作附件，可点缩略图预览。  
- 版式：报告偏证据风；方案/工单/完工偏单据风（见 §6）。

### 5.4 触达与通知

- **关闭**「因相册照片实时更新而主动要订阅消息」的依赖；车主端**不主动**为进度更新弹订阅授权。  
- 商家告知方式：**线下告知**，或 **分享小程序**。  
- 站内消息 / 设置页里与「公开发布」等相关的可选订阅**不在本期强制删除**，但**不得**再作为「车主看见最新进度」的前提。

### 5.5 分享落地

- 有待确认单据时：进入 **服务进度页**，并 **自动滚到 / 高亮** 该待确认步；主操作即确认。  
- **不**做「只有确认按钮、看不到单据上下文」的孤立确认页。

### 5.6 准入与绑定

1. 须 **登录 + 手机号**。  
2. 手机号须与商家建档车主手机号 **一致**，方可绑定并查看该服务进度正文。  
3. 分享链接携带服务 ID，用于打开正确一本；**手机号用于证明车主身份并写入「我的相册」**。  
4. 不一致：不展示单据正文，提示联系门店核对手机号。  
5. **车主不可自助改绑**；纠错由商家在工作台改正建档手机号后，车主再进。

## 6. 视觉 · 只读单据壳（一期）

> **2026-09-09**：车主进度页与商家**只读/已完成预览**共用「纸质单感」只读壳；商家编辑态不贴这层。  
> **2026-10-21**：壳是一张文书纸。墨色细框、宋体文书名、状态章、横线字段、条款单独成框。确认与不同意在纸外，按钮用墨色。商家相册详情列出五张：接车报告、检测报告、报价单、维修工单、交车报告。相册详情和节点预览打开的是同一份文书；「查看完整文件」进入这份全文，不进入节点编辑。  
> 落款写在对应步骤里，并出现在报告底部：接车记接车人、时间；检测记检测人、时间；施工记施工人；交车记交付人、完工时间。

统一结构：

```text
单头：单类型大标题 · 状态 · 店名（有则显）
副行：日期 · 车型/车牌 · 里程
分区正文（按单据类型）
协议条（方案/完工待确认或已确认）
确认 / 不同意（仅车主待确认）
有疑问：电话联系门店（有号码时）
作废说明（增项已取消时：门店已取消或车主未同意 + 原因）
```

| 单据 | 正文 |
| --- | --- |
| 检测报告 | 主诉后按三类分段，**不**再挂结果标签、也不再套「本次检测项目」总题。三类标题用卡片标题级字号 + **色点浅底条**：**需要处理**（红）→ **建议关注**（橙）→ **正常**（蓝）。每项竖排卡：部位 → 三列方图 → 说明默认两行可展开。不对车主展示长免责句。商家只读预览同卡、不分段、可保留结果字 |
| 方案 | 费用明细表感行（左项目右金额，金额加字重；有品牌则次行展示；说明默认两行可展开）→ 合计（左「合计」右金额，不重复「合计」字） |
| 工单 | 施工项（含用料 / 品牌 / 数量）+ 旧件/新件证物图；**不向车主展示金额**（工单金额仅用于与已确认报价核对） |
| 完工确认 | 已施工项（可含品牌）→ 交车图 → 质保（期限 + 注意事项）→ 合计 |

- 方案/工单行名展示**要做的事**（如全车补漆），不是检测部位清单；品牌选填另列；说明为**准备做什么**  
- 检测报告发现项说明为**查到了什么**；车主面三类标题为 **需要处理 / 建议关注 / 正常**（不用「项目」）。扫读靠色点+浅底条：处理 `--color-danger`、关注 `--color-warning`、正常 `--color-primary`；**不**给整卡涂满底色  
- 检测项**禁止左图右文挤成长栏**；多图一律三列网格，不随张数改排法  
- 方案页不展示检测档位与检测图（增项「新发现」区除外）  
- 车主工单状态：工单**不需车主确认**，无「待确认 / 草稿」态，仅作施工留档只读展示  
- 禁止需求话术上屏（§2.4.1 / `ui-copy-audience`）

## 7. 公开层

公域展示已确认件时 **脱敏**；**不**把方案确认真实金额直接公示（公域藏价策略另遵）。

公开档案页（H5）按单据链阅读，并 **单独成章** 展示施工过程图（车主进度页不单独给这一步）。无确认按钮、无协议句。版式见设计体系 §10.8.2、托管口径 [`15_`](../01_项目总览与业务架构/15_案例档案与托管状态机.md) §7.9。

## 8. 实现顺序

1. `26` / 本文口径与字段（含 §5 车主 IA）  
2. 商家单页：核对报告与方案合发 / 工单填写 / 完工确认  
3. **车主端服务进度**：单据时间线、列表进度文案、分享定位、手机号一致绑定、去掉独立看图与相册更新订阅依赖  
4. 施工中增项插入
