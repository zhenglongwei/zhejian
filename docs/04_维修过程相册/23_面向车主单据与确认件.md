## 1. 目标

门店在过程照片之外产出面向车主的结构化单据；**方案确认 / 完工确认** 经车主（或代确认）成为确认件；检测报告与工单逐步可见、无需二次签字。

**车主阅读心智（2026-09-08）**：进相册是为了**看报告与确认单据**，不是翻照片墙。照片只作为某张单据里的**附件证据**。

---

## 2. 单据类型

| 类型 | docType | 主要内容 | 车主 | 生成 |
| --- | --- | --- | --- | --- |
| 检测报告 | `inspection_report` | 主诉 + 发现项（图 + 部位 + 结果三档 + 处理建议） | 与方案同次通知后可阅 | 接车与检测后规则生成 |
| 方案确认 | `quote_confirm` | **部位名** + **真实金额** + 处理建议（不含检测结果标签） | **需确认** | 自报告发现项预填；商家补金额 |
| 工单 | `work_order` | 已确认方案行留档；车主状态不用「草稿」→ **已确认** | 只读 | 方案确认后自动 |
| 完工确认 | `repair_report` | 已施工项 + 交车照 + 质保 | **需确认** | 完工照后生成 |

**废止**：独立 `warranty` 节点；检测报告/工单的车主确认；**单独推送检测报告**（须与方案同次通知）。

增项：再出一张方案确认 → 新工单（见 `26` §3）。

历史别名：`quote`≈方案费用部分；产品文案「报价确认单」一律改为「方案确认」；「维修报告」产品文案为「完工确认」。

---

## 3. 确认件规则

- 仅方案确认、完工确认写入确认件（`immutable`）。  
- 确认文案为平台**固定协议句**；商家编辑页不展示；**车主确认时展示**（进度页待确认步内）。  
- 商家代确认：须弹窗确认「已获得车主确认」；可选证明图。  
- 商家改已确认内容须另存修订（二期）。

固定文案：

| 单据 | 文案 |
| --- | --- |
| 方案确认 | 本人同意按上述项目施工，费用以本单为准。 |
| 完工确认 | 本人确认上述施工与交车状态，并知悉质保条款。 |

---

## 4. 车主逐步可见（业务顺序）

1. **检测报告 + 方案确认**（商家「通知车主」后同屏出现；报告只读，方案待确认）  
2. 方案确认通过后 → 工单（只读）  
3. 完工确认（待确认 → 已确认）  
4. 增项时再次方案确认 → 新工单  

施工/完工过程照片**不**作为车主时间线独立步骤；需要时挂在对应单据内（发现项图、交车照等）。

## 5. 车主端信息架构（定稿 2026-09-08）

### 5.1 命名

| 位置 | 文案 |
| --- | --- |
| 列表入口（我的） | **我的相册**（可保留「相册」叫法） |
| 详情页标题 | **服务进度**（或「车牌/车型 + 服务进度」） |
| 内部/接口 | 可继续用 `albumId` 等，不对用户强调「相册照片」 |

商家端仍可称「服务相册 / 流程」；两端不强制同名。

### 5.2 列表（我的相册）

- **保留封面图**（首张可用证据或商家封面）。  
- **主信息 = 进度文案**（如待确认方案 / 施工中 / 已完工），副文可用最新单据名。  
- 弱化「只看张数/翻照片」观感。

### 5.3 详情（服务进度）

- **竖向时间线 + 单据卡片**，视觉参照商家端流程时间线样式。  
- **单据整链可见，未到步骤灰显且不可点**；已送达 / 待确认可展开阅读与操作。  
- **车主链按单据视角**，不逐步镜像商家拍照步（接车拍照、施工拍照等不单独成车主节点）。  

建议车主标准链：

```
检测报告 → 方案确认 → 工单 → 完工确认
```

（增项方案确认插入在施工期对应位置；质保内容挂在完工确认内，不单独节点。）

- **去掉独立看图入口**（无照片流 / 按节点看图 Tab）。照片仅在单据内作附件，可点缩略图预览。  
- 版式：报告偏证据风；方案/工单/完工偏单据风（见 §6）。

### 5.4 触达与通知

- **关闭**「因相册照片实时更新而主动要订阅消息」的依赖；车主端**不主动**为进度更新弹订阅授权。  
- 商家告知方式：**线下告知**，或 **分享小程序**。  
- 站内消息 / 设置页里与「公开发布」等相关的可选订阅**不在本期强制删除**，但**不得**再作为「车主看见最新进度」的前提。

### 5.5 分享落地

- 有待确认单据时：进入 **服务进度页**，并 **自动滚到 / 高亮** 该待确认步；主操作即确认。  
- **不**做「只有确认按钮、看不到单据上下文」的孤立确认页。

### 5.6 准入与绑定

1. 须 **登录 + 手机号**。  
2. 手机号须与商家建档车主手机号 **一致**，方可绑定并查看该服务进度正文。  
3. 分享链接携带服务 ID，用于打开正确一本；**手机号用于证明车主身份并写入「我的相册」**。  
4. 不一致：不展示单据正文，提示联系门店核对手机号。  
5. **车主不可自助改绑**；纠错由商家在工作台改正建档手机号后，车主再进。

## 6. 视觉 · 只读单据壳（一期）

> **2026-09-09**：车主进度页与商家**只读/已完成预览**共用「纸质单感」只读壳；商家编辑态二期再贴。

统一结构：

```text
单头：单类型大标题 · 状态 · 店名（有则显）
副行：日期 · 车型/车牌 · 里程
分区正文（按单据类型）
协议条（方案/完工待确认或已确认）
确认按钮（仅车主待确认）
```

| 单据 | 正文 |
| --- | --- |
| 检测报告 | 主诉 → **本次检测项目**（图 + 部位 + 结果 + 建议）；不对车主展示长免责句 |
| 方案 / 工单 | 费用明细表感行（左项目右金额）→ 合计 |
| 完工确认 | 已施工项 → 交车图 → 质保 → 合计 |

- 方案/工单行名只展示**部位**；说明为处理建议  
- 车主工单状态：生成后为 **已确认**，不用「草稿」  
- 禁止需求话术上屏（§2.4.1 / `ui-copy-audience`）

---

## 7. 公开层

公域展示已确认件时 **脱敏**；**不**把方案确认真实金额直接公示（公域藏价策略另遵）。

## 8. 实现顺序

1. `26` / 本文口径与字段（含 §5 车主 IA）  
2. 商家单页：核对报告与方案合发 / 工单开始施工 / 完工确认  
3. **车主端服务进度**：单据时间线、列表进度文案、分享定位、手机号一致绑定、去掉独立看图与相册更新订阅依赖  
4. 施工中增项插入
