## 1. 一句话目标

商家按**指引清单**拍照挂图；车主看到的是**真实发生过的作业清单**（有图/有说明才出现），同一检查项可跨接车→检测→施工→完工挂多张图；建议换但未换要能看出来；**永不因清单未完成阻断完工**。

## 3. 跨阶段如何「对上号」（白话）

### 3.1 核心：一份项，多阶段多张图

指引里每一项有稳定编号（如刹车的「刹车片厚度」→ `pad_thickness`）。

```text
检测阶段：拍旧片 → 挂到 pad_thickness → 说明「太薄，建议更换」
施工阶段：拍新片 → 仍挂到 pad_thickness → 说明「已更换××品牌」
完工阶段：可再挂试车/复查图 → 还是 pad_thickness
```

车主打开这一项，按时间看到：**旧况 → 建议 → 新件/过程 → 复查**（有则显示）。

不是「检测一个清单、施工另一个清单」，而是**同一个检查项下追加证据**。

### 3.2 建议换了，但没换成（要打标）

例：检测已挂旧片 +「建议更换」；车主不同意换 / 本次未换 → 施工没有新片图。

| 层 | 表现 |
| --- | --- |
| 商家 | 该项仍在；可标结果为「建议更换·未更换」（或等价）；不强求补新片 |
| 车主 | **仍展示该项**（因为检测已有真实图文）；展示旧片与建议；并标明 **未更换 / 本次未执行更换** |
| 禁止 | 装作已经换好；或因没新片而把检测记录从车主视野抹掉 |

实现上为项增加**处理结果**（示意，名称可调）：

| outcome | 含义 | 车主可见时 |
| --- | --- | --- |
| `observed` | 仅检查记录 | 有图/说明即显示 |
| `recommend_replace` | 建议更换（默认检测后） | 显示建议 |
| `replaced` | 已更换（通常有施工新件图） | 显示旧况+新件 |
| `not_replaced` | 建议过但未换 | **必须打标**「未更换」 |
| `repaired_other` | 已处理（非更换，如清洗/调整） | 按说明展示 |

规则建议：

- 检测说明含建议更换、且该项下**没有任何**归入「施工/完工」且商家标为新件/更换的图 → 默认或提示商家确认为 `not_replaced`（可一键确认）。  
- 商家挂上新件图并可写「已更换」→ `replaced`。

### 3.3 指引有、但店里没拍

例：指引建议拍刹车片，门店认为没必要，**全程未挂任何图、也未写项说明**。

→ **车主清单不出现「刹车片」**。  
指引只约束商家侧「可以拍什么」；车主侧只反映「实际留下了什么」。

## 4. 两套清单视角（必须分清）

| | **指引清单（配置）** | **真实作业清单（车主所见）** |
| --- | --- | --- |
| 给谁看 | 商家编辑 | 车主详情（主阅读） |
| 内容 | `17` 定稿的全量检查项 | **仅**有真实证据的项 |
| 证据 | — | 至少 1 张关联图，**或**非空项说明 |
| 未拍项 | 商家可见（待检/跳过） | **不出现** |
| 目的 | 少漏项、规范拍摄 | 看得懂本次实际查了/建议了/做了什么 |

商家完整度可提示「指引项还剩 N 项未拍」，**绝不**因此阻断完工，也**绝不**把空项推给车主。

## 6. 数据方案

### 6.1 配置

`service-checklist-catalog`：`catalogVersion`、`categoryId`、`inheritsFrom`、`items[]`（字段对齐 `17`）。

匹配：`templateId` 优先；`chassis_noise` 关键词/选择；否则 `default`。

### 6.2 运行时 `albums.checklistJson`

```text
{
  catalogVersion,
  categoryId,
  items: [
    {
      itemKey,
      status: "pending" | "active" | "skipped",  // 商家侧：未动 / 已有内容 / 明确跳过
      outcome: "observed" | "recommend_replace" | "replaced" | "not_replaced" | "repaired_other" | null,
      note: "",
      imageIds: []
    }
  ]
}
```

- `pending` / `skipped` 且无图无 note → **不进车主清单**。  
- 有图或 note → 进入车主清单；`outcome=not_replaced` 时强制展示未更换标记。  
- `album_images.checklistItemKey` + 本图 `caption` 保留。  
- 图片仍落入四阶段 `nodeId`（接车/检测/施工/完工）。

### 6.3 与 evidence 分离

不复用 `evidenceItemsJson`（单据/旧件槽语义不同）。

## 7. 端体验摘要

### 7.1 商家

- 主区：指引清单（可分组）；点项拍照 → 写入对应阶段节点 + itemKey。  
- 施工/完工：选已有项挂图（如挂到 `pad_thickness`）。  
- 对「建议换但无新件图」给出 **标为未更换** 的入口。  
- 去掉教练卡片与阶段 `photoTips` 主文案（隐私「别拍」若需可极简静态一句，不走教练引擎）。

### 7.2 车主

- 详情默认：真实作业清单（项名 + outcome 文案 + 图 + 说明，按阶段或时间排列图）。  
- 无证据项不展示。  
- 点图可进翻页详看。  
- 老相册无 checklist → 回退现有翻图。
