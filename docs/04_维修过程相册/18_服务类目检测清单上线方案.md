## 3. 跨阶段如何「对上号」（白话）

### 3.1 核心：一份项，多阶段多张图

```text
检测：拍旧刹车片 → 挂 pad_thickness → 结果「建议更换」
施工：施工清单自动出现「刹车片」→ 拍新片仍挂 pad_thickness
车主：同一「刹车片」下看到旧况图 + 新件图 + 结果文案
```

### 3.2 检查结果 → 是否进施工清单

**原则：施工是检测的延伸。**  
无检测（无图无标注）→ 无施工；检测正常 → 无施工；检测有问题 → 必有施工。  
施工清单的进队、标签与状态**必须随当前检测结论同步**：图注/快捷标签能明确推断结果时，**以当前图注为准覆盖落库旧 outcome**（例如先标「建议更换」再改「正常」→ 立刻退出施工清单，不得残留「建议更换 / 待施工」）。  
施工清单里若已出现某项，商家上传施工图后**不得**因尚未点标签（空图注）而从列表消失；离开清单须走删除两步（§3.3）。

| outcome | 含义 | 进施工清单？ | 车主（有图/说明时） |
| --- | --- | --- | --- |
| `normal` | **正常** | 否 | 展示检查图 +「正常」 |
| `observed` | 仅检查（未判好坏） | 默认否（可手动加入） | 展示检查记录 |
| `recommend_replace` | 建议更换 | **是**（见下「队列展示」） | 展示建议 |
| `repaired_other` | 需处理 / 已处理（非更换） | **是**（见下） | 按说明展示 |
| `replaced` | 已更换 | **是**（挂新件图） | 旧况 + 新件 |
| `not_replaced` | 建议换但本次未换 | **是**（或已在跟进） | 按 disposition 展示 |

**施工清单展示（与进队区分）：**

| 类型 | 示例 | 是否出现在施工清单 |
| --- | --- | --- |
| 有衍生项的检测父项 | 旧机油状态 | **否**（只解锁子项；父项留在检测节点） |
| 施工衍生项 | 新机油规格 / 机油滤芯 / 新机油液位 | **是**（仅当父项已有留证且标了需处理/需更换，或手增） |
| 无衍生的异常检测项 | 火花塞（同 key 挂施工图） | **是**（检测异常后本项进队） |

衍生项**禁止**仅因自身已有图、而父项未检/未判异常就进入施工清单。

接车建档项（catalog `group=接车建档`，如里程表、到店诉求）：默认**不**因「有说明 / 自由图注」自动进施工清单；仅当图注或结果明确为建议更换/需处理（及已更换/未更换），或**手动加入**时进入。自由说明（如里程数）不得推断为「需处理」。

### 3.3 删除：本次不做 → 是否跟进

商家点「删除」（或完工关卡触发）后：

1. 确认 **本次不做**（施工清单立刻可移除）  
2. 再问 **需要记入跟进、方便回访再约吗？**

| 原因码 | 含义 | 商家后续 | 车主相册 | 案例 |
| --- | --- | --- | --- | --- |
| `skipped` | 本次不做、**不**跟进 | 离开施工清单；不进跟进 | 保留检测图与结果；**不**强调「本次不做 / 暂缓」 | **不写入**正文 |
| `follow_up` | 本次不做、**需**跟进 | 离开施工清单；进完工「跟进清单」 | 展示该项 +「择日再约」及可选说明 | **有证则逐条写入**（项名 + 择日）；无证不写 |

兼容读旧值：`mismatch` → 按 `skipped`；`owner_declined` → 按 `follow_up`。

可手动**新增**施工清单项（从已有检查项中勾选未自动进入者）。跟进清单支持「重新纳入施工」。

### 3.4 指引有、但店里没拍

全程无图无 note → **车主不出现该项**（与首轮一致）。

### 3.5 车主阅读信息架构（2026-08-14 定稿）

| # | 决策 |
| --- | --- |
| A | **阅读单元 = 检查项**；类目（电气/外观/机油机滤…）只做列表**分段小标题**，不当每张卡大标题 |
| B | **检测父项 + 施工衍生项**（如旧机油 → 新机油规格/机滤/液位；刹车油/防冻液同规则）车主端**合成一张主题卡**；商家端仍分项挂图，但清单/待处理**固定成组连续排列** |
| C | 接车/检测/施工**不当第三层标题**；仅多段有图时轻量分段或纯图流；单段有图则省分段标题 |
| D | **结果只在项上出现一次**；图下仅「本图人话」；空说明留空。点选结果标签**只改 outcome，不写入说明框** |
| E | 展示时若整句说明几乎等于结果标签（可带分号），**视为无说明**（兼容旧数据） |
| F | **取消**按「建议更换」等结果聚合成卡 |
| G | 「择日再约」仍占卡，降调展示；无证据空项不展示 |

## 6. 数据方案

### 6.1 配置

同前：`service-checklist-catalog`。  
- `suggestStageId`：`stage_1` / `stage_2` / `stage_6` → 出现在对应节点清单；`stage_5` → **仅施工衍生项**（`workOnly`，不常驻固定施工清单）。  
- `workFollowUpKeys`：父检查项进入施工清单后，自动解锁子项（例：`old_oil` → `engine_oil` / `oil_filter` / `oil_level_confirm`）。

### 6.2 运行时 `albums.checklistJson`

```text
{
  catalogVersion,
  categoryId,
  items: [
    {
      itemKey,
      status: "pending" | "active" | "skipped",
      outcome: "normal" | "observed" | "recommend_replace" | "replaced"
               | "not_replaced" | "repaired_other" | null,
      note: "",
      imageIds: [],
      work: {
        // 施工清单控制（缺省按 outcome 自动推断）
        source: "auto" | "manual_add" | null,
        removedAs: null | "skipped" | "follow_up"
                   // 兼容旧：mismatch→skipped；owner_declined→follow_up
        deferNote: ""   // follow_up 时车主可见回访说明
      }
    }
  ]
}
```

- 进施工清单：`removedAs` 为空，且（有留证且 outcome ∈ 建议更换/需处理/已更换/未更换 **或** `source=manual_add`），建档类默认排除见 §3.2。  
- 跟进清单：`removedAs=follow_up`（及旧 `owner_declined`）。  
- `removedAs=skipped`（及旧 `mismatch`）：不进施工清单、不进跟进。  
- 车主有证项：有图或 note；跟进项展示择日说明；skipped 不强调「不做」。

### 6.3 与 evidence / 配件报价分离

- 不复用 `evidenceItemsJson` 做检查项。  
- **不再**依赖报价单 OCR、配件原厂/副厂类型作为主路径。  
- 完工质保保留（图 + 每图说明 + 一段总说明）；**下线**结算单 evidence 槽（正文不展示，旧图仅存档）。
- **相册藏价**：不引导填写金额，正文不展示金额。

## 7. 端体验摘要

### 7.1 商家

- **采集主路径（A1 · 2026-08-18 · 对齐 `19` §4.0）**：以**项下挂图 + 点选结论**为主；自由备注降权（N1）；主题卡挂「AI 对照」（M2/L2）；完工后主推「生成案例」；机审缺口从案例侧跳回对应主题卡补证。阶段 Tab 结构保留，不做 A2 级「声称工单台」重做。  
- **接车 / 检测 / 完工**：各节点列出本阶段检查/交付项 → 项内多图 + 图下标签；**取消**项级大文本框。  
- **检测**标「建议更换 / 需处理」等（有留证）→ 触发施工延伸；有 `workFollowUpKeys` 时**只解锁衍生项**进施工清单，父项（如旧机油）不出现在施工列表；无衍生时该项本身进清单。  
- **施工**：**仅施工清单**（解锁衍生 + 无衍生异常项 + 手增）；无「跟进服务」区；上传施工图不掉队；删除走两步。  
- **完工**：交付项 +（若有）跟进薄入口；可重新纳入施工；**不**展示施工清单；**无**结算单槽；质保为图文 + 一段总说明；**无**金额填写；**不做**配件三列表。  
- **点完工**：施工清单仍有未施工项 → 逐项强制删除确认，取消则中断；不因检测项未拍完阻断。  
- 顶部不再放独立总清单主操作区。

### 7.2 车主（阅读 · 修订 2026-08-14 · P1 可见时机 2026-08-18）

- **可见时机（P1）**：关联车主对**私密过程本**全程可看——**进行中即可**看已上传的有证项与图；**不是**等完工才开图。案例预览 / 公开页仍须完工后按 `19` §4.0 / §4.3。  
- **AI 解读（M2 · L2 · `19` §4.4）**：上传不自动识图；挂在**主题卡**上按需调用（商家「AI 对照」/ 车主「AI 解读」）；打包该卡全部图；中立真实、可评门店方案且默认包容合理做法；禁止护短作假。  
- **门店说明（N1 · `19` §4.4.3）**：有证项对车主可见须有**门店结论（点选）**；自由备注鼓励、不强制每图长文；AI 为可选增强。  
- 默认：完整有证检查项 + 结果；同项下旧况与施工图一并展示。  
- **阅读单元 = 检查项**：类目（电气 / 外观 / 机油机滤…）只做列表**分段小标题**，不当每张卡大标题。  
- **父子合成**：检测父项与施工衍生项（含多检查项共用施工项）合成 **一张主题卡**；结果只在卡上出现一次；图下仅本图人话说明。  
- **阶段**：接车 / 检测 / 施工仅作轻量分段；**仅一段有图时不展示阶段标题**。  
- **说明去重**：展示时若整句说明几乎等于结果标签（可带分号），视为无说明（兼容旧数据「正常;」）。  
- **点图**：单张全屏预览，再点退出。  
- **下线整本全屏翻页**：车主详情以清单阅读为主；分享 / 评价 / 发布等挂在清单下方。  
- **质保**：清单下方独立「质保承诺」块；无内容则不出现。  
- **取消**按「建议更换」等结果聚合成卡。  
- `follow_up`：仍占卡，降调展示「择日再约」。  
- `skipped`：只保留检测事实，不强调「本次不做」。  
- 无证据项（无图且无真人话说明）不出现。  
- 老相册无 checklist → 按节点过程图做简易阅读卡。

#### 7.2.1 服务项目 = 检查项 + 施工项（车主合成卡真源）

配置真源：`backend/src/constants/service-checklist-work-followups.js`（与 `17` 衍生项一致）。  
合成规则：检查父项 ↔ 其施工衍生项；**共用同一批施工项的多个检查项**并入同一项目卡。  
卡标题优先用检查父项名称（多项父项时顿号并列）；类目名只做分段头。

| 类目 | 分段（group） | 检查项（卡标题参考） | 施工衍生（合入同卡） |
| --- | --- | --- | --- |
| 小保养 / 大保养 | 机油机滤 | 旧机油状态 | 新机油规格、机油滤芯、新机油液位检查 |
| 小保养 / 大保养 | 刹车油 | 刹车油液位 | 刹车油更换/深度检 |
| 小保养 / 大保养 | 防冻液 | 防冻液液位 | 防冻液更换/深度检 |
| 刹车 | 制动检测 | 刹车片厚度、刹车盘厚度… | EPB、新配件、新旧对比等 |
| 电瓶 | … | 电瓶检测读数 | 规格匹配、新电瓶… |
| 轮胎 / 空调 / 钣喷 / 事故车 / 底盘 | 见 catalog | 对应检测父项 | 对应衍生项 |

无衍生关系的检查项（如环车预检、灯光等）→ **各一张卡**，仍按类目分段。

#### 7.2.2 商家标签与排序（与车主对齐）

- 图下快捷标签（正常 / 建议更换 / …）**只写入检查项 outcome**，**不**写入图注；图注仅人话补充。  
- 施工清单中，同一父项解锁的衍生项**固定成组连续排列**（如旧机油链路：新机油规格 → 机滤 → 液位）。

### 7.3 案例文档（2026-08-17 修订）

公开案例要证明「这家店查过、做过判断」，不靠店员写长文。商家通常只拍照并点结果标签。

- **有证检查项完整写入**（有图、有结果或有说明）：项名 + 结果，如「制动液位（正常）」。无证空项不写。  
- **本次施工**：已更换 / 已处理 / 有施工留证的项。  
- **与检查不一致**：只写相册里已有的原因——检查正常故未施工、建议更换但本次未更换、与车主约定择日。不准编性价比或「暂缓无妨」。  
- **`skipped`**：仍不写入。  
- **接车建档**类项不进公开检查清单。

废止「案例只写做成的、跟进最多一句总述」——那会把专业判断藏掉。车主相册阅读规则不变（§3.5）。
