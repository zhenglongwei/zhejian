## 3. 跨阶段如何「对上号」（白话）

### 3.1 核心：一份项，多阶段多张图

```text
检测：拍旧刹车片 → 挂 pad_thickness → 结果「建议更换」
施工：待处理列表自动出现「刹车片」→ 拍新片仍挂 pad_thickness
车主：同一「刹车片」下看到旧况图 + 新件图 + 结果文案
```

### 3.2 检查结果 → 是否进施工待处理

**原则：施工是检测的延伸。**  
无检测（无图无标注）→ 无施工；检测正常 → 无施工；检测有问题 → 必有施工。  
施工列表里若已出现某项，商家上传施工图后**不得**因尚未点标签而从列表消失；移出须选原因（§3.3）。

| outcome | 含义 | 进施工待处理？ | 车主（有图/说明时） |
| --- | --- | --- | --- |
| `normal` | **正常** | 否 | 展示检查图 +「正常」 |
| `observed` | 仅检查（未判好坏） | 默认否（可手动加入） | 展示检查记录 |
| `recommend_replace` | 建议更换 | **是**（见下「队列展示」） | 展示建议 |
| `repaired_other` | 需处理 / 已处理（非更换） | **是**（见下） | 按说明展示 |
| `replaced` | 已更换 | **是**（挂新件图） | 旧况 + 新件 |
| `not_replaced` | 建议换但本次未换 | **是**（或已在跟进） | **必须**打标未更换/暂不处理 |

**施工队列展示（与进队区分）：**

| 类型 | 示例 | 是否出现在施工待处理列表 |
| --- | --- | --- |
| 有衍生项的检测父项 | 旧机油状态 | **否**（只解锁子项；父项留在检测节点） |
| 施工衍生项 | 新机油规格 / 机油滤芯 / 新机油液位 | **是**（仅当父项已有留证且标了需处理/需更换，或手增） |
| 无衍生的异常检测项 | 火花塞（同 key 挂施工图） | **是**（检测异常后本项进队） |

衍生项**禁止**仅因自身已有图、而父项未检/未判异常就进入施工列表。

接车建档项（如里程表、到店诉求）：默认**不**因「有说明」自动进待处理；仅当商家标为建议更换/需处理，或**手动加入**时进入。

### 3.3 待处理删除原因

| 原因码 | 商家操作 | 商家后续 | 车主 |
| --- | --- | --- | --- |
| `mismatch` | 从待处理移除 | 不进跟进列表 | 检测记录照常（若有图/说明）；**不**显示「车主暂缓」类文案 |
| `owner_declined` | 从待处理移入跟进 | **跟进服务列表**保留 | 仍展示该项 + **原因**（如「车主要求暂不处理」） |

可手动**新增**待处理项（从已有检查项中勾选未自动进入者）。

### 3.4 指引有、但店里没拍

全程无图无 note → **车主不出现该项**（与首轮一致）。

## 6. 数据方案

### 6.1 配置

同前：`service-checklist-catalog`。  
- `suggestStageId`：`stage_1` / `stage_2` / `stage_6` → 出现在对应节点清单；`stage_5` → **仅待处理衍生项**（`workOnly`，不常驻施工清单）。  
- `workFollowUpKeys`：父检查项进入待处理后，自动解锁子项进入待处理（例：`old_oil` → `engine_oil` / `oil_filter` / `oil_level_confirm`）。

### 6.2 运行时 `albums.checklistJson`

```text
{
  catalogVersion,
  categoryId,
  items: [
    {
      itemKey,
      status: "pending" | "active" | "skipped",
      outcome: "normal" | "observed" | "recommend_replace" | "replaced"
               | "not_replaced" | "repaired_other" | null,
      note: "",
      imageIds: [],
      work: {
        // 待处理列表控制（缺省按 outcome 自动推断）
        source: "auto" | "manual_add" | null,
        removedAs: null | "mismatch" | "owner_declined",
        deferNote: ""   // owner_declined 时车主可见原因
      }
    }
  ]
}
```

- 进待处理（商家施工）：`removedAs` 为空，且（outcome ∈ 建议更换/需处理/已更换/未更换 **或** `source=manual_add`），建档类默认排除见 §3.2。  
- 跟进列表：`removedAs=owner_declined`。  
- `removedAs=mismatch`：不进待处理、不进跟进。  
- 车主有证项：有图或 note；展示 outcome / deferNote；图按阶段排列。

### 6.3 与 evidence / 配件报价分离

- 不复用 `evidenceItemsJson` 做检查项。  
- **不再**依赖报价单 OCR、配件原厂/副厂类型作为主路径。  
- 完工质保字段保留；结算单 evidence 槽改为建议强度。

## 7. 端体验摘要

### 7.1 商家

- **接车 / 检测 / 完工**：各节点列出本阶段检查/交付项 → 项内多图 + 图下标签；**取消**项级大文本框。  
- **检测**标「建议更换 / 需处理」等（有留证）→ 触发施工延伸；有 `workFollowUpKeys` 时**只解锁衍生项**进待处理，父项（如旧机油）不出现在施工列表；无衍生时该项本身进待处理。  
- **施工**：**只有待处理队列**（解锁衍生 + 无衍生异常项 + 手增），**不**展示未检查过的固定施工清单；上传施工图不掉队；删除待处理必选原因。  
- **跟进服务**：展示车主暂缓项，便于回访。  
- **完工**：交付项 + 可对待处理补复查图；结算单建议；质保引导不阻断；**不做**配件三列表。  
- 顶部不再放独立总清单主操作区。

### 7.2 车主

- 默认：完整有证检查项 + 结果；同项下旧况与施工图一并展示。  
- `owner_declined`：展示暂不处理原因。  
- 无证据项不出现。  
- 可进翻页详看；老相册无 checklist → 翻图。
