## 1.1 增量定稿（2026-07-22）

1. **正文归属商家**：公开案例正文由商家在生成时确认（LLM 仅可基于节点**文字**生成初稿）；车主**不可改正文**，可发评价。案例上店页后评价以打码编号展示。  
2. **公域不写金额**：标题/摘要/正文/FAQ/外发长文均不得出现成交价、价税数字；无须费用免责套话。  
3. **图文隔离**：配图只经脱敏嵌入；**禁止**将原图送入外部大模型生成案例。  
4. **结构模板**：事实块（症状→诊断→方案→施工→结果）；**禁止**批量通用攻略 / 「温馨提示」作公开主文。见 `15_…` §10 与 19 §8。  
5. **生成时不可加图**：公开配图只能来自已锁定相册。

### 1.2 案例即信源（2026-08-17）

面向搜索与大模型的主表面是**公开案例页本身**。案例是辙见的核心：在**内容真实、可核对**的前提下，还要**直接回答这单已经处理过的用户痛点**。不另做专题文章给 AI 搜。

### 1.3 生成 → 机审 → 确认（2026-08-18）

流程、门禁、识图缓存、结构偏移、确认页范围以 [`19_商家发布案例上网口径.md`](./19_商家发布案例上网口径.md) **§4.3** 为准。要点：

- 生成模型与审核模型分离；先生成再机审，通过后才商家确认；**确认即公开，取消运营人审（D14）**。  
- 商家门禁 = **真实性 ≥60**（证明确实发生）；痛点加分不凑及格。  
- 不考系统标题/摘要/问答文笔；不以张数公式及格。  
- 确认页可改措辞；改图回相册；重审整单但识图只跑变更图。

公开案例按一篇文章排：

1. **摘要**（标题下短文）：标题是一句人话（做成的项目）。摘要写检查了多少项、做了什么、与检查不一致的一句（有依据才写）。不要「本单已处理」。  
2. **本单问答**：总结这一单能核对的亮点，并给车主一句叮嘱。优先预算、材料、工序与质保、有没有多做。细则见 §10。  
3. **详情**：检查留证列出有证项+结果；施工留证列成本次做成的；空章不展示。图说：正常只写项名+正常；没原因的需处理不写空话。

**摘要 vs 问答**：摘要是一段话，给人和模型先看懂这页是什么；问答是可被抽成 FAQPage 的独立问句。全过程过程本身写在详情，不编一条「服务全过程是什么」的百科问答。

| 写在案例里 | 不写进案例 |
| --- | --- |
| 这台发动机这次为何不换总成 | 「发动机总成要不要换」的百科答案 |
| 这单保养时的里程与所做项目 | 「保养一般多久做一次」贴到每条案例 |
| 这次灯亮查到什么、怎么处理 | 「故障灯是什么意思」总表 |

覆盖面靠**该店多条真实案例**，不靠一篇写全品类常问。  
**废止**：跨店专题 / 服务答案页当检索入口；AI 生成专题文；用通用 FAQ 凑条；只拼施工日志、不把痛点提到前部。

原专题位改成**该店类目文件夹**：本店该类目公开条数 + 链接，不跨店、不写合成长文。见 [`19_商家发布案例上网口径.md`](./19_商家发布案例上网口径.md) D11–D13。

店夸「技术独到」不进要旨和问答。工艺、5S、扭矩留在详情。  
工期、能否开走、为何不换：以相册备注为准；没写的事实生成器不准补——要在完工前写进相册。对车主的一句叮嘱见 §10，不把没写的期限或结论补进档案。

评价随案例上网（打码编号，见 19 D10）；评价里没有的事实，仍不能写进案例稿。

### 1.3 生成时须预览整篇（2026-08-17）

商家点「生成案例」时，须按即将上网的文章通读确认：摘要 → 本单问答（这单已有答案的痛点）→ 详情与图。配图须先打码，**等打完再展示**；商家看到的就是打码后的上网稿，打码失败的图不拿原图充数。可改表述、去掉图、删对不上的问答；**不能加新图、不能手填相册里没有的结论**。确认后的摘要与问答写入案例稿并随快照冻结。生成器须**主动把痛点问句提到前部**，不得只把六阶段备注原样拼接。

### 1.4 本单问答（2026-09-22）

本单问答用来总结这一单里能核对的亮点，并给车主一句用得上的叮嘱。优先看：钱花在哪（不写金额）、材料、工序和质保、有没有多做。问句、答句、条数和缺项叮嘱以 §10 为准。

商家确认时可改、删、增问答。不能补相册里没有的检查结论、质保期限、配件和金额。

## 4. 生成原则

### 4.1 不泄露隐私

生成内容不得包含：

1. 用户真实姓名；
2. 手机号；
3. 车牌号；
4. VIN；
5. 身份证号；
6. 微信号；
7. 精确地址；
8. 保险单号；
9. 报案号；
10. 实际支付金额，除非后续有明确授权策略。

---

### 4.2 不夸大宣传

不得生成：

1. 保证修好；
2. 永不复发；
3. 全网最低价；
4. 事故车保证全赔；
5. 原厂认证，除非有资质；
6. 绝对化用语；
7. 虚假承诺。

---

### 4.3 价格展示规则（V2.0 · Phase 1 修订 · **2026-07-22 公域藏价**）

| 场景 | 展示 | 数据来源 |
| --- | --- | --- |

## **5. 标题生成规则**

### **5.0 现行公开标题（2026-08-17）**

上网主标题 = **一句检索句**，不是档案袋标签。

```
【城市】【城区】【短车型】【项目】：【这次做了什么（至多三项）】
```

示例：`杭州西湖 起亚赛拉图 大保养：机油、滤芯、雨刮`

- 项目用相册服务名（去掉「过程记录」）；有检查项或配件名时用冒号接上。  
- 店名、地址出现在公开页资料卡（门店 / 城市），不写进 H1。

## **6. 摘要生成规则**

### **6.0 现行摘要（2026-08-17）**

公开案例标题下的短文，页面上叫「摘要」，**由规则从相册抽出 2～4 句**，不是把五段详情粘在一起。

应写：车型 + 痛点/症状一句 + 这次做了什么（检查项或方案一句）+ 交车/质保里已有的一句（有才写）。  
不写：施工 5S、扭矩打卡、占位句「以门店留档为准」、金额、店夸。

「打开预览」即自动把这几句写顺，不加点、不改图。写不顺则展示规则稿，店员仍可手改。不再单独点「AI 润色」。

### **6.1 标准摘要模板**

```
该案例为【车型】在【城市】进行【服务项目】的维修记录。检查发现【主要问题】，门店采用【维修方案】完成处理。案例包含维修前、维修过程、配件或完工效果等图片，图片已进行隐私脱敏。价格展示为参考区间，实际费用会因车型、配件品牌、损伤程度和维修方案不同而变化。

```

---

### **6.2 用户授权案例摘要**

```
该案例经车主授权，记录了【车型】进行【服务项目】的维修过程摘要。内容由门店上传，平台已完成隐私脱敏与展示审核，不代表平台对维修质量或配件真伪作出保证。价格仅展示参考区间。
```

---

### **6.3 历史案例摘要**

```
该案例由门店提供，展示了【车型】进行【服务项目】的维修过程。案例图片已进行隐私脱敏，并通过平台审核。由于该案例为商家历史案例，价格和维修方案仅供参考，实际服务需以到店检测和门店确认为准。

```

### **6.4 摘要长度**

| 案例详情页           | 120-200 字 |

```
旧刹车片状态：可以看到旧刹车片已经出现明显磨损。

```

---

### **9.2 自动说明规则**

每张公开配图最多一行图说，不准从照片里「看」出商家没写的读数或好坏：

| 情况 | 图说 | 例子 |
| --- | --- | --- |
| 结果为正常 | 只写「项名 正常」 | 「刹车油液位 正常」 |
| 已更换 / 已处理 | 项名 + 结果 | 「雨刮器 已更换」 |
| 不正常且相册里有原因 | 项名 + 已有原因 | 「雨刮器 刮不干净」 |
| 需处理但没有项名、也没有原因 | **不写**。禁止「本图为…」「具体状态以图中为准」等空话 | （空） |

不要再用阶段套话凑字。图不进外部大模型；没有文字依据就留空。

选图：公开池按章节轮流取，**交车与质保有图时至少留 1 张**，不要被前面阶段占满默认 8 张上限。施工相册与完工前预览仍看原图；**生成案例预览只展示打码成功的图**。商家预览纳入检测/施工/交车过程图（含因车牌、人脸等暂未过闸、打码后可上网的），不含接车等永远私密图，也不含单据拒收图。

---

### **9.3 图片说明风控**

图片说明不得包含：

1. 车牌；
2. 姓名；
3. 电话；
4. VIN；
5. 精确地址；
6. 保险单号；
7. 夸大描述；
8. 未授权承诺。

## **10. FAQ 生成规则**

> **2026-09-22**：公开问答总结这一单的亮点，并给车主一句叮嘱。公开页读侧见 [`05_FAQ生成规范.md`](../09_SEO_GEO_AI内容基础设施/05_FAQ生成规范.md) §1.2。类目清单只用来提醒往哪看，不当成每单必答题。生成器、预置问和过短过滤随后按本节改。叮嘱写在答句里，不另开「温馨提示」作正文。

### **10.1 FAQ 数量**

有亮点才写。没有可核对亮点时可以为空。有则建议不超过 6 条。

档案里没有、但仍想提醒车主的叮嘱，**一案最多一条**，放在亮点后面。这一单已经写了质保、材料或取舍，就不再另补一句空叮嘱。一条亮点都没有时，可以只留这一句，也可以空着，由商家自己加。

---

### **10.2 FAQ 来源**

从本单节点说明、检查项、交车备注里抽**这一单已经写下的亮点**，写到文章前部。往这些方向看，对得上才写成亮点：

1. **预算**（不写金额）：是套餐还是检查后再定；施工中有没有加项；哪些这次没做。
2. **材料**：规格、品牌、包装或新旧件，档案里有才写。
3. **避坑**：这类服务里车主会核的工序、质保、资质，本单写了就写；可以不做的项目，本单没做或写了依据，也写。
4. **其余能核对的过程**：先查再修、交车确认了什么。有空位再写「公开了哪些节点」。

类目清单（检测该拍什么、该记什么）只提示上面几个方向，不逐条硬出题。清单里没有、档案里也没有的资质或工序，不写成这家的亮点。

占位句「以门店承诺为准」不算质保依据。

**禁止**：用服务模板 / 平台通用 FAQ 凑条数；禁止 AI 补写相册里没有的工期、贬值、质保期限、总成结论、配件和金额；禁止把「服务全过程」写成百科问答；禁止「一般来说」；禁止「专业 / 诚信 / 用心 / 注重透明化」；禁止「很多店不提供」「这项常常是多加的」。

本单没碰到的品类百科，不写进这一条。没有亮点时**可以 0 条**，不要硬凑「至少 3 个」。覆盖面靠该店其他真实案例。

---

### **10.3 FAQ 结构**

```
Q：问题
A：回答

```

亮点问句优先用「这例……」。答句两截：先写这例档案里的事实，再接一句对车主的叮嘱。

叮嘱是让车主去做的动作，例如「修完后要向商家确定质保期」「换片时先问盘厚，再决定要不要连盘」「保养时可以让师傅把规格和包装给你看」。

缺项那一条可以只有叮嘱，问句也可以直接是这件事。不把「没写」写成这家的亮点，不编一个档案里没有的期限或结论。

回答要求：

1. 客观；
2. 不绝对化；
3. 不承诺效果；
4. 不暴露隐私；
5. 不诱导虚假低价；
6. 不替代线下检测；
7. **须有信息增量**：禁止「问：这次修了什么？答：后门」。亮点答句建议不少于 30 字；只有叮嘱的那一条可以说短，说清要确认什么即可。不够就空着留给商家补，或不上公开页。

---

### **10.4 FAQ 示例**

#### **刹车片（档案里有取舍和厚度）**

```
Q：这例为什么没连盘一起换？
A：这例没换刹车盘，档案写的是盘厚还没到更换标准。换片时先问盘厚，再决定要不要连盘。

Q：这例是检查后再定，还是进店就按套餐做？
A：这例先查了片厚和盘面，再决定只换前刹车片，施工中没有新增项目。到店可以先问清是套餐还是检查后再报价。

```

#### **钣喷（档案里写了质保）**

```
Q：这例质保怎么写的？
A：这例写了漆面质保一年。修完后要向商家确定质保期，以及不含哪些。

```

#### **没有质保、也没有别的亮点**

可以只留一条，也可以整段为空：

```
Q：修完后要向商家确认什么？
A：修完后要向商家确定质保期。

```
