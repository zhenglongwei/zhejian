# 商家端 · 事件节点与单据节点链流程（DOC-FLOW）

> **生效**：2026-09-03  
> **状态**：一期骨架 · 产品定稿  
> **废止**：ALB-UX 四 Tab 为主导航；「单据嵌入拍照节点」迭代 1 方案  
> **配套**：[`23_面向车主单据与确认件.md`](./23_面向车主单据与确认件.md) · [`15_案例档案与托管状态机.md`](../01_项目总览与业务架构/15_案例档案与托管状态机.md)

---

## 1. 目标

一次服务 = 一条 **按时间排序的节点链**。节点分两类：

| 类型 | 作用 |
| --- | --- |
| **拍照节点** | 只收过程照片（接车、检测、施工、增项发现、完工照） |
| **单据节点** | 只承载 **一份** 面向车主的单据；可引用上游照片 |

商家编辑页采用 **竖向时间线**（自上而下），禁止横向 Tab 作为主布局。

---

## 2. 标准节点链（无增项 · 9 步）

```
接车 → 检测 → 检测报告 → 报价确认单 → 工单 → 施工 → 完工照 → 维修报告 → 质保单
```

| sort | kind | 显示名 | nodeCategory | 需车主确认 |
| ---: | --- | --- | --- | --- |
| 0 | `intake` | 接车 | photo | — |
| 1 | `inspection` | 检测 | photo | — |
| 2 | `inspection_report` | 检测报告 | document | 否 |
| 3 | `quote_confirm` | 报价确认单 | document | **是** |
| 4 | `work_order` | 工单 | document | 否 |
| 5 | `work` | 施工 | photo | — |
| 6 | `delivery_photos` | 完工照 | photo | — |
| 7 | `repair_report` | 维修报告 | document | 否 |
| 8 | `warranty` | 质保单 | document | 否 |

---

## 3. 增项插入段（二期 · 按需动态插入）

施工中发现新问题：

```
施工 → 增项发现(photo) → 增项报价确认单(document) → 工单(document) → 施工(photo)
```

可多次循环。增项工单复用 `work_order` kind，以 `segmentLabel` / `parentNodeId` 区分。

---

## 4. 生成关系

| 下游单据节点 | 生成来源 |
| --- | --- |
| 检测报告 | 接车 + 检测照片 + checklist |
| 报价确认单 | 检测报告 |
| 工单 | 报价确认单（已确认） |
| 增项报价确认单 | 增项发现照片 + 上下文 |
| 增项工单 | 增项报价确认单（已确认） |
| 维修报告 | 全流程节点汇总 |
| 质保单 | 维修报告 + 店规 |

---

## 5. 确认与代确认

适用于 `quote_confirm`、`addon_quote_confirm`：

| 状态 | 展示 |
| --- | --- |
| 待确认 | 「待车主确认」 |
| 车主已确认 | 「车主已确认」+ 时间 |
| 商家代确认 | 「商家代确认」+ 操作人 + 时间；**可选**上传沟通截图（1–3 张，非必填） |

- 线下沟通 **不上链**；截图仅留痕，平台不审真伪。  
- 确认件 **冻结**；修订 **另存**，不覆盖确认件（见 `case-hosting.service`）。  
- **软提示**：未确认仍可进入下一节点、仍可标记完工。

---

## 6. 数据模型

真源：`albums.content_package_json.flowNodes[]`（`flowVersion >= 1`）。

```json
{
  "flowVersion": 1,
  "flowNodes": [
    {
      "id": "fn_001",
      "kind": "intake",
      "nodeCategory": "photo",
      "sortOrder": 0,
      "title": "接车",
      "status": "in_progress",
      "legacyStageId": "stage_1",
      "photos": [],
      "document": null
    }
  ]
}
```

单据节点 `document` 字段见计划文件 §2.4。拍照节点过程图 **一期** 仍写入 legacy `album_nodes`（`legacyStageId` 映射），保证车主端可读。

### legacyStageId 映射（一期）

| kind | legacyStageId |
| --- | --- |
| intake | stage_1 |
| inspection | stage_2 |
| work | stage_5 |
| delivery_photos | stage_6 |

---

## 7. 门禁

全部 **软提示**，不阻断节点切换、不阻断标记完工。

---

## 8. 分期

| 期 | 范围 |
| --- | --- |
| 一期 | 标准 9 节点链 + 竖向时间线 + 拍照/单据节点页空壳 |
| 二期 | 一键生成单据 + 确认/代确认 + 增项动态插入 |
| 三期 | 类目模板、微信迁入、存量迁移、托管汇总 |

---

## 9. 存量兼容

| 类型 | 策略 |
| --- | --- |
| 新相册（flowVersion≥1） | 走节点链编辑页 |
| ALB-UX 四阶段相册 | 仍走 `edit` 四 Tab；可选后续升级 |
| 六阶段历史 | 只读 + 可选升级 |
