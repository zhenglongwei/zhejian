## 1. 目标

一次服务 = 一条 **按时间排序的节点链**。节点分两类：

| 类型 | 作用 |
| --- | --- |
| **拍照 / 过程节点** | 收过程照片，并在本步 **写齐下游单据所需正文**（主诉、发现项、质保等） |
| **单据节点** | 确认本步后 **自动生成完整单据**；商家可微调后再发给车主 |

商家编辑页 = **单页竖向时间线**（`flow-stepper`）：已完成折叠只读、当前步展开内嵌编辑、未解锁不展示。禁止横向 Tab；上传 **不跳页**。

**原则（内容前移）**：正文在上游过程步填写并自动保存；单据步不再从零逐项补录，只做核对与微调。

---

## 2. 标准节点链（无增项 · 7 步 · flowVersion 3）

```
接车与检测 → 检测报告 → 报价确认单 → 工单 → 施工 → 完工照 → 维修报告（含质保）
```

| sort | kind | 显示名 | nodeCategory | 需车主确认 |
| ---: | --- | --- | --- | --- |
| 0 | `intake_inspection` | 接车与检测 | photo | 商家确认本步 |
| 1 | `inspection_report` | 检测报告 | document | **是** |
| 2 | `quote_confirm` | 报价确认单 | document | **是** |
| 3 | `work_order` | 工单 | document | 否 |
| 4 | `work` | 施工 | photo | 商家确认本步 |
| 5 | `delivery_photos` | 完工照 | photo | 商家确认本步 |
| 6 | `repair_report` | 维修报告（含质保） | document | **是** |

### 渐进展示

- 仅展示：已完成（一行，可点开只读）+ 当前步（展开）。
- 解锁：上一步 `completed` 或单据 `confirmed` → 下一步 `in_progress`。
- 已完成 **不可改**；修订 = 新增同类型节点（二期；正文指纹变了才重确认）。

### 过程步文案与草稿

| 过程步 | 本步须写清（自动保存到节点 `photoDraft`） |
| --- | --- |
| `intake_inspection` | **进店主诉**；接车图本图说明；检测图每张 **部位 / 现象症状 / 检查结果 / 处理建议** |
| `work` | 每张施工图本图说明 |
| `delivery_photos` | 每张完工图本图说明；**质保期限 / 范围 / 除外**（写入维修报告） |

- 确认过程步：缺必填项时 **硬拦截**（弹窗列明缺项），不可生成下游空壳单据。
- 过程图上传 / 改文案后 **自动落库**（防中途退出丢失）。

## 4. 单据字段表与生成规则（真源）

> **不用大模型** 写报告正文。一期规则生成 + 商家微调。  
> 参考区间可写，公域藏精确价策略另遵价格合规文档。

### 4.1 检测报告 `inspection_report`

对标社区店常用检测单：**有图 + 部位 + 现象/症状 + 检查结果 + 处理建议**。  
不用大模型；**在「接车与检测」步写齐**，确认该步后生成 **完整草稿**；单据步仅核对微调。

| 区块 | 字段 | 来源 / 规则 |
| --- | --- | --- |
| 页头 | `vehicleBrand` / `vehicleSeries` / `vehicleYear` | 相册车辆 |
| 页头 | `mileageText` | 接车图注优先，否则车辆里程 |
| 页头 | `chiefComplaint` | 来自过程步 `photoDraft.chiefComplaint`（必填） |
| 页头 | `reportDate` | 生成日 |
| 初始状态 | `intakePhotos[]` | stage_1（图 + 本图说明） |
| 发现项 | `findings[]` | 来自过程步 `photoDraft.findings` / 检测图结构化字段 |
| 未检声明 | `disclaimer` | 固定套话 |
| 结论 | `conclusion` | 可选；过程步可预填，单据步可改 |

**`findings[]` 每项（过程步确认前必填）**

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| `url` / `imageId` | 证据图 | 有照片即有 |
| `partName` | 检查部位/项目 | **是** |
| `symptom` | 现象/症状（客户感受或可见异常） | **是** |
| `result` | 检查结果（现状判断） | **是** |
| `advice` | 处理建议（更换/继续观察/择期等） | **是** |

固定未检套话：

> 本次说明仅针对已拍摄部位；未拍照部位不构成全车体检结论。

**生成时机**：商家在「接车与检测」写齐主诉与发现项并确认 → 生成 **完整** 检测报告草稿 → `pending_confirm`。  
**过程步门禁**：缺主诉或缺任一项部位/症状/结果/建议时，**不可**确认本步。  
**单据步**：仍可修改全文；代确认前再跑同一套缺项校验。  
**下游**：报价确认单可按 `advice` 预填行项草稿，商家可改。

**自动保存**：接车与检测步骤中，上传照片或修改主诉/发现项后写入 `photoDraft` + 过程图落库。

### 4.2 报价确认单 `quote_confirm`

| 字段 | 说明 |
| --- | --- |
| `lines[]` | `{ name, note, priceHint }`；可由检测报告 `advice` **预填草稿**，商家改价/改项后确认 |
| `confirmCopy` | 确认文案（配件说明、费用以到店为准等） |
| `evidenceRef` | 引用检测报告 id / 发现项缩略图 |

**生成时机**：检测报告确认后解锁；按发现项处理建议预填行项（可空则留一行空草稿），商家补全后发送确认。

### 4.3 工单 `work_order`

| 字段 | 说明 |
| --- | --- |
| `items[]` | 自已确认报价行：`{ name, note, technician?, planNote? }` |
| `sourceQuoteNodeId` | 来源报价确认节点 |

**生成时机**：报价确认单确认后 **原样带入**；商家可改技师/计划，不改已确认项目名（改项走修订）。

### 4.4 维修报告（含质保）`repair_report`

= **完工确认单**；取消独立 `warranty` 节点。

| 区块 | 字段 | 来源 |
| --- | --- | --- |
| 摘要 | `chiefComplaint` | 检测报告/主诉 |
| 已施工 | `workItems[]` | 已确认工单/报价行 |
| 验证 | `deliveryPhotos[]` | 完工照 + 图注 |
| 质保 | `warrantyPeriod` / `warrantyScope` / `warrantyExclusions` | **完工照步骤** `photoDraft` 预填，单据步可改 |
| 确认文案 | `confirmCopy` | 认可施工与质保条款；过程步可预填 |

**生成时机**：商家在「完工照」写齐质保要点并确认后，生成 **完整** 维修报告草稿 → `pending_confirm`。  
**单据步**：仍可修改后发给车主 / 代确认。

## 5. 确认与代确认

适用于：`inspection_report`、`quote_confirm`、`repair_report`、`addon_quote_confirm`。

| 状态 | 展示 |
| --- | --- |
| 待确认 | 「待车主确认」 |
| 车主已确认 | 「车主已确认」+ 时间 |
| 商家代确认 | 「商家代确认」+ 操作人 + 时间；**可选**证明图 1–3 张 |

商家在进度页操作；车主在车主端异步确认后回写解锁。确认件冻结；修订另存。

---

## 6. 数据模型

`content_package_json.flowVersion = 3`，`flowNodes[]`。

拍照过程图一期仍写入 legacy `album_nodes`（`legacyStageIds`）。

| kind | legacyStageIds |
| --- | --- |
| intake_inspection | stage_1, stage_2 |
| work | stage_5 |
| delivery_photos | stage_6 |

单据 `document.payload` 即 §4 字段；`document.contentFingerprint` 预留（二期修订比对）。

过程节点可带 `photoDraft`（主诉、发现项、质保等），与过程图一并自动保存；确认过程步时并入下游 `document.payload`。

---

## 7. 门禁

切换步骤与整单完工仍以软提示为主。  
过程步确认时：检测主诉/发现项、完工质保等必填项 **硬拦截**（弹窗列明缺项，见 §2 / §4）。
