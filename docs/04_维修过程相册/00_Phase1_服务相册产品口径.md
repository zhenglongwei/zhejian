## 2. 核心对象：服务相册

| 维度 | Phase 1 定义 |
| --- | --- |
| **定位** | 门店为线下服务创建的 **过程记录相册** |
| **创建** | 商家主动创建；**不绑定** `orderId` |
| **主要用途** | **过程记录与争议证据**（记录了什么、何时记录） |
| **次要用途** | 车主查看；车主主动发布并过审后成为公开案例 / GEO 内容 |

> 对内：**每一次服务，都有据可查** — Phase 1 强调可查，不要求配件/方案车主签字。

### 2.1 客群与轻结构原则（定稿 2026-08-10）

> **总句**：辙见帮中小店把**已经在做的服务**说清楚、留得住、可公开；**不**帮他们再造一套修车流程。  
> **对照**：店内「智检 / 检测模板 / 智能报价 / 工单主流程重构」类产品（如知车）与本文定位不同——可借鉴「车主看得懂」的表达，**不**整体看齐其流程管控。

#### 客群预期

| 客群 | 预期 |
| --- | --- |
| **中小店（主客群）** | 相册是主生产工具：一次拍摄完成留证与说明；公域案例为顺带长出的资产 |
| **大型厂 / 4S** | 不宜假设日用相册（多自有进度小程序；双录入不合理）；公网曝光若合作，须以**零二次录入**（对接/导入）为前提，验证期不作为主叙事 |

#### 五条原则

| # | 原则 | 要做 | 不做 |
| --- | --- | --- | --- |
| 1 | **只增强「留证与说清」，不接管主流程** | 拍什么、本图人话、车主可读、可公开案例 | 接车话术、施工排程、收银进销存、OBD/检测仪、店内报价成交主链路 |
| 2 | **一次完成，不制造第二套作业** | 在辙见完成「拍 + 短说明」即可服务车主查看与后续公开 | 要求与店内系统平行再走一遍检测/工单；大店「再录一遍」 |
| 3 | **结构要有，但是软的** | 按服务类型拍摄提示、示例句、完整度提示、空说明兜底、车主侧检查/问题阅读 | 不勾完检测项不能继续；过线前强制签字才能完工；强制全车红黄绿体检才能交车 |
| 4 | **车主「看得懂」优先于门店「检得全」** | 解释已有照片（说明、摘要、检查/问题清单、对比） | 以检测项覆盖率、报告页数为核心成功指标 |
| 5 | **公开与合规是平台能力，不是店内管控工具** | 脱敏、人审、车主发布、快照、公域藏价 → 可信公开与内容资产 | 用公开/GEO 规则反推加压店内作业（如强迫填满检测模板） |

#### 功能取舍三问（新增能力时必问）

1. 这是在帮「说清 / 留证 / 公开」，还是在改「怎么修车」？  
2. 商家要不要多干一套和原流程重复的事？  
3. 不做会不会阻断完工 / 交车？  

若偏向「改修车 / 双录入 / 强阻断」→ **默认不做或极后置**（与知车式流程产品划界）。

与 §3.1「不阻断完工」、相册教练软引导、检查页为**阅读层**（非店内智检主流程）一致；冲突时以本节哲学 + §3 范围为准。

#### 服务类目检测清单（软清单 · 内容演进）

> **内容真源（检查项已定稿）**：[`17_服务类目检测清单.md`](./17_服务类目检测清单.md)。  
> **方向**：按服务类目提供可勾选、可挂图、可写说明的软清单；施工/完工照片可挂回同一清单项；**车主主阅读 = 清单 + 照片 + 说明**（替代「仅翻图」作为看得懂的主路径）；取消以阶段下一句笼统 `photoTips` 作主引导。  
> **强度**：永不因清单未完成阻断完工。**上线方案**：[`18_服务类目检测清单上线方案.md`](./18_服务类目检测清单上线方案.md)（**决策已确认**；车主见真实作业清单，非完整指引）。

## 3. Phase 1 做什么 / 不做什么

### 3.1 Phase 1（当前 MVP）

> **2026-08-07 · ALB-UX**：新建相册为 **四阶段**（接车 → 检测 → 施工 → 完工）；取消独立「方案与报价」「配件验真」阶段。存量六阶段相册兼容只读/可编辑，不强制迁移。

| 能力 | 说明 |
| --- | --- |
| 四阶段记录 | **接车 → 检测 → 施工过程 → 完工交付**（含质保承诺：承诺书图优先 + 可选时长/范围；强烈建议不阻断完工） |
| 新建建档 | 独立新建页（变薄）：服务项目 + **车牌** + **车架号**（扫描页**打开即自动连续识别**，亦可相册选图 → OCR）+ 车主手机号；创建后进入编辑·接车。车牌作**商家侧相册标题**；公开案例标题**不用车牌**，仍走原案例标题规则 |
| 接车结构化 | **仪表里程表为必拍**（强提示）；VIN/车牌优先在新建页识别写入；VIN 解码品牌/年款/底盘/发动机时**优先查本地缓存，未命中再调阿里云**并落库；**不再**在编辑顶部手填里程数字——公里数建议写在里程照片的「本图说明」；用户端/公开侧仍不展示完整 VIN |
| 图文备注 | **每张过程图须有醒目的本图说明入口**（选填）；前后对比修前/修后**各写一条**；**废止**节点级统一文字说明框（含「示例」占位） |
| 配件/材料 | **并入施工过程**拍摄与备注；**不做**车主「配件验真」流程（入口下线） |
| 单据 | 完工建议上传**结算单**；事故车**定损单**挂接车/检测；**不强制**报价单；**取消**施工工单槽 |
| 关联车主 | 手机号**必填**才能完工；新建页以**手填手机号为主路径**（填写即视为已关联，可拍过程图）；输入框下提供「分享给车主 / 邀请车主扫码」次要入口；进入等待关联后须可**改回手填**（可逆）。未填手机号点创建则进编辑页，不强制进等待页 |
| 标记完工 | **不阻断**；不要求配件/方案车主确认 |
| 用户主导发布 | 相册 `completed` 后，生成可分享长文草稿；车主可 **发给微信 / 复制去社交媒体 / 发布到公开网站**（见 §4.5）；公开权 B/D 调研见开发计划 §7.14（冻结） |
| 脱敏 + 审核 | 商家确认完工后异步 pre-mask → 脱敏结束进入 **案例人审**；通过后车主可看并发布（**不再**发布复审） |
| **施工增项留痕** | **不** 做独立增项审批 UI；增项在施工过程图注 / 结算单中体现 |

## 4. 公开两档 · 用户主导发布（定稿 2026-07-18）

| 档位 | 说明 |
| --- | --- |

**废止（2026-07-12 起新写入）**：`authorizationTier = anonymous`（匿名公示档）。  
**产品文案废止（2026-07-18）**：面向车主的主按钮/主说明 **不再使用「授权公示」**；改用 **「发布到公开网站」**（见 §4.5）。实现层字段名（如 `authorizationTier`、`public-case`）可暂保留，**以产品文案与本节流程为准**。

**原则（不可妥协）**：

1. **用户点一下才上线**——未点「发布到公开网站」前，任何长文草稿、预览、私人分享 **均不上** H5 / GEO。  
2. **不骗车主**——发布前须说清将出现在公开网站；预览 = 即将上网内容（WYSIWYG = PublicView）。  
3. **降低顾虑与 GEO 供给同向**——靠透明、荣誉鼓励与控制感提高愿公开比例；**禁止**用隐瞒渠道或分享领钱换量。  
4. **平台不做物质分享奖励**——产品内仅语言/荣誉激励；物质答谢或现金奖励由运营指导门店线下处理，**不在小程序内配置、承诺或结算**，不在分享按钮上诱导现金。

**不属于「发布到公开网站」**：发给微信好友/朋友圈、复制链接私传、复制文案自行发到小红书等（见 §4.5.4）。

**PublicView**：发布预览与 H5/Feed 读侧真源为 `snapshot.publicView`（轻量公开池）；详见 §4.5.8、`14_PublicView与隐私改造计划.md`。  
**公域知识包与教练**：商家正文归属、公域藏价、配图硬拦、文字-only 完工生成、相册教练规则引擎 → §4.5.9 与 [`15_…`](./15_公域知识包与相册教练规则引擎.md)。

## 4.5 发布到公开网站 vs 自主分享（定稿 2026-07-18 · **修订 2026-07-27 · 案例审核收口**）

> **产品原则**：主语是 **车主自己发布**，不是「授权平台随便用」。  
> **平台审核时机（2026-07-27）**：商家 **确认并完工** 后先异步脱敏，脱敏结束再进入 **唯一阻塞审核**——审 **公示案例内容**（确认案例稿 + 脱敏配图），**不审整本私密相册**。前期 **每单人审**（仅通过/驳回；可重试脱敏；本期不做运营手工打码）。  
> **通过前**车主**不可查看**服务相册（列表可提示审核中）；**通过后**车主可看相册/案例稿并决定是否发布，**发布不再过审**；**撤回/一键下架仅在车主已发布到公开站之后**展示（案例审通过但未授权发布时不得出现撤回）。  
> **废止**：相册完工合规（原闸门 A）作为阻塞审；审前车主可看私密相册；车主点发布后再走闸门 B 人审。  
> **双系统转型（2026-06-08）**：公域发现主战场 = **H5 / 站外 GEO**；小程序 = **服务相册工具**。

### 4.5.1 对照（分享面板三列）

| 维度 | **① 发给微信** | **② 复制去社交媒体** | **③ 发布到公开网站** |
| --- | --- | --- | --- |
| **谁发出** | 车主（微信原生） | 车主（自行粘贴到小红书/知乎/头条等） | 车主点击发布 → **立即**展示（须已过案例审） |
| **典型渠道** | 好友、朋友圈 | 小红书、知乎、今日头条等（车主自选） | **H5 公开案例页、站外 GEO/SEO**（**不含** 小程序案例 Tab） |
| **是否上公开网站** | 否 | 否（第三方由车主账号负责） | **是**（须点发布；**不再**发布后人审） |
| **脱敏** | 强制脱敏图 | 长文与配图建议仅基于脱敏公开池 | 强制脱敏（PublicView） |
| **平台审核** | 否 | 否 | **否**（审核已在门店确认完工后完成） |
| **商家/平台代复制站外长文** | — | **禁止**（只给车主复制） | — |

### 4.5.2 发布到公开网站

- **含义**：车主主动将 **脱敏后、预览过** 的内容提交至公开网站展示位；**立即**出现在 H5 / GEO（可被搜索收录）；**不含** 小程序公域案例 Tab。  
- **前置**：相册 `completed` 且 **平台案例审已通过**（`review_passed`）；未通过时车主不见案例稿与发布入口。  
- **流程**：案例审通过 → 车主打开分享面板 → **预览将上网内容**（WYSIWYG = PublicView）→ 确认 **发布到公开网站** + 留痕 → 写 snapshot → **直接** `published`。  
- **默认不上线**：未点发布的内容 **不会** 出现在 H5 / GEO。  
- **可撤回**：发布后车主可撤回；撤回后公开页下线；**相册仍锁定**，商家不可再改（要改只能新建相册）。  
- **文案语气**：优先「由你发布」「发布前可预览」；成功态说「已发布」。

### 4.5.3 完工后长文草稿与荣誉鼓励

- 相册 **完工后** 可自动生成「可分享长文」草稿（标题/正文/配图建议），**仅车主可见**，**不上网**。  
- **荣誉/心理鼓励**（允许）：帮助同城车主、透明维修体验官（称号可随机轮换，无等级差异）、发布成功感谢等。  
- **禁止**：分享有奖、晒图返现、转发领钱、现金红包挂在分享按钮上（与设计体系 §2.4 / §9、主 PRD §10 一致）。  
- **物质答谢**：不在产品内配置；由运营指导门店线下自行处理。  
- **文案语气**：优先长句邀请（荣誉 + 可下架承诺），避免「授权公示」「发布到公开网站」等敏感短句作主按钮。

### 4.5.3a 小程序 · 公域只读访客态（2026-06-15 · 修订 2026-07-22）

与 §4.5 公开网站展示 **并行、不替代**：

| 用户态 | 小程序内可读 |
| --- | --- |
| **未绑定**任何服务相册（含未登录） | 搜一搜 / 分享深链直达的 **已审核公开** 门店/案例/服务详情（`public_guest`）；关联推荐可含同服务其他门店案例 |
| **已绑定**相册 | 仅相册 **关联门店集合** 内的门店及该店公开内容；**多店可看、互不串内容**（看 A 店只出 A 的案例/服务，不回落别店）；跨店浏览拒绝 |
| 商家分享 / 单店上下文 | 按 `storeId` 隔离展示（与 DS-A-09～11 一致） |

**小程序内 H5 公域出口**：已绑定用户不展示（工具台条件出口、关于辙见「浏览门店」等）；**H5/GEO 网页本身保持公域**，不改。

**禁止**：在小程序首页/Tab 增加跨店发现入口；本规则 **不** 改变「公开网站主渠道仍为 H5/GEO」。

### 4.5.4 用户自主分享（私人传播 + 社交媒体复制）

- **发给微信**：关联车主把 **自己的** 服务相册发给好友/朋友圈；完工即可；**不必** 先发布到公开网站。  
- **复制去社交媒体**：提供适配平台的长文（如小红书/知乎/头条风格）+ **一键复制**；由车主自行粘贴发布；平台与商家 **不代发、不代复制到商家运营账号**。  
- 入口：**我的服务相册** 详情 → **半屏 ShareSheet**（三列，见上表；`docs/02_用户端小程序/07_维修相册查看页.md` §17.4）。  
- **脱敏规则（定稿 2026-07-12）**：私人分享与社交媒体复制稿 **仅脱敏图/脱敏文案**；完整原图 **仅在小程序内**（车主/商家登录态）查看。  
- **废止**：私人分享的「原图模式」（`mode=original`）、`share_raw` 场景授权的新增留痕。  
- **复制私人分享链接**：`completed` 即可；链接带 token，**仅脱敏图**；**不** 自动进公开网站。  
- **复制公开网页链接**：仅 **已发布到公开网站** 后出现。  
- 私人分享 / 社交媒体自发 **不** 等同于上公开网站。

### 4.5.5 文档与实现约束

- 文案禁止：「先授权才能分享」「分享即公开」「分享就有钱」。  
- **允许且推荐**：「发给微信不会自动上网」「发布到公开网站才会出现在案例站（低风险立即展示，高风险需审核）」。  
- **A-MASK**：公开网站链路与私人/社交媒体链路均 **禁止原图对外传播**。  
- **商家端**：可展示「用户已发布且过审」的案例与 H5 链接；**允许**商家可复制**同一确认稿**发自媒体（平台不代发）；**禁止**「商家一键代发到平台运营账号」作主能力。  
- **运营审核台**：人审队列以 **高风险** 为主；另设 **自动过审抽检**（不挡上线，不通过可下架）；审核员 **仅查看脱敏图 + OCR 摘要**，不展示原图（不变）。  
- 历史任务名 **U-CASE-06**（分享与公示解耦）精神保留；产品文案与 ShareSheet 三列以本节为准（落地见开发计划 §7.10 / `CASE-OPS-GATEB-RISK`）。

### 4.5.6 平台案例审（完工后 · **修订 2026-07-27：废相册合规阻塞审**）

| 维度 | **商家** | **车主** | **平台** |
| --- | --- | --- | --- |
| **案例审**（确认完工 → 脱敏结束 → 人审） | 审公示案例稿；驳回→改相册+案例稿再完工 | **通过前不可看**整本相册；**通过后**可看案例并发布 | 人审通过/驳回（前期全量）；脱敏异常可重试；**唯一阻塞审**；**不审**整本私密相册 |
| 六阶段 / 过程图 | **义务**（不阻断完工） | **权利**（监督）；不对完整度负责 | **不**因缺节点 alone 驳回 |
| **车主发布** | — | 脱敏预览 → 点发布 → **立即上线** | **不再**发布后人审 |
| 撤回 | **不解锁** | 公开下线；可再发布（仍基于已锁定内容） | snapshot 留痕；H5 下线 |
| pre-mask | **确认案例稿并完工后**后端**异步**自动（不阻塞完工接口）；就绪后通知车主 | 案例审通过后、发布前预览核对（未就绪则稍后再试） | — |

**废止**：相册完工合规（原闸门 A）作为独立阻塞审；「公示合规驳回 → 用户撤回 → 商家改相册」；以及「发布后再过人审才上网」。

### 4.5.7 案例快照分层与相册锁定（定稿 2026-07-09 · 卷九 · **修订 2026-07-27**）

> 真源：`13_案例全流程快照与GEO分层开发计划.md` · 代码：`case-snapshot.schema.js` · `case-enrichment.schema.js`

| 层级 | 冻结时机 | 可变 | 读侧真源 |
| --- | --- | --- | --- |
| **CaseSnapshot** | 车主确认 **发布到公开网站** 时写入 `content_json.snapshot` | **否**（公开后任何人不得改） | H5 / Feed / 小程序公开案例 **只读 snapshot** |
| **GeoEnrichment** | 审核通过后可由运营维护 | **是**（SEO/FAQ/专题挂载；**不得**改 snapshot 事实与数字） | 页顶摘要、FAQ、TDK 等 **优先 enrichment** |
| **相册 live 数据** | **确认并完工后**商家不可 save（待审/已通过） | **仅**案例审**驳回**可再编辑；**撤回发布不解锁** | **仅** 商家/车主私密查看；**不** 作为已公开案例真源 |

**锁定规则（2026-07-27）**：

1. **确认并完工**后 → 写入案例待审 `pending_review`；商家 `save` / 案例稿修订 / AI 润色 → **409**。  
2. **案例审驳回** → **解锁**商家，可改相册节点与案例稿，再确认完工、再送审。  
3. **案例审通过**（`review_passed`）→ 仍锁定；车主可看稿并发布；**不上线**。  
4. **车主发布** → 须已 `review_passed`；写 snapshot 后立即上线。  
5. **用户撤回** → 公开下线；**不解锁**商家（要改只能新建相册）。  
6. **车主可见性**：案例审通过前**不可查看**服务相册（列表可提示审核中）；通过后开放相册、案例稿与发布入口。

**隐私**：公开链仅 snapshot 内 **脱敏图 URL**（`publicView.media`）；禁止 live 相册原图回退到 H5/站外。

### 4.5.8 PublicView 上传分流（定稿 2026-07-12 · PV-REFORM）

> 真源：`14_PublicView与隐私改造计划.md`

| 原则 | 说明 |
| --- | --- |
| **单上传** | 商家每阶段仍一个「添加照片」；系统按阶段策略 + `publicGate` 写入 `album_images.visibility` |

### 4.5.9 公域知识包 · 文案归属 · 藏价 · 相册教练（定稿 2026-07-22）

> 真源：[`15_公域知识包与相册教练规则引擎.md`](./15_公域知识包与相册教练规则引擎.md) · 任务：`00_开发计划.md` §7.11

| 原则 | 说明 |
| --- | --- |
| **私域全量 / 公域精选** | 私域：六阶段全量留档；公域：商家案例正文 + 脱敏关键帧（约 5～8）+ **随案例公开的车主评价线程**（首评 / 商家回复 / 追评；案例 `public_approved` 后自动公开，无单独勾选） |
| **文案归属** | 案例正文 = **商家服务内容**（类电商商品详情）；车主**不可改文案**，仅可**发布评价**并决定是否上公开网站 |
| **公域藏价** | H5 / GEO / 社交媒体长文 / 朋友圈文案 **一律不写金额**；无须「费用以门店为准」类套话；`planAmount` **仅私域**可见 |
| **完工生成** | **一稿定稿**：点完工先进案例预览；默认按节点文字+公开配图**规则拼稿**（不调大模型）；右上角可选「AI 润色」（文字-only，图不进模型）；含 **案例摘要**（页内与搜索共用，禁止金额）；商家改定后确认 = 最终案例稿；确认后才真正完工并触发公开配图脱敏 |
| **车主预览** | 严格只读呈现商家**确认稿**（摘要+正文不可改）+ 脱敏配图（可删不可加）；公示的是案例文案，不是整本相册 |
| **摘要 / SEO** | **只保留一个「案例摘要」**；搜索描述由摘要截断派生；由商家确认 → 车主只读 → 平台仅审合规，**不**由平台私下另生成主真源摘要 |
| **导出** | 同一确认稿可派生：商家复制发自媒体、车主复制发朋友圈/社交媒体；**平台不代发** |
| **朋友圈** | **不**因公开硬拦而阻止分享；文案仍不写金额 |
| **相册教练** | 规则引擎按**服务类型**提示：要拍什么、别拍什么、备注怎么写；域内规则，**不**用外部大模型看原图教练 |
| **AI 出域** | 未发布前禁止原图进外部多模态；外网只吃脱敏/scrub 数据；详见 15 §3 |
| **确认语文案** | 鼓励式（体验官/避坑指南 + 一键下架承诺）；合规窄授权写在副文案/法律专页；见 15 §13 |

授权确认语须写清：精选脱敏节点照 + 商家脱敏案例说明 +（可选）评价；**不含**个人信息、金额、完整工单；**不含**将全量原图交第三方训练。主界面用荣誉与控制权话术，见 `15_…` §13。
