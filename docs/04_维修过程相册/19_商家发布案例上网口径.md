## 1. 一句话

**门店是公开案例档案的唯一发布者；平台提供脱敏工具与托管站，不担保真实、不担保脱敏零残留；辙见不代通知车主。**  
著作权归门店。公开库是门店选出的橱窗档案。车主可从店页请求撤下公开（取消公开仍私密存档）。

定位（2026-09-03）：**案例站 = 托管主台**；**小程序门店端 = 生产工具**；官网 = 介绍 + GEO 体检。

**公开页**

| 页 | 是什么 | 不是什么 |
| --- | --- | --- |
| **公开案例档案** | 三层：概况+脱敏图文 → 脱敏单据 → FAQ | 平台真实性背书；用户授权背书 |
| **门店页** | 这家店的橱窗与总入口 | 跨店推荐、比价目录 |
| **类目聚合** | 该店某一类目的文件夹 | 跨店百科 |

## 4. 主流程

### 4.0 建册到案例：三成品（2026-08-18 · P1）

同一条采集链上有三种成品，**不互相取代**：

| 成品 | 给谁 | 是什么 | 何时成立 |
| --- | --- | --- | --- |
| **A. 私密过程本** | 车主（+店内留证） | 已上传的图与说明 / 清单阅读 | **建册后随上传逐渐可见（P1）**；进行中可看 |
| **B. 案例预览稿** | 商家 | 打码上网稿 + 机审分与缺口 | **完工后**点生成：生成模型→审核模型→再进确认（§4.3） |
| **C. 公开案例页** | 搜索 / AI / 线索 | 脱敏文章（机审过线 + 商家确认后上线） | 确认发布后 |

- **相册逻辑不废除**：废的是「以整本翻页为产品本体」；A 仍是过程可见与留证。  
- **禁止**把 A 与 C 做成同一页；进行中相册**永不**出公网 URL（D8）。  
- 施工中可给商家**轻量举证提示**（某项还缺证明图，规则提示即可），**不等于**自动识图，也**不等于**出完整 B。  
- **识图调用（M2）**：上传**不**自动跑大模型；仅当用户点 **「AI 解读 / AI 对照」**（§4.4）或商家点 **「生成案例」**（§4.3）时调用。  
- **商家采集（A1 · 2026-08-18）**：编辑主路径 = **项下挂图 + 点选结论**；自由备注降权（N1）；主题卡挂「AI 对照」；完工后主推生成案例；机审缺口跳回对应主题卡补证。不把编辑页收成全新「声称工单台」（那是 A2，本期不做）。

```text
施工中     只写私密相册（可改、可传错、可补）。永不公示。施工过程看原图。
           关联车主可读 A（清单式；已上传才见）。
完工       相册收口。不自动生成案例。后台可开始打码（不挡完工）。
生成案例   打码就绪 → 【生成模型】出预览稿 B → 【审核模型】紧接着机审
           → 两步都完成后才进入商家确认页（见 §4.3）
商家确认   机审已过线且商家确认发布 → **直接公开**（无运营人审，见 D14）
           不过线或商家改了素材 → 回相册改 → 再生成/重审（§4.3）
公开       写 CaseSnapshot → H5 店页可见 C（平台不发短信、不等窗口）
收录       另闸（§8）。店页公开 ≠ 自动进 sitemap / Feed / 专题
```

完工门禁不变：须有车主手机号、内容非空、施工清单未完成项须先处理。  
「生成案例」从占位变为真入口；**不是**完工即上网。

### 4.1 生成时允许 / 禁止

| 允许 | 禁止 |
| --- | --- |
| 从相册 PublicView 池选用可公开打码图 | 在确认页 / 生成页直接再拍照、再上传新图 |
| 确认页编辑标题 / 摘要 / 正文措辞（仍须过合规与再机审规则，见 §4.3.6） | 把相册里没有的图混进公开稿 |
| 预览 = 即将上网内容（WYSIWYG：打码图 + 已写顺文案） | 施工未完工就生成公开案例；预览拿原图充数 |

上述限制做进生成与审核流程，**不靠**生成页长文勾选提醒店长。

漏拍、传错：优先在 **完工前** 改相册。若机审未过线需补证据：按 §4.3 **解锁回相册改素材**（与「确认页禁止直接补图」不冲突——补图只能发生在相册编辑，不能发生在确认页）。

生成预览只展示打码成功的图；打码失败的图不拿原图充数。施工相册编辑页仍看原图。

### 4.2 和土巴兔 / Houzz 的分界（可执行版）

不靠「施工中图一张张出现在公开页」（与发布逻辑矛盾，也不符合现场工期、改错图）。

对外只讲三句真的：

1. 公开内容来自该店这本 **已完工相册**，不是另做一套宣传稿。  
2. **公开后不能改这一页**；完工后默认收口，仅机审未过等路径可解锁回相册改素材后再走 §4.3。  
3. 车主有更完整的私密本，公开后可从店页撤下。

店页须展示 **近 90 天完工数 / 公开数**，避免把橱窗装成全貌。

### 4.3 生成 → 机审 → 确认（GEO 就绪 · 2026-08-18 定稿）

> **取代**：以「张数 / 备注覆盖率」凑公示分、以及「生成后立刻给商家改图说再审」的旧设想。  
> **与** `public-case-quality` 旧均分（证据链+文案、分不够不挡发）**关系**：商家上网门禁以本节 **真实性机审 ≥60** 为准；旧分可作内部参考，不得与本节冲突时挡错对象。

#### 4.3.1 产品原则

1. **考商家的是证据，不是系统文笔**：标题 / 摘要 / 本单问答由生成模型产出，**不**计入商家是否可发。脱敏由平台做，**不**用「打码漂不漂亮」给商家打分；无可公示图等仍属**系统硬门槛**。  
2. **真实性优先**：图文素材是否足以证明「本单声称的检查/处理确实发生」。不是数图。  
3. **痛点加分为过线后锦上添花**：在真实性已过线的前提下，若预览稿能回答本单车主关心的痛点且主张可回溯到素材，则加分；**痛点分不能把真实性不够的单子凑过 60（G1）**。  
4. **双模型分离**：生成模型写稿；审核模型独立打分与给缺口清单；禁止「自己生成自己判高分」。  
5. **先生成、再机审，两步都完成后才给商家确认**（不是先让商家确认图说再生成）。  
6. **取消运营人审（D14）**：机审过线 + 商家确认发布 → 直接写快照上店页。

#### 4.3.2 流水线

```text
相册素材（节点 + 检查/施工项名 + 门店备注/结论 + 脱敏图）
    ↓
【生成案例时】若本图尚无可用识图缓存 → 此时才识图（按图缓存；见 M2）
    ↓
【生成模型】出案例预览（要旨 → 本单问答 → 详情与图）
    ↓
【审核模型】紧接着审：
    · 真实性：只看素材（项归属、门店说明、可公示图、已有识图缓存若有），整单一个分（U1）
    · 列出「哪些声称证据不足」
    · 真实性 ≥60 后，再看「预览 + 素材」评痛点加分（主张须可回溯）
    ↓
商家确认页（仅此时展示稿 + 分 + 结论）
```

> **M2**：日常传图不预跑识图。过程中的读图见 §4.4「AI 解读」。

#### 4.3.3 门禁与展示

| 项 | 规则 |
| --- | --- |
| 发布 | **无真实性机审挡发**。须：公开强制脱敏通过、无系统硬拦（如无可公示过程图等）、商家勾选真实性承诺 → 确认后**直接公开** |
| 痛点分 / 机审分 | 可选内部参考或写作提示；**永不**挡发、**永不**对外展示为「已审核」 |
| 反馈形态 | 脱敏预览 + 承诺勾选；机审缺口清单若保留仅作建议 |
| 未脱敏 / 未承诺 | **不可**公开；引导完成脱敏与承诺 |

#### 4.3.4 识图缓存（成本 · M2）

| 变更 | 识图 | 生成 | 机审 |
| --- | --- | --- | --- |
| 只改手填备注，图文件与项归属不变 | **不重识别**（若已有缓存则复用 + 新备注送机审） | 见 §4.3.5 | **整单重审** |
| 换图 / 新图 | **仅该图**在下次「AI 解读」或「生成案例」时识别 | 见 §4.3.5 | **整单重审** |
| 未改素材仅「再审」 | 全复用已有缓存；无缓存则生成链路按需补跑 | 不重生 | 整单重审 |
| 上传图片 | **不调用**识图 | — | — |

**全部重审 ≠ 全部重识别。** 过程中「AI 解读」与「生成案例」共用按图缓存：同一张图内容未变，不重复识图。

#### 4.3.5 叙述结构是否已偏（E1）→ 是否整稿重生成

生成时冻结 **事实骨架** `skeletonHash`（类目、有证检查项集合与结果、有证施工项集合、检查↔施工对应、图↔项绑定、各图内容指纹）。

**任一触发 → 旧预览作废，整稿重生成，再机审：**

1. 类目变了  
2. 有证检查项集合或项结果有无变了  
3. 有证施工/处理项集合变了  
4. 检查↔施工对应关系变了  
5. 某项下配图集合变了（增删换文件）  
6. 审核返回 `draftStale=true`（旧稿主主张与素材矛盾，或素材已能支撑旧稿未写的主项目）

**未触发 1–5，仅备注润色等：** 不整稿重生；可对图说做补丁；**仍须整单重审**。补丁后若出现 #6，再升格整稿重生。

#### 4.3.6 商家改动与确认页（C1）

| 场景 | 行为 |
| --- | --- |
| 机审未过线 | 回**相册编辑**补证据（为改素材而开，不是确认页上传）→ 变更图重识别 →（E1 则重生）→ **整单重审** |
| 已过线，商家不改素材 | 确认页可改**正文措辞**；若改了措辞 → **须再机审**（通常不重识别、不整稿重生，除非审出 `draftStale`）→ 通过后**确认即公开** |
| 已过线，但仍改图/项等素材 | 回相册改 → 按 §4.3.4 / §4.3.5 → 必须重审 |
| 确认页 | **禁止**直接换图、改项归属、上传新图（C1）；改素材只能回相册 |

#### 4.3.7 明确不考 / 不做

- 不以「过程图张数」「备注字数达标率」作为及格公式。  
- 不以生成稿文笔、标题党程度给商家打「能否发布」。  
- 识图与生成 **禁止编造**未在画面/备注中出现的品牌、工序、结果。  
- 只送**脱敏图**做识图；原图不进外部生成/审核模型。  
- **禁止**上传即自动识图（M2）。

### 4.4 过程本「AI 解读」（按需 · 2026-08-18）

> 解决：光图车主看不懂；光门店备注可能被当成推销；又要避免 AI 短期站队门店、长期失信。

#### 4.4.1 触发与挂载（M2 · L2）

| 谁 | 何时调用大模型识图/解读 |
| --- | --- |
| 车主 / 商家（过程本） | 仅当点击某**主题卡**（检查项/项目卡）上的入口 |
| 商家（案例） | 仅当点击 **「生成案例」**（§4.3；可复用解读缓存） |
| 上传 / 保存图片 | **不**自动调用 |

**挂载级别 = L2 主题卡**（不是类目分段、不是整阶段）：

- 一次调用 = 将该主题卡下**全部图片**打包解读。  
- **商家文案**：「AI 对照」——快速看门店方案与常见合理做法的差别、是否落在合理区间、张力时缺什么证据。  
- **车主文案**：「AI 解读」——看懂图上的问题与常见办法；对门店方案中立包容（§4.4.2）。  

同一挂载、同一按图缓存，避免两套入口两套逻辑。

#### 4.4.2 解读原则（中立 · 真实 · 不挑事 · 不作假）

1. **先说图**：图上可见什么、可能意味着什么问题；看不清就写看不清。  
2. **常见办法**：可列出若干常见处理路径（多方案并存），不写成唯一正解。  
3. **评价门店方案**：可以评；**默认包容**——只要落在合理区间，写明「属于常见合理做法之一」。  
4. **明显不合理**：才克制指出顾虑与依据；禁止辱骂、阴阳、煽动对立。  
5. **禁止护短作假**：不得为保护门店编造症状、夸大或隐瞒可见问题。  
6. **目标句**：问题真实可见；处理路径可有多条；门店方案若在合理集合内则予以认可——这是增强可信与成交的正道，不是调教模型站队。

#### 4.4.3 与门店备注的关系（N1）

- **门店结论必有**：对车主可见的有证项，须有门店结论（点选即可：如正常 / 建议处理 / 已处理 / 择日等）；这是过程本主叙事。  
- **自由备注**：鼓励写清「图上要人看懂的一句」，**不**强制每张图长文才能保存。  
- **「AI 对照 / 解读」**：可选增强（§4.4.1），不替代门店结论。  
- 若解读与门店意见张力大：不删改 AI 真实性；引导门店**补图或补说明**（商家侧提示），而不是让模型改口护短。

#### 4.4.4 缓存

与 §4.3.4 同一套按图缓存：环节解读跑过的图，生成案例时尽量复用；图文件变更则失效重跑。

新公开案例主标签：

```text
门店发布 · 已脱敏 · 已审核
```

| 标签 | 含义 | 禁止听成 |
| --- | --- | --- |
| 门店发布 | 门店提交的脱敏施工记录 | 用户点头授权 |
| 已脱敏 | 公开图无车牌 / 人脸 / VIN / 手机号 | 原图实拍未打码 |
| 已审核 | 已过系统脱敏门槛与大模型机审 | 运营人工逐条看过；平台验过修车质量 |

存量「车主点发布」且仍在线的案例：可保留「已发布」，**不批量改口、不回滚下线**。新单不用「用户授权案例」。  
冷启动 / 事后补图的历史案例：继续弱于「施工当时留下的相册」，不得与本口径新案例同一套信任主 Tag。

信任条可写（到天，非每图钟点）：

- 接车日、完工日、公开日  
- 快照版本、公开图数量、公开日（机审通过并确认发布之日）  

**不写**：相机拍摄时刻、精确上传时分秒、GPS、设备型号。  
公网图片文件继续去 EXIF（尤其定位）。拍摄时刻若抽取，仅供内部排查，不上公开页 / Feed / Schema。

「已审核」的一句说明须固定，例如：

> 平台通过自动脱敏与机审检查隐私打码与宣传合规，不代表对维修质量或配件真伪作出保证。

## 6. 平台不代通知

辙见只做案例生成、打码与机审门禁。**不发**「即将放到店页」的短信或催促式站内信。

| 项 | 规则 |
| --- | --- |
| 上线时机 | **机审过线 + 商家确认发布**即写快照并上店页（无人审） |
| 是否告知车主 | 著作权归门店。打码后仍可能被认出来，当面或微信打个招呼更理想，**不是上网条件**，产品不强制勾选「已告知」 |
| 车主权利 | 公开后可随时从店页撤下；不再设上线前异议窗口 |
| 存量窗口 | 切换日后仍停在 `notify_window` / 因短信失败停在 `review_passed` 的单，按新规则 **立即上店页**（已阻止的除外） |

撤下入口：相册详情、公开页投诉。须让 **拿得到相册分享口令的人** 能撤下，不单认当初填写的微信号。

车主「请门店公开」：可做弱入口（请店生成），发布者仍是店。本期可不做，不阻塞主路径。

## 7. 下架、隐藏、争议

| 动作 | 谁 | 结果 |
| --- | --- | --- |
| 撤下（公开后） | 车主 | 店页下线；本相册不得再提交公开 |
| 下架 | 车主 / 投诉成立 / 运营 | 公开页下线（noindex / 410），移出 sitemap 与检索库 |
| 店页隐藏 | 商家 | 本店主页不再展示该条；**快照保留备查**，不得改图改字后再发一版 |
| 争议冻结 | 运营或系统（进行中投诉 / 纠纷） | 先下线，不得当引用源 |

商家隐藏 ≠ 删除证据。公开后快照一字不改。  
撤回 / 下架 **不解锁** 相册。

## 8. 两层「上网」

### 第 1 层 · 公开记录（机审过线 + 商家确认）

- 出现在该 **门店 H5 主页**及该类目聚合（文件夹）  
- 有稳定案例 URL（**面向 AI / 搜索的主表面**）  
- **不保证** 进 sitemap、JSON Feed

### 第 2 层 · 检索 / 引用库

须同时大致满足（实现时可规则化，本期文档定原则）：

- 证据下限：至少有检测或施工关键帧，且有本图说明；或软清单有结果的项达到下限  
- 新鲜：近 12～18 个月优先进入检索库；更旧的可留在店页文件夹  
- 同类过密：同一店、同一服务、短窗口内重复样本，店页可挂、检索节流  
- 高可识别：事故车严重损伤、稀有车型等默认 **noindex**，运营可放行  
- 隐私与合规已过系统脱敏门槛与机审

门店类目聚合只统计**该店已公开**案例数，并写明：

> 基于本店公开的脱敏记录，不是全部完工相册。

禁止跨店汇总当「杭州刹车片」百科；禁止用未公开相册写可下钻的公网统计。

生成器：从节点说明与检查项抽 **事实句**；禁止补写现场没有的情节；禁止批量通用 FAQ / 「温馨提示」作为公开主文。LLM 仅可整理商家已写文字与**识图图说**（规则见 `19` §4.3），且只吃脱敏文本/脱敏图。商家点「生成案例」时：先出稿再机审，**两步完成后**才看到即将上网的完整文章结构（要旨 → 本单 FAQ → 详情与图）并确认。

## 9. 车主侧产品（小程序）

保留：看私密相册、发给微信（分享这本相册）、写评价、公开后从店页撤下。  

废止作为主路径：分享面板「发布到公开网站」、上线前「先不要公开」、为公开而设的荣誉激励主按钮、**车主复制商家案例稿 / 社交媒体长文**。  

案例已公开后：展示「已在店页」+ 打开 H5 + 从店页撤下。不把店里的上网文案交给车主去复制。  
商家尚未生成：不出现「由你发布」。不承诺「你会先收到平台通知」。

评价：案例上店页后，已提交的评价（含追评、门店回复、脱敏配图）一并出现在公开页。展示默认头像 +「车主 12***47」这类打码编号，**不**展示微信名、手机号或真实账号。评价文字仍须过隐私（配图打码）；从店页撤下案例后评价区一并下线。评价不写入 CaseSnapshot，案例稿改了不影响已写评价。

私人分享仍 **不等于** 上公开网站。私人链仅脱敏图。

## 10. 做进流程，不靠勾选告知

生成页 **不展示** 保证条款长文、**不强制**「已告知车主」。下列由流程挡住：

| 约束 | 怎么挡 |
| --- | --- |
| 只发打码施工过程 | 只能从已锁定相册选图；过脱敏硬门槛与机审才上店页 |
| 说明里不写能认出人的信息 | 系统门禁 + 机审拦车牌 / 人脸 / VIN / 手机号等 |
| 不得拿交车 / 质保胁迫公开 | 产品没有「不公开就不交车」开关；公开与交车解耦 |
| 著作权归门店 | 发布者是店，不是车主 |
| 平台不代通知 | 确认发布即上店页，不发即将上网短信 |

不在产品内承诺「点了有钱 / 被引用有分成」。

## 11. 快照与锁定

| 层级 | 冻结时机 | 可变 |
| --- | --- | --- |
| 相册 live | **确认完工** | 否（机审未过需补证时可按 §4.3 解锁改素材，改完须再生成→机审） |
| CaseSnapshot | **商家确认发布、公开生效时**（机审已过线） | 否 |
| GeoEnrichment | 公开后 | 是（SEO / FAQ / 店内文件夹；不得改快照事实） |

废止：以「车主点发布」为快照写入时机（新单）。  
存量已按旧链路冻结的快照不回写。

H5 / Feed / 小程序公开读侧 **只读 snapshot**。进行中相册禁止任何公开 URL。

## 12. 高风险内容

默认不进第 2 层，机审/规则加严；必要时第 1 层也不过：

- 事故车重大损伤、限量 / 稀有车型仍可被认出来  
- 图中有未打码人脸、工牌姓名、可读书证件  
- 说明里出现车牌、手机、VIN、精确住址  
- 进行中投诉、纠纷  

质保图若含证件版式，按既有公示门禁：证件类不进公开包。

## 13. 明确不做

1. 按引用次数、浏览、咨询给商家或车主分钱  
2. 施工过程中把相册直播到公开网站  
3. 用「必须跨天上传」作为真伪门槛  
4. 公开展示每张图的拍摄时刻或精确上传时分  
5. 生成案例时补拍  
6. 用「已审核」暗示修得好比别家好  
7. 把公开案例库当成评价或质量抽样  
8. 未公开相册的个案写入可下钻的公网 N=  
9. 小程序再做跨店案例广场

## 14. 存量与过渡

- 已上线、由车主点发布的案例：保持在线，Tag 可仍为「已发布」；不要求车主再走一遍。  
- 已完工未生成、或「生成案例即将开放」占位：按本文上线后走商家生成。  
- 审核中的旧单：切换日后过审即上店页。仍停在通知窗口或「待补发短信」的单，立即上店页（车主已阻止的除外）。  
- 历史案例 / 冷启动路径：不并入「施工相册生成」的同一信任主 Tag。

## 16. 验收（口径层）

1. 商家未点「生成案例」并机审过线、确认发布，H5 / GEO 无此单。  
2. 进行中相册无公开页。  
3. 生成接口拒绝新上传媒体。  
4. 机审过线 + 商家确认即上店页（**无人审**）；平台不发即将上网短信；车主可事后撤下。  
5. 公开页无「用户授权案例」、无每图拍摄钟点、无金额。  
6. 案例上店页后评价以打码编号展示，不出现微信名。  
7. 「生成案例」预览含要旨、本单 FAQ、详情与图；FAQ 无依据可空。  
7b. 生成后须机审；商家确认页出现在生成+机审完成之后；真实性低于 60 不可发布。  
7c. 确认页不可直接换图；改素材回相册；换一图整单重审但不重识别未改图。  
7d. 上传不自动识图；主题卡按需「AI 对照/解读」或「生成案例」才调用；解读中立不作假（§4.4）。  
7e. 案例链路无运营人审排队（D14）。  
8. 无跨店专题文章作为检索入口；店内类目仅为文件夹。  
9. 车主下架后公开页下线，相册仍锁定。  
10. 「已审核」旁有质量免责句。  
11. 店页能读到完工数与公开数。  
12. 公网图文件无 GPS EXIF。
