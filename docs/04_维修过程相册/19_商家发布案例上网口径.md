## 1. 一句话

**门店是公开案例的唯一发布者；平台审打码与合规、提供案例生成工具；辙见不代通知车主。**  
公开库是门店选出的施工记录（橱窗），不是质量抽样，也不是可分成的内容资产。著作权归门店。打码后仍可能被认出来，店里当面或微信打个招呼更理想，但**不是上网条件**。车主公开后可从店页撤下。

定位仍是：**真实汽修案例的结构化生成工具**。小程序 = 私密相册工具；H5 / GEO = 公开记录与引用。

## 2. 已确认决策

| # | 决策 | 结论 |
| ---: | --- | --- |
| D1 | 谁上网 | **仅商家**。废止车主「发布到公开网站」作为上网开关 |
| D2 | 平台审什么 | 仅 **脱敏残留 + 违规宣传**。不审文采、不背书维修质量 |
| D3 | 车主角色 | **权利人**（看相册、私人分享、评价、公开后撤下），不是发布者 |
| D4 | 上线前通知 | **平台不代发通知**。审核通过即上店页。是否当面/微信告知由门店自行决定，不是上网条件（§6） |
| D5 | 库的性质 | **门店橱窗**。不代表该店全部完工、不代表平均水准 |
| D6 | 分成 | **不做**按引用/曝光给商家或车主分钱 |
| D7 | 生成时补图 | **不允许**。完工后相册只读；公开图只能来自已锁定相册 |
| D8 | 施工中公开 | **禁止**。进行中相册永不公示；不是边修边往公网传图 |
| D9 | 拍摄时间 | **公网不展示**相机 EXIF / 每图钟点。最多到天的接车日、完工日、公开日 |
| D10 | 评价 | **不随案例自动公开**。评价由车主另行决定是否公开 |
| D11 | 文章 vs 证据 | 生成 **事实块**（检查 / 方案 / 结果 / 打码图），不生成通用攻略文 |
| D12 | 上网分层 | **店页可见** ≠ **进入检索 / 引用库**（§8） |

法务：协议须按本文改写后 **律师审过再上生产**。去标识化 + 车主可撤下，不代替书面合规意见。产品不代通知，不等于法律上一定无需告知。

## 3. 权利怎么拆（不设单一「案例所有权」）

| 层 | 含义 | 权利人 |
| --- | --- | --- |
| 照片与过程说明 | 门店拍摄、填写 | 门店（作者 / 发布者） |
| 车、人、联系方式 | 能否被认出来 | 车主（隐私；公开后可撤下） |
| 脱敏后的公开页 | 打码、结构、上网展示 | 门店提交，辙见传播与审核 |
| 整库、专题、聚合统计 | 多条记录上的检索物 | 辙见（不得把橱窗 N= 说成全部完工） |

禁止对外说「用户授权案例」——商家发布后这句话是假的。  
禁止按单篇案例给任何一方标价或分成。

## 4. 主流程

```text
施工中     只写私密相册（可改、可传错、可补）。永不公示。
完工       相册锁定。不自动生成案例、不送审。
生成案例   商家从已锁定相册摘公开稿（可选图、可整理说明；不可加新图）→ 送审
脱敏       异步 pre-mask（失败可重试或驳回）
人审       只过 / 驳回。驳回 → 解锁商家改相册后须再完工、再生成
公开       人审通过 → 写 CaseSnapshot → H5 店页可见（平台不发短信、不等窗口）
收录       另闸（§8）。过审公开 ≠ 自动进 sitemap / Feed / 专题
```

完工门禁不变：须有车主手机号、内容非空、施工清单未完成项须先处理。  
「生成案例」从占位变为真入口；**不是**完工即上网。

### 4.1 生成时允许 / 禁止

| 允许 | 禁止 |
| --- | --- |
| 从已锁定相册选择可公开图（PublicView 池内） | 再拍照、再上传、再从手机加入新图 |
| 编辑标题 / 摘要 / 节点说明（仍须过合规） | 把相册里没有的图混进公开稿 |
| 预览 = 即将上网内容（WYSIWYG） | 施工未完工就生成公开案例 |

上述限制做进生成与审核流程，**不靠**生成页长文勾选提醒店长。

漏拍、传错：在 **完工前** 改相册。完工后要改：本阶段仍无「解开」，只能新建相册（与现行锁定一致）。

### 4.2 和土巴兔 / Houzz 的分界（可执行版）

不靠「施工中图一张张出现在公开页」（与发布逻辑矛盾，也不符合现场工期、改错图）。

对外只讲三句真的：

1. 公开内容来自该店这本 **已完工相册**，不是另做一套宣传稿。  
2. **完工后不能改相册，公开后不能改这一页。**  
3. 车主有更完整的私密本，公开后可从店页撤下。

店页须展示 **近 90 天完工数 / 公开数**，避免把橱窗装成全貌。

## 5. 标签与信任文案

新公开案例主标签：

```text
门店发布 · 已脱敏 · 已审核
```

| 标签 | 含义 | 禁止听成 |
| --- | --- | --- |
| 门店发布 | 门店提交的脱敏施工记录 | 用户点头授权 |
| 已脱敏 | 公开图无车牌 / 人脸 / VIN / 手机号 | 原图实拍未打码 |
| 已审核 | 平台查过打码与违禁 | 平台验过修车质量 |

存量「车主点发布」且仍在线的案例：可保留「已发布」，**不批量改口、不回滚下线**。新单不用「用户授权案例」。  
冷启动 / 事后补图的历史案例：继续弱于「施工当时留下的相册」，不得与本口径新案例同一套信任主 Tag。

信任条可写（到天，非每图钟点）：

- 接车日、完工日、公开日  
- 快照版本、公开图数量、审核通过日  

**不写**：相机拍摄时刻、精确上传时分秒、GPS、设备型号。  
公网图片文件继续去 EXIF（尤其定位）。拍摄时刻若抽取，仅供审核后台，不上公开页 / Feed / Schema。

「已审核」的一句说明须固定，例如：

> 平台审核针对隐私打码与宣传合规，不代表对维修质量或配件真伪作出保证。

## 6. 平台不代通知

辙见只做案例生成、打码与合规审核。**不发**「即将放到店页」的短信或催促式站内信。

| 项 | 规则 |
| --- | --- |
| 上线时机 | 人审 **通过即写快照并上店页** |
| 是否告知车主 | 著作权归门店。打码后仍可能被认出来，当面或微信打个招呼更理想，**不是上网条件**，产品不强制勾选「已告知」 |
| 车主权利 | 公开后可随时从店页撤下；不再设上线前异议窗口 |
| 存量窗口 | 切换日后仍停在 `notify_window` / 因短信失败停在 `review_passed` 的单，按新规则 **立即上店页**（已阻止的除外） |

撤下入口：相册详情、公开页投诉。须让 **拿得到相册分享口令的人** 能撤下，不单认当初填写的微信号。

车主「请门店公开」：可做弱入口（请店生成），发布者仍是店。本期可不做，不阻塞主路径。

## 7. 下架、隐藏、争议

| 动作 | 谁 | 结果 |
| --- | --- | --- |
| 撤下（公开后） | 车主 | 店页下线；本相册不得再提交公开 |
| 下架 | 车主 / 投诉成立 / 运营 | 公开页下线（noindex / 410），移出 sitemap 与检索库 |
| 店页隐藏 | 商家 | 本店主页不再展示该条；**快照保留备查**，不得改图改字后再发一版 |
| 争议冻结 | 运营或系统（进行中投诉 / 纠纷） | 先下线，不得当引用源 |

商家隐藏 ≠ 删除证据。公开后快照一字不改。  
撤回 / 下架 **不解锁** 相册。

## 8. 两层「上网」

### 第 1 层 · 公开记录（人审通过）

- 出现在该 **门店 H5 主页**  
- 有稳定案例 URL  
- **不保证** 进 sitemap、专题、JSON Feed、聚合 N=

### 第 2 层 · 检索 / 引用库

须同时大致满足（实现时可规则化，本期文档定原则）：

- 证据下限：至少有检测或施工关键帧，且有本图说明；或软清单有结果的项达到下限  
- 新鲜：近 12～18 个月优先进入专题统计；更旧的可留在店页  
- 同类过密：同一店、同一服务、短窗口内重复样本，店页可挂、检索节流  
- 高可识别：事故车严重损伤、稀有车型等默认 **noindex**，运营可放行  
- 隐私与合规已过审

GEO 聚合数字必须写明口径：

> 基于门店公开的脱敏记录，不是全部完工相册。

禁止用未公开相册的个案去写可下钻的公网统计。内部产品分析另计，不写入公开页。

生成器：从节点说明与检查项抽 **事实句**；禁止补写现场没有的情节；禁止批量通用 FAQ / 「温馨提示」作为公开主文。LLM 仅可整理商家已写文字，且只吃脱敏文本。

## 9. 车主侧产品（小程序）

保留：看私密相册、发给微信、复制去社交媒体、写评价、公开后从店页撤下。  

废止作为主路径：分享面板「发布到公开网站」、上线前「先不要公开」、为公开而设的荣誉激励主按钮。  

案例已公开后：展示「已在店页」+ 打开 H5 + 从店页撤下。  
商家尚未生成：不出现「由你发布」。不承诺「你会先收到平台通知」。

评价：默认仅店与车主可见；车主可单独选择「把评价公开展示」（须案例已公开或同时满足脱敏）。**禁止** 案例一公开就自动公开评价线程。

私人分享仍 **不等于** 上公开网站。私人链仅脱敏图。

## 10. 做进流程，不靠勾选告知

生成页 **不展示** 保证条款长文、**不强制**「已告知车主」。下列由流程挡住：

| 约束 | 怎么挡 |
| --- | --- |
| 只发打码施工过程 | 只能从已锁定相册选图；过脱敏与人审才上店页 |
| 说明里不写能认出人的信息 | 人审拦车牌 / 人脸 / VIN / 手机号等 |
| 不得拿交车 / 质保胁迫公开 | 产品没有「不公开就不交车」开关；公开与交车解耦 |
| 著作权归门店 | 发布者是店，不是车主 |
| 平台不代通知 | 审核通过即上店页，不发即将上网短信 |

不在产品内承诺「点了有钱 / 被引用有分成」。

## 11. 快照与锁定

| 层级 | 冻结时机 | 可变 |
| --- | --- | --- |
| 相册 live | **确认完工** | 否（人审驳回除外，驳回后改完须再完工再生成） |
| CaseSnapshot | **人审通过、公开生效时** | 否 |
| GeoEnrichment | 公开后 | 是（SEO / FAQ / 专题；不得改快照事实） |

废止：以「车主点发布」为快照写入时机（新单）。  
存量已按旧链路冻结的快照不回写。

H5 / Feed / 小程序公开读侧 **只读 snapshot**。进行中相册禁止任何公开 URL。

## 12. 高风险内容

默认不进第 2 层，人审加严；必要时第 1 层也不过：

- 事故车重大损伤、限量 / 稀有车型仍可被认出来  
- 图中有未打码人脸、工牌姓名、可读书证件  
- 说明里出现车牌、手机、VIN、精确住址  
- 进行中投诉、纠纷  

质保图若含证件版式，按既有公示门禁：证件类不进公开包。

## 13. 明确不做

1. 按引用次数、浏览、咨询给商家或车主分钱  
2. 施工过程中把相册直播到公开网站  
3. 用「必须跨天上传」作为真伪门槛  
4. 公开展示每张图的拍摄时刻或精确上传时分  
5. 生成案例时补拍  
6. 用「已审核」暗示修得好比别家好  
7. 把公开案例库当成评价或质量抽样  
8. 未公开相册的个案写入可下钻的公网 N=  
9. 小程序再做跨店案例广场

## 14. 存量与过渡

- 已上线、由车主点发布的案例：保持在线，Tag 可仍为「已发布」；不要求车主再走一遍。  
- 已完工未生成、或「生成案例即将开放」占位：按本文上线后走商家生成。  
- 审核中的旧单：切换日后过审即上店页。仍停在通知窗口或「待补发短信」的单，立即上店页（车主已阻止的除外）。  
- 历史案例 / 冷启动路径：不并入「施工相册生成」的同一信任主 Tag。

## 15. 文档与实现顺序

**已确认。** 实现顺序：

1. 协议与车主侧撤下文案（平台不代通知）  
2. 生成案例 API + 预览（无新图）+ 送审（无保证条款勾选）  
3. 审核通过即上线；车主公开后可撤下  
4. 快照写入改到公开生效时；评价与案例公开解耦  
5. 店页完工数 / 公开数；Tag 与信任条  
6. 第 2 层收录规则（可稍后于 1～5，但不得在无闸门时把全部第 1 层打进 sitemap）

任务勾选见 [`docs/00_开发计划.md`](../00_开发计划.md) §7.14。

## 16. 验收（口径层）

1. 商家未点「生成案例」并过审，H5 / GEO 无此单。  
2. 进行中相册无公开页。  
3. 生成接口拒绝新上传媒体。  
4. 审核通过即上店页；平台不发即将上网短信；车主可事后撤下。  
5. 公开页无「用户授权案例」、无每图拍摄钟点、无金额。  
6. 评价默认不随案例公开。  
7. 车主下架后公开页下线，相册仍锁定。  
8. 「已审核」旁有质量免责句。  
9. 店页能读到完工数与公开数。  
10. 公网图文件无 GPS EXIF。
