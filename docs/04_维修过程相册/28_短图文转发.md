# 短图文转发（朋友圈 / 小红书 / 抖音）

> 定稿 2026-11-01。车主与商家都要能把「几张打码过程图 + 一段短句」带走，自己贴到自媒体。平台不代发。

## 要解决什么

朋友圈、小红书、抖音上被人看见的是图文本身。小程序卡片和纯文字长稿都带不走过程图，传播很弱。

完工后的相册、已有正文的案例，第一次还没有成稿时，才把这一本案例和下面的类目规矩交给大模型。成稿跟这本相册存着，车主和门店各留一份。再次打开直接用上次的。弹窗里点「刷新」才重跑并覆盖。照片只看一次。后面几步重复用同一份事实，以及已经提炼出来的话。

1. **先自由提炼，并挑出适合传播的图。** 这一步不带类目表。只找这本案例最出彩的一点。它可以是车主最关心的，也可以是能看出这家店手艺的。同时从这本相册的打码过程图里挑出能说明这一点的图。挑中的全部带上，打开后不再勾选。已经分析过的图只带上次留下的分析文字，不再把图送进去看。还没分析过的，只在这一步看一次，并把看见的那一句写进这张图自己的记录。之后整理、节点意见、核对、图说再用来，只带这句，不再把图送进去。
2. **再比一比。** 拿这一本案例和类目规矩对照，看是不是差不多。差不多，就把出彩处收成一个主题。
3. **差得远才做决定。** 三条路里选一条：按规矩提炼、保持原来的出彩处、或者融成一个主题。只留一个。原则是带给消费者价值。用的是上一步已经取出的话和同一份案例事实，不再为了找新点去看照片。
4. **按这个主题写。** 三个平台都写它，句子只围绕这本相册里有的东西。每张图上的短字对应该张已有的分析，不再把图送进去看第二遍。

原图、金额、电话、链接不进模型。看不清的不猜，事实里没有的结果不编。某一步写不出时，用这些事实拼一句最短的顶上，不冒充写好的平台稿。

照片是实拍。画面上不印「AI 生成」。

类目规矩如下。差不多时，主题落到车主拿来打分的那一眼；差得远时，按上面第三条决定：

| 这本相册主要是 | 车主在意 | 点到就停 |
| --- | --- | --- |
| 划痕、凹陷、钣喷 | 好不好看，以后卖车看得出来吗 | 色差、钣金平不平、腻子厚不厚。没有补完的图，不写成已经补好 |
| 事故、动过结构 | 保值 | 结构动没动、腻子厚不厚、色差以后能不能被看出来 |
| 刹车 | 安全 | 片还剩多少、盘有没有槽、要不要连盘一起换 |
| 轮胎 | 安全 | 鼓包、沟深、胎侧，哪一种不能再拖 |
| 底盘、异响 | 安全 | 什么时候响、松的是哪、现在还能不能开 |
| 空调 | 好不好用 | 凉不凉、有没有味，脏的是不是滤芯 |
| 保养、机滤机油 | 会不会多花钱 | 旧件脏成什么样，哪一项不用顺手加 |
| 电瓶 | 安全 | 打不着火之前先有什么征兆 |

一本里如果还有别的部位，图上只标那一张自己的一眼，不另起一个主题。

- **朋友圈**只写给熟人。一段配文，两到四句，第一句就是这个主题在这台车上的样子，然后停。字不印在照片上。照片是按顺序分开的方图，张数用 1、3、4、6、9，多出来的从后面去掉。车主用「我这台」。门店用「这台」，可以收一句「过来坐坐」，不每条都写。
- **小红书**是一组同样大小的竖图，比例 3:4，左右滑。每张图上一行短字，必须这张图里看得到。笔记正文另给一段，围绕同一个主题和这台车，给人和站内搜索看。第一张是最能说明这个主题的那张。
- **抖音**是一组竖图，比例 9:16，左右滑。每张图上一行短字。描述另给一段，回答这个主题在这台车上是怎样，不写口播腔。
- 车主和门店不共用一篇稿。三个平台的句子也不写成同一段。车主不写「过来坐坐」。
- 弹窗照着发出去的样子排。朋友圈是方图加一段配文。小红书、抖音先看到当前这张竖图，短字就在图的底部；点下面的小图，换成另一张和它自己的那句。正文、描述在图下面，复制后自己贴到对应 App。

## 明确不做

- 不再生成知乎、头条、公众号，以及任何五平台长文。旧长文不迁进短图文；之后内容包落库时不再写这些长文。
- 不把私人相册链接写进默认短句。短句本身就能看懂；链接仍由「复制相册链接」单独复制。
- 不代发到任何账号，不出现分享领钱、返现、全网最低、包修好。
- 短句不写金额。发出去的图只用打码成功的地址，不用原图。
- 车主不复制商家写给网站的长文。

## 对象怎么装

短图文是一次导出，不另存一份会和相册走散的稿。

- **什么算一份：** 某一本相册 × 一种口吻（车主或商家）× 一个平台。永远这三份，不能另加平台，也不能删掉某一份再把后面的顶上来。
- **身份：** 平台 id（`moments` / `xiaohongshu` / `douyin`）。改字，份还是这一份。不是列表里的第几张。
- **图的身份：** 优先用相册图片自己的 id。旧数据没有 id 时，用「节点 + 这张图在节点里的序号」。完工后节点内顺序不再变，所以这个备用身份是稳定的。不用本次导出列表的第几张，也不用图片地址当身份。
- **住在哪：** 上次生成的结果跟这本相册走，按口吻分开（车主一份、门店一份）。打开时读这份，不重跑。点刷新才重写并覆盖。一份里有：一个主题（三个平台共用这一次的主题），跟图片 id 走的一行短字（小红书、抖音印在该张图上；朋友圈这行是空的），以及一段配文（朋友圈的配文、小红书正文、抖音描述）。短字的身份是图片 id，不是第几张，也不是图片地址。自由看到的出彩处、挑中的图、和规则差多少、差得远时走的哪一条（按规则、保持、融合）、最终主题，都留在当次调用记录里，不进界面。图只引用打码图。这一次带上哪些图，由生成时按已有分析挑定，全部带上。再次打开沿用这份名单，不重新挑。不在界面上勾选或取消。小红书、抖音点一张，是在改这一张上的字，不改这组图。改的是哪一个平台的字，就只改那一份。三个平台用同一套照片顺序，顺序由这个主题决定，第一张是最能说明主题的那张。没被挑中的图留在相册里，不删除。
- **车主事实来自相册**（服务名、车型、门店、节点备注）。**商家事实来自案例正文**（标题、摘要、各节）。配图都只取打码成功的过程图，接车单、报价单不进这组图。最多 9 张。
- **旧数据：** 库里已有的五平台长文读短图文时忽略，不按段落顺序配图。不做一次性改写成新稿。

## 两端入口

| 谁 | 在哪 | 看见什么 |
| --- | --- | --- |
| 车主 | 评价已保存之后（含再次打开这篇评价） | 底栏「下载图文」。评价表单上不放 |
| 商家 | 完工后的相册总览，托管按钮左边 | 「下载图文」与「托管到案例站」或「管理托管」并排。托管按钮仍是主操作 |

照片还没打完码时，图片区只留一句「照片还在处理」或「打码完成后可保存」。有照片之后，下载先把这一组图准备完，再按当前平台的顺序一张一张存进相册。全部存完才提示已保存。朋友圈只有「配文」。小红书、抖音是「这张图上的字」，另有「正文」或「描述」，可以复制。点一张是在改这一张上的字。

界面不解释模型、搜索或剪贴板。平台名、图、要改的字、下载就够。
