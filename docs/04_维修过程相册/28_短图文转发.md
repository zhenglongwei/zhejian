# 短图文转发（朋友圈 / 小红书 / 抖音）

> 定稿 2026-11-01。车主与商家都要能把「几张打码过程图 + 一段短句」带走，自己贴到自媒体。平台不代发。

## 要解决什么

朋友圈、小红书、抖音上被人看见的是图文本身。小程序卡片和纯文字长稿都带不走过程图，传播很弱。

完工后的相册、已有正文的案例，打开时由大模型按三个平台各写一版。模型看打码后的过程图（最多 4 张）和相册里已有的事实。原图、金额、电话、链接不进模型。看不清的不猜，事实里没有的不编。模型暂时写不出时，用这些事实拼一句最短的顶上，不冒充写好的平台稿。

照片是实拍。画面上不印「AI 生成」，也不要求把这张实拍图标成生成图。

- **朋友圈**只写给熟人。像本人随手发的一两句，第一句就是这件事，带一个过程里真实的细节，然后停住。车主用「我今天把……做了」，门店用「这台车今天……」。字在照片上方，照片按九宫格。不写成封面标题，不写「家人们」「过程记一下」。朋友圈只下载这一张图，没有另贴的正文。
- **小红书**同时写给人和站内搜索、问一问。封面上的字让人一眼知道内容，也让机器知道主题：车型、部位、这一例的事实放在最前。正文第一句把结论说完，后面按现象、看到什么、怎么处理分成短句。封面字和正文说同一件事。不写悬念标题，不堆关键词。
- **抖音**同时写给人和搜索、豆包。画面上只留一两句能扫完的事实，车型或城市、做了什么放在前面。描述里用完整的事实句回答「什么车、做了什么、结果怎样」，给发布页的描述框。不写口播腔。
- 车主和门店不共用一篇稿。三个平台的句子也不写成同一段。

## 明确不做

- 不再生成知乎、头条、公众号，以及任何五平台长文。旧长文不迁进短图文；之后内容包落库时不再写这些长文。
- 不把私人相册链接写进默认短句。短句本身就能看懂；链接仍由「复制相册链接」单独复制。
- 不代发到任何账号，不出现分享领钱、返现、全网最低、包修好。
- 短句不写金额。发出去的图只用打码成功的地址，不用原图。
- 车主不复制商家写给网站的长文。

## 对象怎么装

短图文是一次导出，不另存一份会和相册走散的稿。

- **什么算一份：** 某一本相册 × 一种口吻（车主或商家）× 一个平台。永远这三份，不能另加平台，也不能删掉某一份再把后面的顶上来。
- **身份：** 平台 id（`moments` / `xiaohongshu` / `douyin`）。改字、勾掉某张图，份还是这一份。不是列表里的第几张。
- **图的身份：** 优先用相册图片自己的 id。旧数据没有 id 时，用「节点 + 这张图在节点里的序号」。完工后节点内顺序不再变，所以这个备用身份是稳定的。不用本次导出列表的第几张，也不用图片地址当身份。
- **住在哪：** 每次打开现写，不另存一份会和相册走散的稿。一份里有两段字：画上的字（朋友圈的配文、小红书的封面、抖音画面上的短句）和小红书正文、抖音描述。朋友圈没有第二段。图只引用打码图，不把文件再复制进文案。勾选和改字只影响这一次，不从相册删图。改的是哪一个平台的字，就只改那一份。
- **车主事实来自相册**（服务名、车型、门店、节点备注）。**商家事实来自案例正文**（标题、摘要、各节）。配图都只取打码成功的过程图，接车单、报价单不进这组图。最多 9 张。
- **旧数据：** 库里已有的五平台长文读短图文时忽略，不按段落顺序配图。不做一次性改写成新稿。

## 两端入口

| 谁 | 在哪 | 看见什么 |
| --- | --- | --- |
| 车主 | 评价已保存之后（含再次打开这篇评价） | 底栏「下载图文」。评价表单上不放 |
| 商家 | 完工后的相册总览，托管按钮左边 | 「下载图文」与「托管到案例站」或「管理托管」并排。托管按钮仍是主操作 |

照片还没打完码时，图片区只留一句「照片还在处理」或「打码完成后可保存」。有照片之后，三个平台都是「下载图文」一张。小红书另有「封面」「正文」和「复制正文」。抖音另有「画面上的字」「描述」和「复制描述」。朋友圈只有「配文」。

界面不解释模型、搜索或剪贴板。平台名、图、要改的字、下载就够。
