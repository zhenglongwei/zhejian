## **2. 流程总览（Phase 1）**

```text
商家创建服务相册（门店 + 服务 + **车主扫码关联手机号**）
→ 阶段一～六：接车、检测、方案与参考价、配件录入、施工、交付（商家留档）
→ 案例预览（可选 AI 润色）→ **确认并完工**（商家锁定；车主端不可见）
→ 异步 pre-mask → 脱敏结束进入案例人审（仅通过/驳回；可重试脱敏）
→ 通过前：车主不可看相册
→ 通过后：车主可看相册/案例稿 → 脱敏预览 → 发布到公开网站（**立即上线，不再过审**）
→ H5 公开案例 / GEO
```

**Phase 1 不含**：配件/方案车主待确认、L2+ 阻断完工。

## **3. 创建服务相册**

### **3.1 入口**

```
商家工作台 → 新建服务相册
```

快捷方式（P1）：扫码创建、从咨询线索一键创建。

### **3.2 字段**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| store_id | 是 | 门店 |
| service_id | 是 | 服务项目 |
| user_phone | **是** | 车主手机号；须车主扫码关联，商家不可代填；未关联不可标记完工 |
| complexity_level | 建议 | L1–L4 |

可选：车辆品牌/车系/年款、里程、内部工单号。

### **3.3 系统动作**

1. 创建 `album`（status=`draft`）；  
2. 匹配相册模板，生成六阶段空节点；  
3. 生成分享路径（有手机号时可用于通知）；  
4. 可选：短信/订阅消息通知车主。

**不再**：监听平台订单、支付回调。

## **4. 六阶段操作（商家 · Phase 1）**

### **4.1～4.2 接车 / 检测**

同 V2.0：外观、里程、故障点、检测图、诊断结论。

### **4.3 方案与报价**

商家填写本次服务的 **固定参考报价**（`planAmount`，以线下确认为准）；**不在此阶段录入价格区间**。  
**2026-06-24 增强**：须上传 **详细报价表/说明图** → OCR 生成 **`planParts[]`** → 商家确认锁定（见 `02_相册模板` §3.5、`03/04_维修相册` §13）。

**施工增项（2026-07-10）**：拆检或施工中新增工项/配件时，**不** 使用独立「方案外增项」表单；须 **补传经客户确认的报价/增项单** → 更新 `planParts` 并重新锁定。标准步骤见 **`11_施工增项留痕SOP.md`**。

**Phase 2**：L3/L4 维修方案车主确认。

### **4.4 配件告知（录入留档 + 按目录上传）**

对每个更换件 **录入**（**按 `planParts` 逐项**，见 `02_相册模板` §3.6）：

- 配件名称、品牌、**标准类型**、**编码**（凭证图 OCR 或手工）、价格、凭证图；  
- **不**推送 Phase 2 车主确认、**不**阻断 Phase 1 完工；  
- **方案外增项**：Phase 1 **不** 提供独立增项表单；须按 **`11_施工增项留痕SOP.md`** 在阶段三更新报价单与 `planParts`，阶段四按目录登记；验真页对历史 `source: extra` 仍单独分组展示。

```text
阶段三 报价表 OCR → planParts（锁定）
        ↓
阶段四 按 planParts 逐件上传 + 配件编码 OCR → partsJson
        ↓
车主   配件验真：planParts ↔ partsJson 对照留痕
```

### **4.5～4.6 施工 / 交付**

新旧件对比、包装编码、完工图、试车说明、**质保承诺**（承诺书拍照优先；无则填时长/范围/说明；强烈建议不阻断完工；公示前脱敏）。

## **6. 状态流转（Phase 1 主路径 · 案例审核收口 2026-07-27）**

```text
draft
  ↓ 商家编辑/upload
in_progress
  ↓ 商家确认并完工（案例稿确认）→ 锁定商家 + 车主端不可见
completed + pending_desensitize
  ↓ 后端异步 pre-mask
  ↓ 脱敏结束（就绪/部分失败/失败）→ pending_review
  ↓ 运营案例人审（仅通过/驳回；可重试脱敏）
review_passed
  ↓ 车主可看相册/案例稿 + 脱敏预览 → 确认「发布到公开网站」
published（立即上线 · **不再**过发布后审核）
```

异常：`rejected`（案例审驳回→**解锁**商家；车主仍不可见）、`offline`（用户撤回 · **不解锁**商家）。

**Phase 2 启用**：`pending_part_confirm` 及方案变更回退。

## **7. 发布到公开网站与案例上线**（修订 2026-07-18 · **案例审收口 2026-07-27**）

> 历史用语「授权公开 / 授权公示」= **发布到公开网站**。口径：`00_Phase1_服务相册产品口径.md` §4 / §4.5。

### **7.0 平台案例审（完工后唯一阻塞审 · 2026-07-27）**

1. 商家点击**确认并完工**后，商家相册锁定；车主端**整本相册不可查看**；写入 `pending_desensitize`；后端异步 pre-mask；  
2. **脱敏结束**（就绪 / 部分失败 / 失败）后升为 `pending_review` 进入运营待审；失败/需人工在详情标出，可重试脱敏或驳回商家（本期不做运营手工打码）；  
3. **平台案例审**审公示案例稿与脱敏配图：前期全量人审，仅 **通过 / 驳回**；  
4. **通过前**：车主**不可**看相册 / 案例稿 / 发布入口；  
5. **通过后**（`review_passed`）：车主可看相册与案例；可发布或撤回，**不再过审**；**不上线**直至车主点发布；  
6. **驳回**：解锁商家 → 改相册与案例稿 → 再确认完工 → 再脱敏 → 再送审；车主在再次通过前仍不可见。  

**废止**：相册完工合规（原闸门 A）作为阻塞审入口；审前车主可看私密相册。

### **7.1 触发条件（用户发布到公开网站）**

1. 档案 `completed` 且 **平台案例审已通过**（`review_passed`）；  
2. **无图亦可**提交发布（2026-07-08 口径不变）；  
3. 无进行中的隐私投诉；  
4. **须车主主动点击确认**（用户点一下才上线）。

**不负责**：车主 **不对** 六阶段完整度负责；缺项 **不得** 阻止提交发布。

**Phase 2 增加**：L2+ 配件车主确认已完成。

### **7.2 公开两档**

见 `00_Phase1_服务相册产品口径.md` §4：① 不公开 / ② 发布到公开网站（含门店名）。

### **7.3 脱敏与发布（废止发布后复审）**

`service_pre_mask`（完工后异步）→（案例审通过后）用户预览（须脱敏已就绪；否则稍后再试）→ 确认 **发布到公开网站** → **直接** `published` / 写 snapshot：

| 项 | 说明 |
| --- | --- |
| 脱敏预览 | 车主核对即将上网内容 |
| **不再** | 发布后人审挡上线 |
| **不审** | 六阶段齐全、整本私密相册（已在案例审完成公示内容） |

**GEO 证据链**：用户提交公开案例 **不** 调用 `assertGeoPublishable`（口径不变）。

### **7.4 发布后 Tag**

**已发布 · 已脱敏 · 已审核**（审核指完工后案例审；过渡期可并存「已授权」；不得使用「平台订单案例」）。

### **7.5 用户撤回发布**

用户在 **任何时候** 均可撤回已发起的公开发布：

| 当前状态 | 撤回后 |
| --- | --- |
| 已在公开网站 / `public_approved` | 案例立即下线（H5 noindex 或 404，移出 sitemap，停止推荐） |

撤回后：`album.status` 保持 **已完工**（`completed`），`publicCaseStatus` 回退 **private**；**合规态保持通过**；**商家仍锁定**；用户可再次发布（仍基于已锁定案例稿）。脱敏任务（`task_auth_*`）重置 `maskingConfirmed`，预览接口 **upsert** 避免重复创建冲突。

入口见「我的 → 我的公开发布」（`12_我的页面与账户体系.md` §8）；确认交互使用 **BottomSheet**。处理细则见 `10_隐私协议与授权规则.md` §10.2。

### **7.6 用户端列表展示（Phase 1）**

| 维度 | 用户可见文案 | 说明 |
| --- | --- | --- |
| 列表 Tab | **私密相册** / **公开相册** | 仅两 Tab |
| 私密 Tab 卡片 | **维修中** / **已完工**；可选 **案例审核中** | 案例审未通过时附加提示；详情不可打开 |
| 公开 Tab 卡片 | （无状态 Tag） | 已发布到公开网站 |
| 详情头部 | 维修进度 + 可见性 Tag | 见 `07_维修相册查看页.md` §14.1 |

列表 **禁止**「可授权 / 已授权 / 已公开 / 待授权公开」等内部态文案；面向用户用「发布到公开网站 / 门店案例审核中 / 已在公开网站」。

### **7.7 案例快照冻结与再发布（2026-07-09 · **修订 2026-07-26**）**

| 事件 | 相册 | public_case | snapshot |
| --- | --- | --- | --- |
| 确认并完工 | **锁定**（409）+ 案例待审 | `pending_review` | — |
| 案例审驳回 | **解锁** | `rejected` | — |
| 案例审通过 | 仍锁定 | `review_passed` | — |
| 用户确认发布到公开网站 | 仍锁定 | **直接** `public_approved` / `published` | **首次写入** `contentJson.snapshot` + `snapshotVersion=1` |
| 用户撤回 | **仍锁定** | `offline` 留痕 | 保留 audit；H5 下线 |
| 用户再发布 | 仍锁定 | 再次 `published` | **`snapshotVersion++`** 新快照覆盖 |
| 发布后商家改 DB | 409 | — | H5/API **仍读旧 snapshot**（无 drift） |

**商家内容优化 / AI 润色**：仅 **确认并完工前**；确认后不可再改案例正文（入口已下线「内容优化」页）。

实现：`public-case.service.js` · `service-album.service.js` · `content.service.js`（`resolvePublicCaseContentNodes`）。

## **11. P0 验收（Phase 1）**

1. 商家可创建档案并完成六阶段留档；  
2. 可录入配件类型，**不发起**车主确认；  
3. 可标记完工，**无** L2+ 阻断；  
4. 车主可查看时间线；  
5. 授权 + 脱敏 + 审核后可发布；  
6. 公开 Tag 符合 Phase 1。
