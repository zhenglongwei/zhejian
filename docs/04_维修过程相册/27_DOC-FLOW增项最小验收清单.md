# DOC-FLOW · 增项相关最小验收清单

> **生效**：2026-09-09  
> **配套真源**：[`26_商家端事件节点与单据节点链流程.md`](./26_商家端事件节点与单据节点链流程.md) §3 · [`23_面向车主单据与确认件.md`](./23_面向车主单据与确认件.md)  
> **用途**：改「施工中新发现 / 增项工单 / 施工拍照」前后必点；默认只报告，不替代完整回归。

---

## 0. 前置

- [ ] 使用 **flowVersion≥4** 相册；能走到施工步  
- [ ] 已完成：检测 → 通知车主 → 方案确认 → 首张工单 → 已开始施工并至少 1 张施工图（部位已填）  
- [ ] 准备：车主端账号手机号与建档一致  

---

## 1. 入口与命名（双端一致）

| # | 步骤 | 期望 | ☐ |
| --- | --- | --- | --- |
| 1.1 | 商家施工步 | 按钮文案为 **发现新的待处理项目**（不是「添加方案」） | ☐ |
| 1.2 | 点入口后当前步标题 | **施工中新发现** | ☐ |
| 1.3 | 车主服务进度时间线 | 同名 **施工中新发现**（不是「方案确认」） | ☐ |
| 1.4 | 首张方案确认 | 标题仍为 **方案确认**，未被改成增项文案 | ☐ |

---

## 2. 打断施工 · 部位不丢

| # | 步骤 | 期望 | ☐ |
| --- | --- | --- | --- |
| 2.1 | 施工中为已有图填好部位后，再点「发现新的待处理项目」 | 进入增项填写页 | ☐ |
| 2.2 | 增项确认并回到施工后 | **原施工图部位名仍在**（不出现「缺部位」） | ☐ |
| 2.3 | （可选）断网/慢网时点入口 | 有保存失败提示或重试，不应静默丢草稿 | ☐ |

---

## 3. 施工中新发现 · 填写与确认

| # | 步骤 | 期望 | ☐ |
| --- | --- | --- | --- |
| 3.1 | 增项行 | 有 **故障图** 上传；部位 / 品牌(选填) / 建议 / 金额 | ☐ |
| 3.1b | 未发送前点行上删除 | 可删掉多余行；删至只剩一行时变空行可续填 | ☐ |
| 3.1c | 误点入口后、**未发送**点「取消本项」 | 确认即可（**不**填原因）；回到施工；时间线**无**该增项痕迹 | ☐ |
| 3.1d | 已发送后作废 | 必填原因；双端可见「门店已取消」+ 原因；无「不同意」按钮 | ☐ |
| 3.1e | 待确认时 | 仅确认 + 电话联系门店（有电话时） | ☐ |
| 3.2 | 未传故障图点发送 | 拦截，提示补图 | ☐ |
| 3.3 | 未发车主时底栏 | **仅**「发送车主确认」；无「草稿」标、无并排代确认/上传证明 | ☐ |
| 3.4 | 发送后 | 状态「待车主确认」；出现「车主已口头确认」 | ☐ |
| 3.5 | 车主端确认 或 商家代确认 | 通过；可选附带沟通截图（代确认流程内） | ☐ |

---

## 4. 工单分开展示 · 直达施工

| # | 步骤 | 期望 | ☐ |
| --- | --- | --- | --- |
| 4.1 | 增项确认后商家时间线 | **两张工单**（首张 + 增项），项目列表各含各自行，**不合并成一张** | ☐ |
| 4.2 | 车主时间线 | 同样两张工单分开展示 | ☐ |
| 4.3 | 增项确认后商家当前步 | **直接进入施工拍照**（不长期停在只有清单、无拍照入口的空工单页） | ☐ |
| 4.4 | 新工单对应项目 | 施工步出现 **部位已预填、待拍照** 的行；可点上传施工图 | ☐ |

---

## 5. 继续施工 · 完工确认合并

| # | 步骤 | 期望 | ☐ |
| --- | --- | --- | --- |
| 5.1 | 为增项部位补施工图并确认施工步 | 可继续后续完工照；同一部位可传多张（≤6） | ☐ |
| 5.1b | 交车/完工步 | **整车外观必选**（施工图里选或补拍）；其他交车图可选自施工图；勾选**不复制**存档 | ☐ |
| 5.2 | 完工确认单据 | **合计与已施工项目 = 全部工单行之和**；交车区为选用图；质保为**期限 + 注意事项**两行（期限须实质，非「以门店公示为准」） | ☐ |
| 5.3 | 车主确认完工（或商家代确认） | 协议文案正确；确认后单据已确认，且**相册自动整单完工**（无需再点「标记整单完工」） | ☐ |

## 6. 回归（改增项代码时至少抽测）

| # | 路径 | ☐ |
| --- | --- | --- |

---

## 失败时优先查

1. 点增项入口前是否调用了施工 `persistPhotos` / `persistPhotoDraft`  
2. 新施工步 `photoDraft.findings` 是否从打断前施工步带入，读侧是否按图 URL 合并  
3. 增项方案确认后是否对增项工单做了「开始施工」等价解锁（直达施工）  
4. 完工确认是否走 `collectAllWorkOrderItems`（勿只读第一张工单）
