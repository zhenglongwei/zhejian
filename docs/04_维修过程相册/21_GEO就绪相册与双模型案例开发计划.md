## 1. 产品一句话

过程本：门店说明 + **按需 AI 客观对照/解读**。  
案例：生成模型出稿 → **审核模型机审** → 商家确认 → **直接公开**（**取消运营人审**）。

---

## 2. 边界（实现红线）

1. AI 不默认跑（M2）；上传不识图。  
2. 门店点选结论为主叙事（N1）；AI 旁证。  
3. AI 中立、不作假、包容合理方案。  
4. 过程本进行中可看（P1）；公开须完工后链路。  
5. **无人审排队**：机审真实性 ≥60 + 系统脱敏硬门槛 + 商家确认 = 上店页。  
6. 运营可保留**事后**投诉下架 / 抽检，**不挡**上线。

## 4. 推荐开发波次（自行排期）

```text
波次 1 · 基础设施（约先做）
  VIS-01 → VIS-02 → VIS-03 → VIS-04

波次 2 · 过程本 AI（商家优先，因「方案对照」是改造动机）
  ALB-AI-01/02 → OWN-AI-01/02
  并行：ALB-CAP-01/02、ALB-EDIT-01（N1/A1 收口）

波次 3 · 案例双模型核心
  CASE-GEN-01 → CASE-AUD-01 → CASE-AUD-02/03/04
  → CASE-FLOW-01/02/04 → CASE-FLOW-06（确认即公开）
  → CASE-FLOW-03/05（解锁重审）

波次 4 · 串联与收口
  ALB-EDIT-02（生成真入口）→ ALB-EDIT-03（缺口跳回）
  → CASE-SCORE-01 → CASE-OPS-01（撤人审入队）
  → QA-01/02 → OBS-01
```

原则：先有识图缓存，再挂主题卡 AI；先有机审门禁，再改「确认即公开」并拆掉人审入队，避免半套状态机。

## 5. 与现有专项

| 专项 | 关系 |
| --- | --- |
| CASE-SRC | 成稿结构保留；生成后加机审；确认后直接公开（不再等人审） |

| 软清单 / 18 | 主题卡沿用；叠加 AI 入口与 N1/A1 |
| 运营审核台 | 上网前待审队列**停用**；投诉/下架/抽检可后置 |

---

## 6. 验收摘要

1. 上传不产生识图调用。  
2. 商家对照 / 车主解读按主题卡按需可用。  
3. 生成→机审→确认后**直接上店页**，无运营待审态。  
4. 真实性低于 60 不能发布；痛点分不能凑及格。  
5. 确认页不能换图；改素材回相册并重审。  
6. 进行中车主可读过程本；公网无进行中相册。
