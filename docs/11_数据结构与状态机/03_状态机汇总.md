## 2. 状态机设计原则

1. 状态值使用约定枚举（线索多为 UPPER_SNAKE；相册/案例多为 lower_snake）。
2. 只允许按合法路径流转；关键变更写日志。
3. 状态变更接口支持幂等。
4. 审核类状态记录审核人、时间、备注。
5. 风控/门禁不得被普通业务绕过。
6. 终态原则上不可逆（如下线、车主阻止）；再授权等例外须单独定义。
7. **不适用**：交易对账、订单与支付状态分离等 V1 交易原则。

## 3. 商家入驻状态机

### 3.1 适用对象

`merchants`、`merchant_certification`（若拆表）、`stores`

### 3.2 商家 status

| 状态 | 说明 |
| --- | --- |
| DRAFT | 草稿未提交 |
| PENDING_AUDIT | 待审核 |
| AUDIT_REJECTED | 驳回 |
| ACTIVE | 正常 |
| SUSPENDED | 暂停 |
| CLOSED | 关闭 |

### 3.3 流转（摘要）

```
DRAFT → PENDING_AUDIT → ACTIVE ⇄ SUSPENDED → CLOSED
PENDING_AUDIT → AUDIT_REJECTED → DRAFT → PENDING_AUDIT
```

### 3.4 认证 auth_status

`none` → `pending` → `verified` / `failed`

### 4.1 适用对象

`merchant_service_plans`

### 4.2 常见状态（与实现对齐）

| 状态 | 说明 |
| --- | --- |
| draft | 草稿 |
| pending_review | 待审（若路径需要） |
| approved / online | 可售/上架 |
| rejected | 驳回 |
| offline | 下架 |

具体枚举以服务审核实现为准；原则：上架可见与审核通过解耦时，须在对象文档写清字段。

## 5. 服务相册状态机

### 5.1 相册 albums.status

| 状态 | 说明 |
| --- | --- |
| draft | 新建草稿 |
| in_progress | 维修进行中 |
| completed | 维修已结束（完工确认完成后自动进入） |
| pending_authorization | 历史：待授权（对外可视为已完工） |
| published | 历史：已发布相关 |

**维修已结束**集合：`completed`、`pending_authorization`、`pending_review`（历史）、`published`。

### 5.2 节点 FlowNode.status

| 状态 | 说明 |
| --- | --- |
| locked | 未解锁 |
| in_progress | 当前可编辑 |
| completed | 本步完成 |

流转：上一步完成后解锁下一步 `in_progress`；完成后 `completed`。已完成过程步默认不可改；修订策略另议。

### 5.3 单据 document.status（常用）

| 状态 | 说明 |
| --- | --- |
| draft | 草稿 |
| delivered | 已送达/已生成可阅（如检测报告） |
| pending_confirm | 待车主确认 |
| confirmed | 已确认 |
| （代确认） | 商家代确认时仍落 confirmed，并留 proxy 凭证 |

**报告与方案合发**：一次通知写入检测报告 `delivered` + 方案 `pending_confirm`；仅方案需确认。

### 5.4 相册进度约束

- 接车发出后接车节点锁定。
- 检测生成报告后检查项锁定。
- 方案确认前不可进入工单主路径（按门禁）。
- 完工确认成功 → 相册 `completed`。
- 缺里程不拦完工；公开前可警告。

## 6. 公开案例状态机

### 6.1 public_cases.status

| 状态 | 说明 |
| --- | --- |
| pending_desensitize | 脱敏处理中 |
| pending_review | 待运营/机审人审 |
| audit_passed | 机审过线，待商家确认发布（若启用） |
| review_passed | 审过；通知未发出时可停此态 |
| notify_window | 已通知车主，异议窗口内 |
| public_approved | 公域通过 |
| user_rejected | 用户拒绝 |
| owner_blocked | 车主阻止，本相册不得再送审 |
| rejected | 驳回 |
| need_modify | 需修改 |
| offline | 下线 |

### 6.2 article_status（文章发布渠道态，与审核态分离）

| 值 | 含义 |
| --- | --- |
| pending | 尚未生成 |
| draft | 草稿 |
| ready | 生成完成待发布 |
| published_h5 | 已 H5 发布 |
| published_wechat | 已发公众号 |

跃迁摘要：`pending|draft|ready` → `published_h5`（审核通过或补跑）；`published_h5` → `published_wechat`（运营标记）。  
H5 对外可见通常要求 `published_h5` 或 `published_wechat`。

### 6.3 托管维度（案例档案）

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| hosted | true/false | 是否托管 |
| visibility | private/public | 公域是否可见 |
| publicPublishStage | awaiting_privacy → awaiting_geo → awaiting_geo_confirm → published | 公开托管进度 |

约束：`visibility=public` 须 hosted、隐私通过、GEO/店页说明已确认。

## 7. 咨询线索状态机

适用对象：`consult_leads`。

### 7.1 lead status

| 状态 | 说明 |
| --- | --- |
| SUBMITTED | 已提交 |
| VIEWED | 商家已查看 |
| CONTACTED | 已联系 |
| CANCELLED | 用户取消 |
| CLOSED | 商家关闭 |

### 7.2 流转

```
SUBMITTED → VIEWED → CONTACTED → CLOSED
SUBMITTED → CANCELLED
SUBMITTED | VIEWED → CLOSED
```

用户可取消：SUBMITTED、VIEWED。

### 7.3 close_reason

`UNREACHABLE` / `VISITED` / `DUPLICATE` / `INVALID` / `OTHER`（及文档中的 USER_CANCELLED 语义）

每次变更写 `lead_status_logs`。

**禁止**：把线索写成待支付、维修中、已完工等订单态。
