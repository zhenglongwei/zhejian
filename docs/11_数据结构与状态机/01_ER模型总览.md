## 3. 核心实体关系总览

### 3.1 主链路（V2.0）

```
用户 user
  └── 车辆 user_vehicle（可空）
        └── 服务相册 albums
              ├── 流程节点链 content_package_json.flowNodes
              │     ├── photoDraft（过程草稿）
              │     └── document（定稿单据）
              ├── 媒体 media_assets / album_images
              ├── 脱敏任务 desensitize_*
              └── 公开案例 public_cases（0..1）
                    ├── content_json（公开稿 / 兼容 snapshot）
                    ├── enrichment_json（GEO 提炼层）
                    └── 托管档案 archive（事实层 / 可公开面 / GEO）

用户 / 访客
  └── 咨询线索 consult_leads → 门店 store（可再关联相册 lead_id）
```

**嵌套真源**：案例相册 ⊃ 流程节点 ⊃ 图与字。发出/确认后图文进入该节点的定稿报告；托管与公开只读定稿，不另拼草稿第二真源。

### 3.2 商家侧关系

```
商家 merchants
  └── 门店 stores
        ├── 服务方案 merchant_service_plans
        ├── 服务相册 albums
        ├── 公开案例 public_cases
        └── 咨询线索 consult_leads
```

### 3.3 审核与风控关系

```
业务对象（商家 / 服务方案 / 公开案例 / 媒体）
  ├── 审核日志（merchant_review_logs / service_review_logs / case_review_logs）
  ├── 脱敏任务 desensitize_tasks → desensitize_assets
  └── 内容举报 content_reports
```

### 3.4 明确不存在的关系

- 用户下单 → 支付 → 退款 → 平台履约（已废止）
- 评价 → 奖励 → 分享分佣（已废止）
- 相册主路径依赖 `order_id`（遗留可空字段，新单不建订单）

## 4. 实体边界原则

1. **服务相册**是一次进店维修的过程与单据容器；主键是 `albums.id`（`albumId`）。
2. **流程节点**住在相册的 `content_package_json.flowNodes[]`；`kind` 是类型身份，`id` 是节点身份，`sortOrder` 只排序。
3. **过程草稿** `photoDraft` 与 **定稿单据** `document` 按节点类别二选一为主；发出后读侧只认定稿 payload。
4. **咨询线索**不是订单：无支付、无履约、无退款状态。
5. **公开案例**与相册 1:1；公开页事实来自定稿/托管事实层，GEO 提炼可改但不得与事实矛盾。
6. **确认件**在车主确认瞬间冻结，不可静默覆盖；商家修订另存。
7. **里程**等车辆档案字段住在新建相册的 `vehicle_json`；接车报告页眉可展示，正文不重复第二份里程字段当真源。

## 6. 界面中间量（不进本目录数据模型）

下列名称只存在于页面绑定或临时计算，**不是**持久化对象或跨端契约：

- `intakePile`（由节点 `pendingImages` 当场算出的列表绑定）
