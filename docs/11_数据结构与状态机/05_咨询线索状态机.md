# 咨询线索状态机

> **当前版本：V2.0**

---

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档名称 | 咨询线索状态机 |
| 所属目录 | 11_数据结构与状态机 |
| 核心目标 | 定义用户咨询/预约线索的状态枚举与合法流转（非订单） |
| 对象正式名 | ConsultLead / 表 `consult_leads` |

---

## 2. 适用对象

`consult_leads`：用户通过服务/门店/案例/GEO 等入口提交的咨询或到店预约信息。

**不是**平台订单，不绑定支付、履约、退款状态。

### 2.1 关键字段（与对象文档一致）

| 字段 | 说明 |
| --- | --- |
| id | 线索 ID |
| user_id / store_id | 用户与门店 |
| status | 见 §3 |
| service_id / service_name / case_id / source_page | 来源 |
| lead_type | 如 message |
| vehicle_json / description / images_json | 车辆与诉求 |
| appointment_json / contact_json | 预约与联系 |
| is_accident / price_mode / platform_consent | 标记与同意 |
| close_reason / close_note | 关闭原因与备注 |

---

## 3. 主状态 status

| 状态 | 说明 |
| --- | --- |
| SUBMITTED | 已提交，待商家查看 |
| VIEWED | 商家已查看 |
| CONTACTED | 商家已联系用户 |
| CANCELLED | 用户取消 |
| CLOSED | 已关闭（商家标记无效/已到店/重复等） |

---

## 4. 状态流转

```text
SUBMITTED → VIEWED → CONTACTED → CLOSED
SUBMITTED → CANCELLED（用户）
SUBMITTED / VIEWED → CLOSED（商家关闭）
```

用户可取消的状态：SUBMITTED、VIEWED。

**不允许**：待支付、待接单、维修中、待确认、已完成、售后等订单态。

---

## 5. 关闭原因 close_reason（商家）

| 枚举 | 说明 |
| --- | --- |
| UNREACHABLE | 无法联系 |
| VISITED | 用户已到店（线下后续不在平台跟踪） |
| DUPLICATE | 重复提交 |
| INVALID | 无效/垃圾咨询 |
| OTHER | 其他（须填备注） |

用户取消走状态 `CANCELLED`，不必再写商家 close_reason。

---

## 6. 平台侧扩展（可选）

| 字段 | 说明 |
| --- | --- |
| risk_flag | 风控标记（垃圾/骚扰） |
| platform_note | 运营内部备注 |

平台**不可**将线索改为「已支付」「已完工」等状态。

---

## 7. 状态日志

表 `lead_status_logs`：lead_id、from_status、to_status、operator_type（user/merchant/platform）、operator_id、reason、created_at。

---

## 8. P0 验收标准

1. 用户提交后状态为 SUBMITTED；
2. 商家可标记 VIEWED、CONTACTED、CLOSED；
3. 用户可在未关闭前 CANCELLED（SUBMITTED/VIEWED）；
4. 状态流转有日志；
5. 前端展示状态与枚举一致，无订单态文案。
