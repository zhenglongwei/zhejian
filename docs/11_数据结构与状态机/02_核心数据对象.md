### 6.3 嵌套真源（不变量）

1. **相册 ⊃ 节点 ⊃ 图/字**。
2. 接车留证照片唯一真源：接车节点 `photoDraft.pendingImages`。
3. 检测/工单：图挂在项 `findings[].images[]`，项身份是 `findings[].id`，不是下标或名称。
4. 发出/生成报告后：定稿写入 `document.payload`；读侧（车主/托管/公开）只读定稿，禁止再用草稿拼第二套。
5. 禁止为展示另留可脏的列表副本当真源；界面绑定可以是「由节点当场算出」，但不得与节点并行维护。

### 7.1 节点公共字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 节点身份（如 fn_001） |
| kind | string | 节点类型，见 §7.2 |
| nodeCategory | photo \| document | photo → photoDraft；document → document |
| sortOrder | number | 仅排序 |
| title | string | 标题 |

| photos | array | 散图投影（只读派生，非第二真源） |

### 7.2 标准链 kind（flowVersion ≥ 6）

| sort | kind | 显示名 | category | 说明 |
| ---: | --- | --- | --- | --- |
| 0 | intake | 接车 | photo | 进店留证；发出后不可改 |
| 1 | inspection | 检测 | photo | 部位级 findings |
| 2 | inspection_report | 检测报告 | document | 与方案同次通知后可阅，不确认 |
| 3 | quote_confirm | 方案确认 | document | 需车主确认 |
| 4 | work | 工单 | photo | 按已确认方案留证（对外是单据） |
| 5 | delivery_photos | 完工照 | photo | 交车证据选用 |
| 6 | repair_report | 完工确认 | document | 需车主确认 |

**存量兼容 kind**

| kind | 说明 |
| --- | --- |
| intake_inspection | v5 接车+检测合并节点；读侧兼容，新建不用 |
| addon_quote_confirm | 增项方案（常与 insertedReason=addon 的 quote_confirm 同类） |

**读侧过滤（库内可留、不进时间线）**：`work_order`、`warranty`。

### 7.3 photoDraft 字段

#### 接车 emptyIntakeDraft

| 字段 | 说明 |
| --- | --- |
| chiefComplaint | 车主诉求 |
| pendingImages | **留证照片唯一真源** `{ url, imageId? }[]` |
| mileageKm | 旧字段；新单里程在 vehicle_json |
| fuelReading / intakeResults / walkaround | 存量兼容 |
| odometerUrl / odometerImageId | 存量；打开时并进 pendingImages 一次后清空 |
| vehicleBrand / vehicleSeries / vehicleYear | 缺档时手补；优先车辆档案 |
| receiverName / receivedAt | 接车人与接车时间 |

#### 检测 / 工单 / 交车 emptyPhotoDraft（及扩展）

| 字段 | 说明 |
| --- | --- |
| findings | 发现项/施工项数组，见 §7.4 |
| pendingImages | 尚未归到项上的图（工单现行可不进未归组） |
| conclusion | 检测结论 |
| inspectorName / inspectedAt | 检测人与时间 |
| workerName / finishedAt | 施工人与施工时间（工单） |
| delivererName / finishedAt | 交付人与交车时间（交车） |
| warrantyPeriod / warrantyNotes | 质保 |
| selectedDeliveryUrls / deliveryExteriorUrl | 交车选图与整车外观 |
| confirmCopy | 确认文案 |

**时间字段约定**：统一存 `YYYY-MM-DD HH:mm`；编辑器用日期+时间选择器，默认当前时刻；报告落款可格式化为「M月D日 HH:mm」。

### 7.4 finding（一项）

| 字段 | 说明 |
| --- | --- |
| id | **稳定身份**；不是下标、不是 partName |
| partName | 部位/项目名（可重名、可改） |
| images | `{ url, imageId }[]`，图跟 id 走；检测项不限张数，施工项每项最多 6 张 |
| url / imageId | 首图冗余兼容 |
| result | 检查结果：状态良好 / 需关注 / 需处理 / 仅记录 |
| advice | 检查发现 |
| quoteLineId | 工单实现行引用的方案行 id（可空） |
| outsideQuote | 方案外新增标记 |
| caption | 施工说明等 |

**禁止**：按下标或 URL 跨数组配对；用 partName 当主键合并。

### 7.5 document（定稿单据）

| 字段 | 说明 |
| --- | --- |
| docType | 如 inspection_report / quote_confirm / repair_report |
| status | draft / delivered / pending_confirm / confirmed / … |
| payload | 定稿正文：主诉、findings、报价行、照片、签字等 |
| confirmedAt / confirmedBy | 确认时间与方式 |
| proxyProofImages | 代确认凭证 |
| sourceNodeIds | 来源过程节点 |
| contentFingerprint | 内容指纹 |

**定稿规则（摘要）**

- 接车发出：`pendingImages` 等写入接车报告 payload；之后不可改。
- 检测生成报告：findings 挂图写入检测报告 payload。
- 工单完成：施工项定稿供交车与托管汇总。
- 交车：选图写入交车/完工确认 payload。
- 里程展示：payload/页眉用车辆档案里程；正文不重复第二份里程当真源。

### 7.6 职员签字字段一览

| 步骤 | 人名 | 时间 |
| --- | --- | --- |
| 接车 | receiverName | receivedAt |
| 检测 | inspectorName | inspectedAt |
| 工单 | workerName | finishedAt |
| 交车 | delivererName | finishedAt |

城市/车型/故障等聚合页：slug、标题、正文模块、关联案例统计等。提炼层可挂载专题，但不得捏造与单案事实矛盾的数据。

## 11. 对象边界原则

1. 相册是过程与单据容器；案例是托管与公开单元；二者 1:1 关联时共享定稿事实。
2. 线索只表达咨询意向，不产生平台交易状态。
3. 节点 kind 用正式名；废止名只出现在兼容表。
4. 项的身份是 id；图跟项走。
5. 界面中间量不是对象。

---

## 12. P0 验收（文档口径）

1. 新设计能在本文找到对象与字段正式名。
2. 不出现平台订单/评价奖励作为现行主对象。
3. work / delivery_photos 等 kind 与实现一致；无 work_order 新写入。
4. 嵌套真源与定稿读写规则写清且无第二真源描述。
