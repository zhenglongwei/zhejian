## 2. 设计原则

1. 金额用整数（分）或明确单位说明。
2. 时间用 datetime / ISO 字符串；职员签字时间业务串为 `YYYY-MM-DD HH:mm`。
3. 主键字符串 ID。
4. 核心表含 `created_at` / `updated_at`；删除优先逻辑删除（若有 `deleted_at`）。
5. 敏感字段加密或脱敏展示。
6. 业务状态与审核状态分离（如案例 `status` vs `article_status`）。
7. 流程节点主数据住在相册 JSON 包，不强制拆成多行关系表才可运行。
8. 界面中间量不入库。

### 7.2 content_package_json 契约

```json
{
  "flowVersion": 6,
  "flowNodes": [ /* FlowNode 见 02 §7 */ ]
}
```

**flowNodes[] 每项必填语义**：id、kind、nodeCategory、sortOrder、title、status；photo 类带 photoDraft；document 类带 document。

**photoDraft / document / findings** 字段表见《02_核心数据对象》§7.3–§7.5（本文不省略要点）：

- 接车：`pendingImages` 为留证真源；`receiverName`/`receivedAt`
- 检测/工单：`findings[].id` + `images[]`；职员时间字段
- 交车：`selectedDeliveryUrls`、`deliveryExteriorUrl`、质保字段
- document.payload：定稿后读侧只读此对象

**禁止**：把 UI 列表副本写入包内与 pendingImages 并行当真源。

### 7.3 album_nodes / album_images

关系表形态的节点与图片行（legacy / 辅助）：

- album_nodes：album_id + node_id、title、sort_order、status、note、compare_pair_rows
- album_images：id、album_id、node_id、raw_url、caption、checklist_item_key、visibility、public_gate_*

**说明**：DOC-FLOW 主编辑态以 `content_package_json.flowNodes` 为准；打开进度时可将旧 stage 图并进对应节点一次。

### 7.4 album_image_vision_caches

按图识图缓存：album_image_id、content_fingerprint、prompt_version、result_json。

### 7.5 其他相册附属

album_authorizations、album_share_tokens、album_inspection_reports：授权、分享令牌、检测报告附属（若启用）。

1. 新建相册不依赖 order_id。

4. consult_leads 状态与 03 一致。
5. 文档字段与 Prisma / 运行时 JSON 无系统性冲突。
