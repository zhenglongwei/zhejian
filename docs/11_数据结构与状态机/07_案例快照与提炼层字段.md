# 案例确认件、公开稿与提炼层字段

> **版本**：2026-09-03 修订起生效  
> **存储**：`public_cases` + `albums.content_package_json` / 托管档案字段  
> **代码参考**：`backend/src/schemas/case-snapshot.schema.js`、`case-enrichment.schema.js`、`album-content-optimize.schema.js`；托管读侧以 archive / hostMeta 为准

---

## 1. 分层模型（现行）

| 层 | 存储位置 | 可变？ | 说明 |
| --- | --- | --- | --- |
| **确认件** | 托管事实层 / `hostMeta.confirmedDocs[]`（或等价 archive 确认副本） | **否** | 车主确认瞬间冻结；不可静默覆盖 |
| **事实层** archiveSnapshot | 托管包内 | 托管后只读 | 定稿节点图文、门店快照 storeSnapshot、确认件 |
| **公开稿** | 最新可公开面 / 公开页正文 | 修订另存 | 公域展示最新公开稿；页脚可标最近更新 |
| **兼容 CaseSnapshot** | `public_cases.content_json.snapshot` | 公示后旧逻辑视为冻结块 | **读侧可兼容**；新写入主逻辑不以「整案永久冻结」为产品口径 |
| **GeoEnrichment** | `public_cases.enrichment_json` | **是** | 摘要、FAQ、TDK 等；不得与事实矛盾 |
| **商家润色草稿** | `albums.content_optimize_draft_json` | 授权/公开前可覆盖 | 不直接改确认件 |

**废止口径**：整案一旦 snapshot 冻结则永不可修订公开叙述。  
**现行口径**：确认件保全 + 商家修订另存；公开页看最新公开稿。

**读侧规则**

- 过程节点与定稿事实 → 事实层 / 确认件 / 兼容 snapshot  
- 页顶摘要、FAQ、TDK → enrichment 优先，不得与事实矛盾  
- 脱敏图 URL 须对得上报告属性，禁止另建平行名单

## 2. 确认件 confirmedDoc（逻辑字段）

| 字段 | 说明 |
| --- | --- |
| docKind / nodeId | 哪一张单据 |
| payload | 确认瞬间正文副本 |
| confirmedAt | ISO 时间 |
| immutable | true |
| proxy / proof | 代确认信息（若有） |

商家后续修改不得覆盖该 payload；须写入 revisions / 新公开稿版本。

---

## 3. 兼容 `content_json.snapshot` 字段

旧链路仍可能存在以下字段；读侧可提取，新产品叙述以 §1 为准。

| 字段 | 说明 |
| --- | --- |
| version | ≥1 表示有效块；再授权可递增 |
| frozenAt | ISO 时间 |
| authorizationTier | named / anonymous 等 |
| title / summary / articleBody | 文案 |
| coverImage | 脱敏封面 |
| nodes[] | `{ id, title, note, images[] }`，images 为脱敏 URL |
| vehicle / parts / planParts / evidenceItems | 留档 |
| planAmount / price | 价格结构 |
| geo | 叙事块 |
| storeId / storeName / serviceName / city | 门店上下文 |
| templateId / serviceItemId | 模板与服务 |

## 4. `enrichment_json` 主要字段

| 字段 | 说明 |
| --- | --- |
| version | 提炼层版本；变更不要求 bump 确认件 |
| aiSummary | 页顶可引用摘要 |
| seoTitle / seoDescription | TDK |
| faq[] / faqLinks[] | FAQ 与延伸 |
| schemaGraph | JSON-LD |
| topicMountIds[] | 挂载专题页 |
| slug / canonicalPath / seoNoindex | URL 与收录 |
| geo | 发布态镜像（如 publishedH5At） |

写入 enrichment **不得**修改确认件或擅自改事实层字节。

---

## 5. `albums.content_optimize_draft_json`

| 字段 | 说明 |
| --- | --- |
| status | ready / applied / failed |
| source | rule / llm_v1 等 |
| aiSummary / geo / nodeNotes | 建议文案 |
| suggestions[] | 规则提示 |
| updatedAt | 草稿更新时间 |

并入公开叙述时走明确合并步骤；润色阶段不写死 public_cases 事实。

---

## 6. 动作对照

| 动作 | 确认件/事实层 | enrichment | 相册可编辑 |
| --- | --- | --- | --- |
| 车主确认单据 | 写入确认件 | — | 按节点锁定 |
| 托管 | 冻结事实层 | 可选初始化 | 托管后事实只读 |
| 商家修订公开叙述 | 不覆盖确认件；另存修订 | 可更新 | — |
| 运营改 TDK/FAQ | 不变 | 更新 | — |
| 车主阻止/下线 | 保留审计与确认件 | — | 按策略 |
| 再公开 | 确认件仍在；公开稿可新版 | 可合并 | 按门禁 |

相关错误语义（实现名可演进）：内容锁定、试图覆盖冻结确认件、相册不可编辑等。

---

## 7. 与文章顶列关系

`public_cases` 顶列 `seo_title`、`ai_summary`、`article_body`、`article_status` 等与 enrichment / 生成器可能双写过渡：读侧以「顶列优先或 enrichment 优先」的统一规则为准，但**不得**用提炼层覆盖确认件事实。完整顶列见《06_案例文章与GEO字段映射》。

---

## 8. 验收要点

1. 确认件不可被静默覆盖。  
2. 公开页展示最新公开稿，且可追溯确认件。  
3. enrichment 可变，且不改事实层。  
4. 文档与代码均不再把「整案永久冻结」当作唯一产品规则。
