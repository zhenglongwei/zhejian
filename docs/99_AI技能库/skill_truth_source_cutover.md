# Skill: 新口径切换 · 旧口径须确认后收口

> Agent 入口：`.cursor/skills/truth-source-cutover/SKILL.md`  
> 联用：`docs-before-code`、`communication-first`、`invariant-close-loop`、`feature-build-verify`、`object-model-first`、`node-mask-state-machine`  
> **凡出现「真源改了 / 废止某表或某字段 / 只认节点或报告」：必须先走本 skill，再改代码。**

## 目标

口径一变，旧读法、旧表、旧信封必须**有计划地退役**，不能默默留作「兼容旁路」。  
**最重要**：在有新口径时，要认真评估怎么处理旧口径并跟我确认。不要单方面决定保留旧口径。

## 使用场景（命中即用）

- 文档或对话里出现：废止、只认、禁止再读、真源改到…、删旧表、不再双写
- 改托管 / 公开 / 打码 / 进度读图 / 单据预览的数据从哪来
- 修「预览有、确认没有」「界面有图、接口说没有」这类双真源 Bug
- 想「先改主路径、旧路径暂时留着」——**不准默认这么做，须先问用户**

## 本轮踩过的错（写进习惯，禁止再犯）

| 错 | 表现 | 教训 |
| --- | --- | --- |
| 只改看得见的预览 | 托管预览已读节点/报告，确认硬拦仍数 `album_images` | 真源切换 = 预览 + 硬拦 + 打码收图 + 鉴权 **同一套** |
| 单方面留旧口径 | 以为「兼容旧册」就可继续读旧表/信封 | **保留旧口径必须先问用户**；默认应退役并迁一次 |
| 把信封当内容库 | 打码收图只扫 `document.payload`，定稿后信封常无图 → 409「暂无过程图」 | 信封只记类型/状态/时间；图文只住节点 `content` / 已生成报告 |
| 入口没收口 | 改了一处读写，其它接口仍走废止路径 | 交付前全库搜旧名；没有清单不准说做完（`invariant-close-loop`） |
| 文档已禁、代码仍行 | `26_` / `15_` 已写禁止双真源，代码仍平行读 | 改文档当天就要列「旧入口退役方案」并确认，不能只改正文 |

## 辙见现行：合法真源（对照用）

产品只认这一套（细节以 `26_` §1.0、`15_` 为准）：

1. **节点 `content`**：商家编辑期的图+文唯一内容袋  
2. **已生成报告**：定稿后车主 / 托管预览 / 公网读这一份  
3. **`document` 信封**：只记单据类型、状态、时间——**不是**正文或挂图仓库  
4. **已废止、不得再当真源**：`album_images` 闸字段、`stage_*` 镜像、`photoDraft` 第二草稿、把正文塞进 `document.payload`

若实现里还在读 4，视为漏口，不是「多数据源设计」。

## 新口径出现时的强制流程

### 1. 说清新口径（产品语言）

用一两句话写：**现在什么算唯一真源？谁读它？**

### 2. 盘点旧口径（不准偷懒）

至少列出：

| 旧东西 | 还在哪些入口读/写 | 存量数据怎么办 |
| --- | --- | --- |
| … | 搜到的文件/接口 | 迁一次 / 忽略 / 双读过渡（须用户批） |

搜索关键词示例：旧表名、旧字段、`payload` 当正文、`stage_`、`photoDraft`、`visibility`+`publicGate`、平行 `mapImageMeta` 等。

### 3. 处理方案必须问用户（禁止单方保留）

向用户给出**选项**，等明确同意后再写码。推荐默认问法：

> 新口径是 A。旧口径 B 还在这些入口：…  
> 你要哪种？  
> 1）**立刻废止**旧读/写，存量只跑一次迁移（推荐）  
> 2）**限期双读**：读优先 A，写只写 A，到期删 B（须约定日期）  
> 3）**其它**（你指定）

**禁止**：未询问就「先留兼容」「暂时还读旧表/信封」「主路径改了旁路以后再说」。

### 4. 先改文档，再改代码

按 `docs-before-code`：在对应 PRD/口径里写明新真源 + 旧口径命运（废止句）。用户确认文档后才动代码。

### 5. 收口搜索（与 `invariant-close-loop` 同级）

改完后在回复里列出：

- 搜了哪些词  
- 还剩几处旧读/写  
- 每处为何安全（或已删）  

没有这份清单，**不准**说「已切到新口径」。

## 与相近规则的关系

| 规则 / skill | 分工 |
| --- | --- |
| `communication-first` | 先对齐再改；本 skill 专管**真源切换时旧口径的确认** |
| `docs-before-code` | 先改文档废止句 |
| `invariant-close-loop` | 已定禁止句必须搜全入口；本 skill 在**定禁止句之前**就要问清旧口径怎么死 |
| `object-model-first` | 新对象装什么；本 skill 管**旧装法怎么下线** |
| `node-mask-state-machine` | 打码结论只住节点；切真源时打码收图必须跟节点走 |

## 输出格式（切换真源或修双真源 Bug 时）

```md
## 真源切换确认

### 新口径（一句话）
…

### 旧口径盘点
| 旧路径 | 入口 | 建议命运 |
| --- | --- | --- |
| … | … | 废止迁一次 / 双读到期… |

### 请你选
1）…  2）…  （默认推荐写在前）

### 确认前不改代码
等你点头后再改 docs → 再改代码 → 交收口搜索清单。
```

若用户已明确「删旧表 / 废止 / 不要兼容」，选项 1 视为已批准，仍须做盘点 + 收口搜索，不得漏旁路。
