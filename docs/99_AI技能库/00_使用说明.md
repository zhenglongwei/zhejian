# AI 技能库使用说明

本目录存放**可复用的开发工作流提示词**，供 Cursor / AI 助手在专项任务中按项目规范执行，**不是业务代码**。

与 `.cursor/rules/` 的分工：

| 位置 | 作用 |
|---|---|
| `.cursor/rules/` | 长期强约束，每次对话自动加载 |
| `docs/99_AI技能库/` | 常驻专项任务（本目录根下 `skill_*.md`） |
| `.cursor/skills/` | Agent 可发现的技能入口，指向本目录对应文档 |
| `_归档/` / `.cursor/skills/_archived/` | 历史专项，默认不加载；需要时再 @ 或移回 |

---

## 常驻技能（仅 7 套）

写码前硬门槛：**先想清楚数据结构**（流程 / 节点 / 图 / 报告住哪、谁读谁；含大模型返回的固定形状）。未写清不准拆功能写码，见 `object-model-first`。

| 文件 / 入口 | 用途 | 适合时机 |
|---|---|---|
| [skill_feature_build_verify.md](./skill_feature_build_verify.md) | **需求→数据结构/对象边界→拆分→写码→逐项验证** | 新功能、需求变更、跨端链路 |
| [skill_object_model_first.md](./skill_object_model_first.md) | **数据结构先想清**：对象边界、身份、读写唯一路径；**LLM 输出形状必须固定** | 动流程/节点/图/报告；接大模型；增删后串项 |
| [skill_truth_source_cutover.md](./skill_truth_source_cutover.md) | 新口径切换；**须用户确认是否保留旧口径**；预览/硬拦/打码同一套收口 | 废止表/字段、双真源 Bug |
| `.cursor/skills/grill-me` | 共识前严格追问，每次一问；未共识不写码 | 需求澄清、方案对齐 |
| [skill_node_mask_state_machine.md](./skill_node_mask_state_machine.md) | 节点图打码状态机（结论只住节点；失败可原图上网） | 打码 / 托管对账 / 公开读图 |
| [skill_merchant_flow_photo_pipeline.md](./skill_merchant_flow_photo_pipeline.md) | 商家进度：本批识图成项、图跟项走、不等整本 | 归组 / 打码 / 增删项串图 |
| [skill_ui_copy_audience.md](./skill_ui_copy_audience.md) | 禁需求话术上屏；商家专业 / 车主友好 | 改可见文案、双端展示 |

归档技能见 [`_归档/`](./_归档/)（页面脚手架、设计检查、脱敏排障、卷九快照等）。需要时直接打开该文件执行，勿默认当常驻清单。

字段真源（业务）：[`07_案例快照与提炼层字段.md`](../11_数据结构与状态机/07_案例快照与提炼层字段.md) 等 `docs/11_数据结构与状态机/`。

**每日开发节奏**：项目根 [`每日固定动作.md`](../../每日固定动作.md)。

---

## 使用方式

1. 非 trivial：先 `grill-me` / 沟通对齐 → `object-model-first`（数据结构）→ `feature-build-verify` 拆分写码验证。
2. 废止旧表 / 双真源：`truth-source-cutover`（须用户确认旧口径）。
3. 打码 / 进度传图：挂对应领域 skill，仍须先过数据结构五问。
4. 改 UI 文案：`ui-copy-audience` + 规则 `ui-copy-not-prd`。

## 维护约定

- 常驻只保留上表 7 套；新增常驻须用户同意后再进根目录与 `.cursor/skills/`。
- 专项一次性流程进 `_归档/`，不要堆回常驻表。
- 若与 `.cursor/rules/zhejian-development.mdc` 冲突，以 **rules 的合规底线** 为准。
