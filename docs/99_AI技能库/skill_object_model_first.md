# Skill: 新对象先设计边界与身份

> Agent 入口：`.cursor/skills/object-model-first/SKILL.md`  
> 配套：`feature-build-verify`（需求对齐之后、拆功能之前）· `docs-before-code` · `invariant-close-loop`  
> 检测项+挂图的实例：`merchant-flow-photo-pipeline`（真源 `26` §6.3～6.5）

## 目标

遇见**新功能、新业务对象、或改一项里装什么**时：先用产品语言把「什么算一项、身份是什么、什么住里面」写进对应文档，再拆任务写码。禁止按页面上一排卡片去排两个数组，再用第几项把字和图对上。

## 使用场景

- 新增一类可增删改的东西（检测项、施工项、接车分类、方案行、相册节点……）
- 一项里要挂图、挂金额、挂结论，或两端各自展示同一对象
- 用户提到：增删后对错了、串项、删了又拼回来、同名两项并成一项
- `feature-build-verify` 第 1 步发现会动对象边界

**可跳过**：改一个错字、只改文案、已批准方案下的机械改字段名、对象边界文档已写清且本轮不改边界。

## 动手前必须答清（产品语言，写进方案给用户看）

1. **什么算一个对象？** 一句话说清边界。例：一项检测 = 部位 + 挂图 + 检查结果 + 检查发现；不是「第几张图」也不是「第几行卡片」。
2. **身份是什么？** 改名、换顺序、中间插入、删除之后，还是不是「同一个」。**默认不是身份**：展示顺序、名称、图片地址。名称可重名、可改，不能当主键。
3. **什么住在对象里面，什么只引用？** 同生共死的放进去（图跟该项）。可卸下、可进本单图库、可被多项共用的，用身份去挂，不要复制成另一套平行名单再按下标对。
4. **哪些操作不能把关系拆乱？** 至少写：加一项、删中间一项、改名、换图、换顺序、两端各自展示。列表认卡片必须用该项自己的稳定身份，不能用第几项。
5. **旧数据怎么迁一次？** 允许「打开一次按旧形状生成身份并落库」；禁止每次读取都按下标再对一遍。

未写清这五条，**不准进入功能拆分和写码**。用户确认方案后，先把口径写入对应 `docs/`（及必要时 `docs/11_数据结构与状态机/`），再写代码。

## 反模式（禁止）

- 两个数组（一排字、一排图）用第几项对齐
- 用部位名 / 项目名合并两项
- 用图片地址反查「这是哪一项」
- 页面列表用第几项当卡片身份（增删后后面卡片会显示别人的图）
- 空列表用库里散图把项重新拼出来
- 只改这一页的数组形状，读写接口、另一端、归组结果仍按下标对

## 收口搜索（改完必须做）

至少搜：按下标配对、用名称当主键、用图片地址反查项、列表卡片身份用第几项、把一排图重生成项。有命中须说明为何安全，或改掉。搜过什么写进验证，没有清单不准说做完（`invariant-close-loop`）。
