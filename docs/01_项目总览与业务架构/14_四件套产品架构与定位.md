## 1. 一句话定位

**辙见平台 = 汽修维修案例托管站**（类 GitHub：门店托管自己的案例档案，公开/私有门店说了算）。  
**辙见小程序门店端 = 案例生产工具**（上传图文、生成面向车主的单据、微信群转案例）。  
生产出来的档案**可以托管到案例站，也可以不托管**。

| 类比位 | 我们的东西 |
| --- | --- |
| GitHub（内容**托管**平台） | **辙见案例站** `geo.simplewin.cn` |
| 本地/IDE + 工具（**生产**） | **辙见小程序门店端**（含迁入后的微信群转案例） |
| 独立诊断（不进托管链路） | **GEO 体检工具**（挂在官网 `simplewin.cn`） |

官网 `simplewin.cn` **只做**：盈简/辙见介绍 + GEO 体检（及榜单）。**不做**案例库主台，微信转案例主入口迁入小程序（官网 archive 仅导流，三期下线）。

## 2. 四件套各是什么（2026-09-03）

| 名称 | 是什么 | 谁用 | 现状 / 分期 |
| --- | --- | --- | --- |
| **辙见平台 / 案例站** | 维修案例**档案托管**：托管/取消托管、公开/不公开、浏览三层公开页、下载与删除（分期） | 门店 | 公域展示已有；**我的案例库**二期；单据与硬删三期 |
| **辙见小程序（门店端）** | **生产**：原始图文 → 报价/工单/确认单/质保/报告等；托管开关；公开前脱敏预览 | 门店技师 | **解冻**按托管定位分期改造；不再「冻结新功能」 |
| **微信案例转换工具** | 群聊 → **完整相册 + 面向车主单据**（非草稿） | 门店 | 一期官网导流；**三期迁入小程序** |
| **GEO 体检工具** | AI/搜索可见性诊断与榜单 | 任何人 | 官网 `/check` `/rank`，不进案例站根路径 |

### 2.1 小程序两端

- **门店端 `packageMerchant/`**：生产工具（剪映/IDE 位）。  
- **车主端**：收缩为**服务配合**——接收/确认单据、查看自己的维修档案；**废止「用户授权公开」**；公域逛案例以案例站为主。

### 2.2 案例 = 详细档案（不是一篇文章）

托管对象是一份档案，公开时默认三层整包可见（均须脱敏 + 商家预览确认）：

1. **概况 + 原始图文（脱敏后）**  
2. **面向车主的各类单据（脱敏后）**  
3. **本单 FAQ**（AI 可辅助生成，商家确认后公开）

商家可修改全部公开稿内容；见 §3.4 确认件规则。

## 3. 核心规则

### 3.1 主权与托管

| 权利 | 含义 |
| --- | --- |
| **托管 / 取消托管** | 门店决定档案是否进入案例站托管库；未托管不上公域索引 |
| **公开 / 不公开** | 托管时可选择；**默认不公开**；公开须强制脱敏并预览确认 |
| **下载** | 门店可导出完整档案（三期） |
| **删除** | **硬删**与「取消公开仍私密存档」分离；硬删策略三期单独立项 |
| **上传** | 门店上传历史材料，来源统一为「商家上传」 |

平台不因托管取得内容所有权，不要求独家。

### 3.2 平台不背书真实性（2026-09-03）

- **不担保**内容真实，**不审核**真实性（含取消「真实性机审 ≥60」作为公开发布硬门禁）。  
- 公开前商家须勾选 **真实性承诺**；违诺或投诉可 **取消公开**（档案仍私密保留）。  
- 对外禁止「已审核」背书字样。

### 3.3 来源标签（仅一类）

| 标签 | 含义 |
| --- | --- |
| **商家上传** | 唯一对外来源标签（含小程序生产、微信工具迁入后的产物、历史上传） |

**废止**：沟通记录转化 / 用户授权 / 其他 SaaS 作为对外来源标签；**废止「用户授权发布」路径**（商家可持续改稿，授权标签不可靠）。

### 3.4 确认件冻结 + 修订另存

- 车主确认过的单据在确认瞬间冻成 **确认件**（带时间戳），**不可静默覆盖**。  
- 商家后续修改须 **另存修订版**；公开页可展示确认件与商家更新版，并标最近更新时间。  
- 平台 **不比对**修订是否与确认件一致；投诉指向误导时按违诺取消公开。

### 3.5 隐私与脱敏

| 场景 | 规则 |
| --- | --- |
| **不公开（私密）** | 脱敏可选；发布/保存旁「使用脱敏工具」**默认勾选**，商家可取消 |
| **公开** | **强制**走脱敏过滤；商家预览、可改后再确认 |
| **责任** | 不论是否使用脱敏工具，平台 **不担保零残留、不担责** |
| **对外文案** | 不必强调「工具辅助」；须标「商家上传」；保留投诉 / 通知下架 |
| **下架** | 仅取消公开，**仍作为私密档案存储** |

保留技术过滤（`MASK_RULES`）作为公开硬门槛能力；与「不担保零残留」并存。

### 3.6 三个易混概念

| 概念 | 平台做不做 | 说明 |
| --- | --- | --- |
| **真实性背书 / 真实性审核** | ❌ | 不机审挡发、不人审真实 |
| **公开前脱敏过滤** | ✅（公开强制） | 硬过滤敏感信息；不担保零残留 |
| **确认件保全** | ✅ | 冻结确认副本；修订另存 |

## 6. 分期（与开发计划一致）

| 期 | 内容 |
| --- | --- |
| **一期** | 文档/协议/文案对齐；取消真实性机审硬门禁；公开强制脱敏+承诺；来源仅商家上传；去用户授权；官网 archive 导流；车主端去授权公开 |
| **二期** | 托管/取消托管主链路；概况+FAQ；案例站「我的案例库」；确认件冻结+修订另存；公开三层页骨架 |
| **三期** | 单据产品化；微信工具迁入小程序；下载/硬删；托管台 IA 加深；`MASK_RULES` 下沉 shared |
