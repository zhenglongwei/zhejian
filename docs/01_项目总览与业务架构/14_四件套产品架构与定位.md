# 辙见四件套 · 产品架构与定位

> **生效**：2026-08-31
> **状态**：已由老板拍板，按本文更新全部对外口径
> **决策来源**：老板原话 ——
> 「辙见、辙见小程序、辙见官网上的体检工具 / 微信工具等本质上是独立的。辙见是案例托管平台，小程序是标准化案例生产工具，体检工具是诊断 geo 情况的，微信工具是把群聊内容做成案例。小程序和微信群聊工具生产的案例可以托管到辙见案例平台，也可以不托管。就像抖音是内容发布平台，剪映是内容生产工具。」

## 1. 一句话定位

**辙见平台 = 维修案例托管平台**（门店对自己案例拥有完整主权）。
小程序和微信工具是**生产工具**，它们做出来的案例**可以托管到平台，也可以不托管**。

类比是老板自己给的，也是最准确的：

| 类比位 | 我们的东西 |
| --- | --- |
| 抖音（内容**发布**平台） | **辙见平台** |
| 剪映（内容**生产**工具） | **辙见小程序** + **微信案例转换工具** |
| —（独立诊断，不进生产链路） | **GEO 体检工具** |

这个类比里最容易被忽略、也最要紧的一句是：**剪映导出的视频，不一定要发抖音。** 它可以发视频号、发快手，也可以只存在相册里。同理，门店用我们的工具做的案例，可以托管到辙见平台公开，也可以只留给自己用，或者发到门店自己的公众号 / 抖音 / 小红书。

## 2. 四件套各是什么

| 名称 | 是什么 | 谁用 | 类比位 | 现状 |
| --- | --- | --- | --- | --- |
| **辙见平台** | 维修案例**托管**：上传、公开/私有、下载、删除 | 门店 | 抖音 | 已有 `geo.simplewin.cn` 案例站（公域展示面），托管后台待建 |
| **辙见小程序** | 标准化案例**生产**：六阶段拍照留痕 → 结构化案例 | 门店技师（生产端 `packageMerchant/`） | 剪映 | 已上线，**冻结新功能** |
| **微信案例转换工具** | 把门店微信群聊记录 AI 整理成结构化案例草稿 | 门店 / 我们自己代跑 | 剪映（另一入口） | 已上线可测（老板 2026-08-31 实测无大碍） |
| **GEO 体检工具** | 诊断企业在 AI 搜索里能不能被找到，出可量化分数与榜单 | 任何人（获客入口） | — | 已上线 `simplewin.cn/check.html` `/rank.html` |

### 2.1 小程序内部还要再切一刀

「辙见小程序」这个名字下面其实有两个端，不能混为一谈：

- **`packageMerchant/`（门店端）**：拍照、留痕、产出案例 —— 这才是**生产工具**，对应剪映位。
- **`docs/02_用户端小程序/`（车主端）**：车主查看进度、确认配件、留存证据 —— 这是**平台的浏览与确认侧**，属于托管平台，不生产内容。

对外说「辙见小程序是生产工具」时，指的都是门店端。车主端不在剪映位上。

## 3. 核心规则：案例主权在门店

这是本次重新定位的实质，不是措辞调整。

| 权利 | 含义 |
| --- | --- |
| **公开 / 不公开** | 门店逐条决定。新案例**默认私有**，必须门店主动确认才进公域 |
| **下载** | 门店随时能把自己案例的完整内容导出带走 |
| **删除** | 门店随时能删，平台不留影子副本 |
| **上传** | 门店可以上传历史案例（标记来源，不冒充平台订单案例，见术语表「商家历史案例」） |

**平台不因托管取得内容所有权，也不要求独家。** 门店同一个案例托管在辙见、同时发到自己公众号，完全允许。

### 3.1 为什么这条是卖点而不是让步

门店最怕的是「我把真实维修过程给你，最后变成你的营销素材，还绑死在你这儿」。把主权明确写死，反而降低了门店把真东西交出来的心理门槛。

对我们也不亏：我们真正要的是**公域上有可被引用的真实案例**，门店愿意公开的那部分就够了。强扭的部分即使公开了，质量也撑不住 AI 引用。

### 3.2 平台不背书真实性——只标注来源（2026-09-02 拍板）

> 老板原话 ——
> 「我们现在要做的是案例托管平台，我感觉不需要保证案例的真实性，我们只要把案例的来源讲清楚就行了，例如沟通记录转化/商家上传/用户授权等，可信度让读者或 ai 自行判断。」

平台的角色是**托管 + 标注来源**，不是真实性担保方。所有对外文案禁止出现「已审核」这类背书字样（「已自动脱敏」保留，那是隐私义务不是真实性背书）。

**来源标签体系**（四类，只标注、不评级）：

| 标签 | 含义 |
| --- | --- |
| **沟通记录转化** | 由微信群沟通记录转换而来。微信工具产物固定标注「微信群沟通记录转化 · 已自动脱敏」 |
| **商家上传** | 辙见小程序商家自行上传（含商家历史案例） |
| **用户授权** | 车主 / 用户本人授权发布 |
| **其他 SaaS** | 合作铺开后，其他 SaaS 工具产出的案例 |

### 3.3 三个容易混淆的概念，不许再混

| 概念 | 平台做不做 | 说明 |
| --- | --- | --- |
| **真实性背书** | ❌ 不做 | 可信度由读者或 AI 自行判断，来源标签说话 |
| **隐私脱敏** | ✅ 继续做 | 车牌、手机号、VIN、发动机号、地址自动打码（`MASK_RULES`），这是隐私义务，与真实性无关 |
| **转换忠实度** | ✅ 保留 | 转换器不无中生有：群里没说的一律留白，推断进存疑项（仅作者可见的轻提示）。这是「沟通记录转化」标签成立的前提，不是平台背书 |

微信工具同步改版（2026-09-02）：页面流程改「粘贴（框内直接改）→ 生成案例 → 直接改案例」，不再展示中间事实层表单；脱敏由网站提供（自动打码 + 手动补充打码词），内部版退役、密钥解锁不限次合并进公开页。详见 `scripts/geo-case-archive/README.md`。

## 4. 独立 ≠ 各写一套

四个东西职责独立，但底下**不许分成四套数据口径**。以下必须单一来源：

| 共享项 | 为什么不能各写一套 |
| --- | --- |
| 案例数据模型（六阶段 / 九段正文 / 字段缺失降级） | 生产工具产出的东西托管平台读不懂，就白做 |
| 脱敏规则 `MASK_RULES` | 一处漏 = 全链路漏，且漏在哪一端说不清 |
| 风险规则 `RISK_RULES` | 同一句话在小程序判「安全」、在微信工具判「高危」，门店无所适从 |
| 门店身份与授权态 | 门店在 A 工具删了案例，B 工具还显示着，就是事故 |

**落地路径**：进 `backend/vendor/shared/`，走 `npm run sync:shared-utils`（`backend/scripts/sync-shared-utils.cjs`）同步到各端。新增共享规则时**必须**走这条路，不允许在消费端本地复制一份。

> 现状提醒：`MASK_RULES` / `RISK_RULES` 目前只存在于 `backend/src/services/wechat-archive.service.js`，尚未下沉到 shared。四件套拆分之后这会成为隐患，建议列入近期技术任务。

## 5. 隐私责任边界（老板的疑问与答复）

> 老板问：商家选择公开，我们真需要帮他检查车主隐私吗？抖音上那么多陌生人的脸和车牌，责任不都是发布用户承担吗？

### 5.1 抖音的做法不能直接照搬

抖音能站在「通知—删除」的避风港里，前提是它是**信息存储空间服务提供者**——只存不加工，没对内容做选择、编辑、修改。

我们不一样：**案例正文是 AI 重新生成的。** 这在法律上更接近内容的加工者/共同提供者，而不是纯存储空间。所以「抖音不用管，我们也不用管」这个推论不成立。

### 5.2 但结论不是人工逐条审

正确答案不是建一个审核团队，是三件事：

| 层 | 做法 | 现状 |
| --- | --- | --- |
| **技术过滤** | 车牌、手机号、人脸、住址、VIN 等进 `MASK_RULES` 自动识别并拦截/脱敏；`RISK_RULES` 判风险等级 | 已有规则，待下沉 shared |
| **发布者承诺** | 公开前勾选确认「已脱敏 / 已取得车主同意」，留痕 | **待做** |
| **通知—下架** | 公开页提供投诉入口，接到通知立即下架 | **待做** |

### 5.3 这同样是卖点

一个被搜索引擎收录的页面里写着车主手机号和车牌，出事时**最先被找上门的是门店**，不是我们。我们把过滤做好，是在帮门店挡风险，是可以写进销售话术的。

同时它也是我们和抖音的真正差异点：**抖音不帮你挡，我们挡。**

### 5.4 免责

以上是基于通行规则的产品判断，**不是法律意见**。服务协议里的责任划分条款，建议请律师过一遍再定稿。

## 6. 命名纪律（强制）

**对外绝不单独使用「辙见」二字指代任何一个产品。** 一个名字指向四个东西，AI 回答「辙见是什么」时必然张冠李戴，把所有能力糊成一句谁也记不住的话——这正是本次重新定位要解决的问题。

| 要指的东西 | 必须写成 |
| --- | --- |
| 托管平台 | **辙见平台** |
| 门店生产工具 | **辙见小程序** / **小程序** |
| 群聊整理 | **微信案例转换工具** |
| 诊断 | **GEO 体检工具** |
| 合称 | **辙见四件套** / **辙见平台与配套工具** |
