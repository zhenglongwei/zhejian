## 1. 为什么改

> **2026-11-20 口号更换**：主口号由「让真实被看见」改为 **「用真实重构信任」**。对外论证统一成一条因果链：**遇到不懂的问题，越来越多人先问 AI → AI 只能拿网上的资料拼答案 → 网上营销信息远多于真实信息，答案就偏离真实 → 我们用真实案例破解，不用营销口号润色**。「专业性高、普通人难分辨、造假多」是**内部理由，不上公开页面**——写在对消费者说话的页面上，等于替用户下判断。官网文案围绕新口号重写，勿再沿用旧口号（含 `og-image`、`llms.txt`、页脚）。  
> **2026-11-20 同日 · 案例站跟进**：`zhejian.simplewin.cn` 的口号位全部换成「用真实重构信任」——`h5/index.html`（title 与 description）、`h5/shared/home-render.js`（title + 三处 hero `<h1>`）、`h5/shared/empty-shelf.js`（默认标题）、`backend/src/services/h5-page-prerender.service.js`（bot 预渲染 title + `<h1>`）、`backend/scripts/h5-html-prerender-smoke.js`（断言）。副标题「这里展示用户选择公开的案例。现阶段以修理厂商家为主。」保持不变，与 `constants/home.js` 的 `HOME_PLATFORM_IDENTITY` 一字不差——案例站对浏览者说的是事实，不塞论证。改 shared 脚本要同步 bump 引用页的 `?v=`。  
> **2026-11-20 辙见定位修订**：辙见改写成「**汽修门店的记录与宣传工具，案例公开是它的一个出口**」，不再叫「案例上传与公开产品」——门店付钱是因为效率与宣传，GEO 是附赠。对外叙事顺序：**记清楚每一单 → 顺手出各平台文案 → 需要时托管公开 → AI 可见是顺带结果**。官网与工具页**先专注汽修门店**，其他行业只在公司介绍里带一句，不再承诺「先补齐官网、地图、公众号」。盈简帮助**各行商家与组织**这一条不变，页面勿用「门店」指代全部用户。公开案例站 **`zhejian.simplewin.cn`**。  
> **2026-09-20**：GEO 是档案被看见之后的附带结果，**不是**公司身份。案例站公开域名为 **`zhejian.simplewin.cn`**（过渡期仍接受 `zhejian.simplewin.cn`，不做长期 301）。  
> **案例站 = 公开案例站**；**小程序商家端 = 生产**（含从聊天创建）；  
> **官网 = 公司介绍 + 辙见说明**。GEO 体检已于 **2026-11-20** 从官网下线（见 §3），诊断能力只留内部脚本。从聊天创建的主入口在小程序；**2026-11-20 起官网不再宣传这个入口**（工具卡、专用码、`?entry=wechat-archive` 引用全部撤下），也不再单开 `/archive` 页。

当前阶段：

1. 官网讲清盈简做什么：把商家真实发生过的业务整理成可核对、可被搜索和 AI 准确引用的案例。  
2. 案例生产与公开能力在小程序 + 案例站按三期推进；现阶段以修理厂为主。  
3. 案例站继续做公域信源，**不**把体检塞进案例站根路径；体检已不是官网工具，只是内部诊断能力，更不是公司标题。

**命名纪律**：不单独用「辙见」二字指代任一产品。详见 [`14`](14_四件套产品架构与定位.md)。

## 2. 品牌怎么切

| | 盈简科技 | 辙见 |
| --- | --- | --- |
| 是谁 | 公司 | 汽修门店的记录与宣传工具，案例公开是一个出口（当前深耕汽修） |

禁止把官网写成「我们是一家 GEO 公司」。禁止把「专注汽修门店的 GEO 服务商」当作公司总定位。禁止把「专业性高、普通人难分辨、造假多」写进对消费者说话的页面——那是内部理由，上页面就变成替用户下判断。对外文案**不再使用「数字资产」**（易被理解成虚拟币），统一说「可核对、可公开的案例／档案」。禁止用「门店」概括盈简全部客户。

四件套的完整切分、案例主权、命名纪律见 [`14_四件套产品架构与定位.md`](14_四件套产品架构与定位.md)。

对外主语仍是**客户信得过、资料找得到**，不主打「讨好模型 / 骗过 AI」。

## 4. 体检：全自动，两条通道不许混

> **2026-11-20 起本节只描述内部能力**：官网页面与公开 API 已下线，商家不再自助操作。  
> 巡检服务、题库派发、评分口径与历史数据全部保留，改由内部脚本（`backend/scripts/geo-*`）在拜访前后跑，结论用于自家诊断与报告，不对外承诺分数。

> **2026-08-30 改版**：原方案要求用户手动提交 10 题 × 5 个大模型 × 2 张截图，
> 操作成本过高、无法落地。改为**程序自动巡检**，用户只填企业名 + 城市 + 行业，其余全自动。

输入：企业名称（必填）+ 城市（强烈建议）+ 行业（决定用哪套题，必填）。

程序用 Playwright 驱动本机 Chrome，按配置的顺序访问各平台、逐条提问、抓回答与引用源、结构化解析、落库评分。用户全程不用动手。

### 4.1 题库按平台类型自动派发（关键设计）

| 平台类型 | 问什么 | 测出来什么 | 典型平台 |
| --- | --- | --- | --- |
| `search` | **带店名**的查询 | 网页实测地基分——车主搜你名字，搜出来的是什么 | 百度 / 360 / 必应 |
| `chat` | **不带店名**的业务题 | AI 可见性分——车主不问店名时，AI 会不会主动想到你 | 豆包 / 通义 / 元宝 |

**这两套题绝不能混。** 早期版本给搜索引擎喂「杭州底盘异响常见原因」这种不带店名的问题，
结果 13 家门店清一色 17 分、0% 提及，彻底排不出名次——不是数据造假，是**活儿派错了**：
搜索引擎的强项是「拿名字搜」，不带名字的推荐类问题只会返回通用文章，永远不会点名一家小店。
拆开之后，同批门店立刻分化成 79 / 78 / 74 / 70 / 70 / 69 / 59。

### 4.2 评分：三个分数，各测各的

| 分数 | 来源 | 权重构成 |
| --- | --- | --- |
| **网页实测地基分** | 搜索引擎带店名查询 | 命中率 30 / 首条位次 30 / 来源质量 25 / 来源广度 15 |
| **AI 可见性分** | 大模型不带店名提问 | 提及率 50 / 位次 30 / 准确度 20 |
| **接口联网分** | 联网 API 通道 | 另一条路，不冒充网页实测 |

- 同一轮两块都测到 → `0.6 × 可见性 + 0.4 × 地基`，标签写「综合分」
- 只测到一块 → **就用那一块**，标签如实写。**绝不因为「反正有个数」就把单块成绩标成综合分**
- 没测的列显示「未测」，不做任何估算

来源质量按「车主会不会真看这里」加权：地图/本地生活 1.0 > 社区内容 0.8 > 其他 0.6 > 工商黄页 0.4。
命中来源里六成以上是工商黄页的，单独打标「只有工商档案」——**你活在工商档案里，但没有自己的经营资产**。

| 限制 | 处理 |
| --- | --- |
| 大模型网页版要登录 | 专用 Chrome profile 存 cookie，人扫一次码；过期时记 `login_required` 并跳过该平台 |
| 验证码 / 滑块 | 探到风控关键词立刻终止该平台剩余题目，记 `captcha`；批量巡检自动延长冷却 |
| 平台改版 | 多候选选择器，全失败才报 `selector_broken`；搜索平台额外容忍一次重试 |
| 单 IP 频控 | 查询间隔（百度 15 秒）+ 每场题数上限 + 门店之间冷却 45 秒 |
| 进程被 kill | 开跑前回收超 30 分钟的僵尸批次 |

**铁律：抓不到就是抓不到。** 任何失败状态**绝不**当成「没被提到」计入分母。
门店看到 0 分会去 AI 那里求证，对不上的话分数和公司信誉一起完蛋。

详细操作见 [`docs/09_SEO_GEO_AI内容基础设施/15_GEO浏览器巡检操作手册.md`](../09_SEO_GEO_AI内容基础设施/15_GEO浏览器巡检操作手册.md)。

### 4.4 报告怎么写

- 三个分数分开展示，不要合成一个「87 分」交差。
- 每条回执都能点开看原始证据：问了什么、搜出来第几条是什么、来源是谁。
- 正文必须是：**缺什么、错什么、自动查了什么、哪些没查成**。
- 结论是抽样与公开检索，不是全网公证。

### 4.5 滥用与成本

公开可用必须 **按 IP 限每日次数**。巡检耗时长（单店 2–3 分钟），按异步任务排队，前端轮询进度。  
**2026-11-20**：公开入口已撤，本条不再对外生效；但 `geo-check-rate-limit` 仍被登录、短信、微信转案例等公开接口复用，**不可随体检一起删**。

## 7. 文案红线

- 不写好评返现、全网最低、100% 修好、事故车线上估价。
- 不承诺「AI 引用 N 次」「保证出现在豆包/元宝」；工具页第 5 条只能写「有机会出现在 AI 的问答里」。
- 体检结论是抽样与公开检索，不是全网公证。
- 官网首屏 6 字口号为「用真实重构信任」，无旧门店长句。
- **官网不出现任何未经核实的数字**：门店数、扫描数、行业趋势百分比一律不放；宁可不写，也不借个人经历充当公司数据。
- **不写行业批判**：「专业性高、普通人难分辨、造假多」是内部理由；对消费者说话的页面改成「AI 拿到的资料里营销信息太多，所以答案偏离真实」。
- **不写「证据摆出来，判断留给消费者」**：普通人看不懂原始证据，正是需要被解读的部分。正确表述是「把案例整理成消费者和 AI 都看得见、看得懂的样子」。
- 对外文案不用「数字资产」，统一说「可核对、可公开的案例／档案」。
- 公司介绍通读一遍，看不到「盈简只服务汽修门店」。
- 辙见 / 案例站通读，无用「门店」指代全部上传者；现阶段限制有一句老实说明。
- 汽修案例、小程序仍可深讲修理厂场景，不与总定位打架。
