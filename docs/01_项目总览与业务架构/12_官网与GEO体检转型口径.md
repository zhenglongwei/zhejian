# 盈简官网与 GEO 体检工具 · 转型口径

> **生效**：2026-08-28  
> **状态**：已共识，按本文开发  
> **进度勾选**：[`docs/00_开发计划.md`](../00_开发计划.md) §7.18  
> **共识来源**：产品方向讨论（官网最小可用 + 两层体检 + 小程序冻结）

---

## 1. 为什么改

辙见小程序的本质是**门店日常生产真实案例的工具**。在自己还没被搜索和 AI 找到、客户也还没感到「网上找不到会丢客」之前，先推这套生产工具，时机不对。

当前阶段改成：

1. 把 **盈简科技** 和 **辙见** 的对外身份先放到公网上（能被搜到、能被引用）。
2. 做一个谁都能用的 **极简 GEO 体检**，拜访时打开就能演示。
3. 先把盈简和辙见自己运营到「AI 搜索可见」，再拿同一套方法服务客户。
4. 服务客户的前期仍是补齐在线信息、发布**真**案例文章；案例生产小程序留到中后期门店需要稳定产出时再作为主工具。

小程序：**冻结新功能**（只修阻塞性故障），不作废。现有 `geo.simplewin.cn` 案例站继续作为辙见公域内容，不改成体检工具的家。

## 2. 品牌怎么切

| | 盈简科技 | 辙见 |
| --- | --- | --- |
| 是谁 | 公司 | 公司在汽修行业的落地产品 |
| 对外一句话 | 帮企业把真实业务变成网上能查到、问答里能被提到的公开资料 | 用较低成本，做出经得起看的真维修案例 |
| 体检工具 | **开口产品**，不限行业 | 汽修解法之一，挂在产品页，不占用工具品牌 |

禁止两个站都写成「我们做 GEO、做案例」，以免搜索和模型把两家认成一家。

对外主语仍是**客户信得过、资料找得到**，不主打「讨好模型 / 骗过 AI」。

## 3. 第一期交付（同一域名）

全部挂在 **simplewin.cn**（盈简主站），三个入口：

| 路径 | 页面 | 第一期要做到 |
| --- | --- | --- |
| `/` | 公司 | 谁、做什么、不做交易撮合、怎么联系 |
| `/zhejian` | 辙见产品 | 给谁用、案例在公网、小程序是生产工具（中后期）、链到案例站 |
| `/check` | GEO 体检 | 输入企业名（建议加城市）→ 报告；可上传截图 |

对照：免费检测挂在公司官网下（如常见的网站评分工具），不另开检测专用域，也不塞进 `geo.simplewin.cn` 案例库。

现有 `simplewin.cn` 若仍是旧 Next 站：本仓库 `brand-web/` 为新真源；上线时替换或按路径切流，**不得**把体检接到辙见案例 Nginx 根上。

代码放本 monorepo `brand-web/`；体检 API 走辙见 backend 的公开接口（见 §6），主站页面用静态 HTML，便于收录。

## 4. 体检工具：两层，不许混

输入：企业名称（必填）+ 城市（强烈建议）。不规定用户拍哪个 App。

### 4.1 第一层 · 信息在不在、对不对

| 渠道 | 第一期怎么查 | 说明 |
| --- | --- | --- |
| 百度网页 | **自动** | 结果按来源打标：疑似官网、知乎、搜狐、百科、媒体、其他。知乎/搜狐**不**单独接接口 |
| 地图 | **自动**（高德或百度地点检索） | 有没有点、名称是否对得上 |
| 公众号 / 视频号 / 小程序 | **自动尝试** TokenHub 混元联网 + 截图补 | 走混元 `web_search_options`（不是元宝 App、不是搜一搜）。报告只认来源里的 `mp.weixin.qq.com` 等链接；没有公众号链接就写「这次没搜到公众号」，禁止写成「已查遍微信」。旧结论「元宝不含公众号」仍成立，混元联网是否覆盖公众号以实测为准 |
| 抖音 / 头条 | 截图识别或勾选 | 有没有号归第一层；豆包会不会提到归第二层 |

调不到的接口必须写 **「未查 / 无开放接口」**，禁止写成已搜索。

### 4.2 第二层 · 大模型有没有引用

| 通道 | 第一期 | 报告必须标明 |
| --- | --- | --- |
| 豆包（火山方舟 + 联网） | **自动** | 「字节系模型联网探测，不是豆包 App」 |
| 任意截图 | **识别 + 对照企业名分析** | 提到没有、名称对不对、有无竞品、看得见的来源（公众号/网页/地图等）、像搜索还是对话。平台认不出就标未识别 |
| 通义联网 | 可后台自动（不阻塞第一期主路径） | 同样标明非 App |
| 元宝 App / 微信搜一搜 AI / Kimi / DeepSeek 官方 | **不**接开放对话接口冒充 App | 用户若上传了这类截图，走通用识别 |

禁止用混元/TokenHub 联网冒充「元宝实测」或「搜一搜实测」。禁止用阿里云套 DeepSeek 冒充 DeepSeek 自家检索。

### 4.3 报告怎么写

- 两层分开展示，不要合成一个「87 分」交差。
- 可以用简要综合判断（红 / 黄 / 绿或低 / 中 / 高），但正文必须是：**缺什么、错什么、自动查了什么、截图补了什么**。
- 截图分析是补充，不是规定拜访拍几家。

### 4.4 滥用与成本

公开可用必须 **按 IP（及可选设备）限每日次数**。缺密钥时该项标未配置，其余项仍出报告。

## 5. 自己先体检、再拜访

站点上线后，用本工具查「杭州盈简科技」「辙见」，缺的公开页和资料先补。这是获客前提，不是上线后的可选项。

服务客户前期：补官网/地图/微信/短视频等公开资料，整理**确实发生过**的案例发到公网。禁止用假案例或纯软文冒充辙见案例。生产小程序的启用条件（后续可量化）：门店需要稳定、多篇真过程案例时再作为主工具。

## 6. 技术边界

| 项 | 约定 |
| --- | --- |
| 主站 | `brand-web/` 静态页 + `sitemap.xml` + `robots.txt` + `llms.txt` |
| 体检 API | `POST /api/v1/public/geo-check`（`geo.simplewin.cn`）；`GET …/geo-check/status` 只报哪几路已配密钥（不泄密） |
| 豆包探测 | 复用已有 `geo-probe-engines`（火山 Responses + web_search） |
| 混元联网 | TokenHub Chat `web_search_options`（`hy3-preview`）；密钥可复用 `GEO_PROBE_YUANBAO_API_KEY` |
| 百度网页 | 千帆网页搜索；无 Key 则改用通义联网结果，并标明不是百度 |
| 地图 | 高德地点检索；无 Key 则从网页结果里的地图/到店链接弱推断 |
| 截图 | 多模态读图（与现有百炼视觉 Key 共用），只分析用户上传图 |
| CORS | 生产允许 `https://simplewin.cn`（配置里已有）及 `https://www.simplewin.cn` |
| 小程序 | 本卷不加功能 |

## 7. 文案红线

- 不写好评返现、全网最低、100% 修好、事故车线上估价。
- 不承诺「AI 引用 N 次」「保证出现在豆包/元宝」。
- 体检结论是抽样与公开检索，不是全网公证。
