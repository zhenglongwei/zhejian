## 2. 品牌怎么切

| | 盈简科技 | 辙见平台 |
| --- | --- | --- |
| 是谁 | 公司 | 公司在汽修行业的落地产品（四件套之一，托管位） |
| 对外一句话 | **帮门店把真实业务，变成可被看到的公开档案** | 维修案例托管平台：店页由门店控制；全球库尽量全、来源可追溯 |
| 与生产工具的关系 | — | 小程序 / 微信工具产出的案例**可以**托管过来，**也可以不托管** |
| GEO | 档案被看见之后的附带结果；体检是官网工具，不是公司身份 | 不把 GEO 当案例站品牌；公开域名用 `zhejian.simplewin.cn` |

禁止把官网写成「我们是一家 GEO 公司」。禁止首页主标题使用「数字资产」（易被理解成虚拟币）。禁止两个站都写成「我们做 GEO、做案例」，以免搜索和模型把两家认成一家。

四件套的完整切分、案例主权、命名纪律见 [`14_四件套产品架构与定位.md`](14_四件套产品架构与定位.md)。

对外主语仍是**客户信得过、资料找得到**，不主打「讨好模型 / 骗过 AI」。

## 3. 第一期交付（同一域名）

全部挂在 **simplewin.cn**（盈简主站），三个入口：

| 路径 | 页面 | 第一期要做到 |
| --- | --- | --- |
| `/` | 公司 | 谁、做什么、不做交易撮合、怎么联系 |
| `/zhejian` | 辙见平台 | 案例托管站定位、门店主权、小程序生产、链到案例站 |
| `/check` | GEO 体检 | 企业名 + 城市 + 行业 → 巡检评分 |
| `/rank` | GEO 榜单 | 门店分数排序 |
| `/archive` | （过渡） | **一期**：说明微信转案例迁入小程序并导流；**三期下线**主功能 |

对照：免费检测挂在公司官网下（如常见的网站评分工具），不另开检测专用域，也不塞进 `zhejian.simplewin.cn` 案例库。过渡期 `geo.simplewin.cn` 仍解析到同一套服务。

现有 `simplewin.cn` 若仍是旧 Next 站：本仓库 `brand-web/` 为新真源；上线时替换或按路径切流，**不得**把体检接到辙见案例 Nginx 根上。

代码放本 monorepo `brand-web/`；体检 API 走辙见 backend 的公开接口（见 §6），主站页面用静态 HTML，便于收录。

### 3.1 官网首页入口（2026-09-19）

官网让门店老板 30 秒内搞懂盈简做什么、先点哪个工具。**不要**改成案例列表风。可被 AI 引用的事实句（公司是谁、做什么、不做什么、工具口径）保留。

**空库不装有货**：生产环境若还没有公开档案，所有指向案例站的按钮不得写成已经有一批档案可逛。查询 `GET /api/v1/public/h5/case-shelf`（读案例站，默认 `zhejian.simplewin.cn`；过渡期 `geo.simplewin.cn` 同接口）：

| 位置 | 没有公开档案 | 至少 1 条 |
| --- | --- | --- |
| 顶栏「公开案例」 | **了解公开案例站** → `zhejian.simplewin.cn`（外链，一直显示） | **公开案例** → 同址 |
| 第一屏次要入口 | **了解公开案例站怎么运作** → `/zhejian.html` | **我是车主，看公开维修档案** → 案例站 |
| 辙见模块 | **了解公开案例站** → 案例站；**了解托管** → `/zhejian.html` | **看公开维修档案** → 案例站；托管链不变 |

HTML 默认按「没有」写。Case 0 是盈简自己的 GEO 日记，**不是**维修案例：标题写全称，**不进一级顶栏**，放首页模块 + 页脚。

**第一屏**：主句即公司身份。一个蓝主按钮「了解辙见托管」→ `/zhejian.html`；文字链「免费做 GEO 体检」→ `/check.html`、空库时「了解公开案例站怎么运作」。不要三个一样重的蓝按钮。Logo 写「盈简科技」，不带「·GEO」。

**顶栏**：盈简科技（回首页）· 公司 · 辙见 · 工具 · 公开案例（外链）· 联系。当前项用蓝，不用橙。

官网与案例站都须给出 **辙见小程序**入口：微信搜一搜「辙见」+ 小程序码（码失败则只留文字）。小程序须可被找到：官网工具区与页脚都放入口；案例站空页把小程序码放在主路径上。

## 4. 体检工具：全自动，两条通道不许混

> **2026-08-30 改版**：原方案要求用户手动提交 10 题 × 5 个大模型 × 2 张截图，
> 操作成本过高、无法落地。改为**程序自动巡检**，用户只填企业名 + 城市 + 行业，其余全自动。

输入：企业名称（必填）+ 城市（强烈建议）+ 行业（决定用哪套题，必填）。

程序用 Playwright 驱动本机 Chrome，按配置的顺序访问各平台、逐条提问、抓回答与引用源、结构化解析、落库评分。用户全程不用动手。

### 4.1 题库按平台类型自动派发（关键设计）

| 平台类型 | 问什么 | 测出来什么 | 典型平台 |
| --- | --- | --- | --- |
| `search` | **带店名**的查询 | 网页实测地基分——车主搜你名字，搜出来的是什么 | 百度 / 360 / 必应 |
| `chat` | **不带店名**的业务题 | AI 可见性分——车主不问店名时，AI 会不会主动想到你 | 豆包 / 通义 / 元宝 |

**这两套题绝不能混。** 早期版本给搜索引擎喂「杭州底盘异响常见原因」这种不带店名的问题，
结果 13 家门店清一色 17 分、0% 提及，彻底排不出名次——不是数据造假，是**活儿派错了**：
搜索引擎的强项是「拿名字搜」，不带名字的推荐类问题只会返回通用文章，永远不会点名一家小店。
拆开之后，同批门店立刻分化成 79 / 78 / 74 / 70 / 70 / 69 / 59。

### 4.2 评分：三个分数，各测各的

| 分数 | 来源 | 权重构成 |
| --- | --- | --- |
| **网页实测地基分** | 搜索引擎带店名查询 | 命中率 30 / 首条位次 30 / 来源质量 25 / 来源广度 15 |
| **AI 可见性分** | 大模型不带店名提问 | 提及率 50 / 位次 30 / 准确度 20 |
| **接口联网分** | 联网 API 通道 | 另一条路，不冒充网页实测 |

- 同一轮两块都测到 → `0.6 × 可见性 + 0.4 × 地基`，标签写「综合分」
- 只测到一块 → **就用那一块**，标签如实写。**绝不因为「反正有个数」就把单块成绩标成综合分**
- 没测的列显示「未测」，不做任何估算

来源质量按「车主会不会真看这里」加权：地图/本地生活 1.0 > 社区内容 0.8 > 其他 0.6 > 工商黄页 0.4。
命中来源里六成以上是工商黄页的，单独打标「只有工商档案」——**你活在工商档案里，但没有自己的经营资产**。

### 4.3 现实限制怎么处理

老板已拍板：**手动登录一次 + 持久化**（不接打码平台，不绕过风控）。

| 限制 | 处理 |
| --- | --- |
| 大模型网页版要登录 | 专用 Chrome profile 存 cookie，人扫一次码；过期时记 `login_required` 并跳过该平台 |
| 验证码 / 滑块 | 探到风控关键词立刻终止该平台剩余题目，记 `captcha`；批量巡检自动延长冷却 |
| 平台改版 | 多候选选择器，全失败才报 `selector_broken`；搜索平台额外容忍一次重试 |
| 单 IP 频控 | 查询间隔（百度 15 秒）+ 每场题数上限 + 门店之间冷却 45 秒 |
| 进程被 kill | 开跑前回收超 30 分钟的僵尸批次 |

**铁律：抓不到就是抓不到。** 任何失败状态**绝不**当成「没被提到」计入分母。
门店看到 0 分会去 AI 那里求证，对不上的话榜单和公司信誉一起完蛋。

详细操作见 [`docs/09_SEO_GEO_AI内容基础设施/15_GEO浏览器巡检操作手册.md`](../09_SEO_GEO_AI内容基础设施/15_GEO浏览器巡检操作手册.md)。

### 4.4 报告怎么写

- 三个分数分开展示，不要合成一个「87 分」交差。
- 每条回执都能点开看原始证据：问了什么、搜出来第几条是什么、来源是谁。
- 正文必须是：**缺什么、错什么、自动查了什么、哪些没查成**。
- 结论是抽样与公开检索，不是全网公证。

### 4.5 滥用与成本

公开可用必须 **按 IP 限每日次数**。巡检耗时长（单店 2–3 分钟），按异步任务排队，前端轮询进度。

## 5. 自己先体检、再拜访

站点上线后，用本工具查「杭州盈简科技」「辙见」，缺的公开页和资料先补。这是获客前提，不是上线后的可选项。

服务客户前期：补官网/地图/微信/短视频等公开资料，整理**确实发生过**的案例发到公网。禁止用假案例或纯软文冒充辙见案例。生产工具（小程序 / 微信工具）的启用条件（后续可量化）：门店需要稳定、多篇真过程案例时再启用。

注意口径：生产工具是**产能手段**，不是对外主打。对外主打「**托管与主权**」——案例是门店自己的资产，我们只是让它能被查到、能被引用。

## 6. 技术边界

| 项 | 约定 |
| --- | --- |
| 主站 | `brand-web/` 静态页 + `sitemap.xml` + `robots.txt` + `llms.txt` |
| 体检 API | `POST /api/v1/public/geo-check`（接口通道，同步）/ `POST …/geo-check/browser`（浏览器通道，异步返回 runId）/ `GET …/geo-check/run/:runId`（轮询进度与结果）/ `GET …/geo-check/status` 与 `…/geo-check/browser/status`（通道自检） |
| 榜单 API | `GET /api/v1/public/geo-ranking` 榜单（支持 `city`/`industry`/`source`/`limit` 过滤） |
| 巡检引擎 | `backend/src/services/geo-browser-probe/`（driver / session / runner / platforms / questions） |
| 平台与题库 | 外置 `backend/config/geo-probe-platforms.json`，平台地址与访问顺序可配置，不用动核心逻辑 |
| 浏览器 | Playwright 驱动本机 Chrome，专用 profile 持久化登录态 |
| 评分 | `geo-check-analyze.service.js`，三个分数各算各的，落 `visibility_score` / `foundation_score` / `measured_scope` |
| 持久化 | `geo_check_run` 批次 / `geo_check_answer` 单条回执（含截图路径）/ `geo_check_score` 评分 |
| CORS | 生产允许 `https://simplewin.cn`（配置里已有）及 `https://www.simplewin.cn` |
| 货架状态 | `GET /api/v1/public/h5/case-shelf` → `{ hasPublicCases, total }` |
| 小程序码 | `GET /api/v1/public/h5/miniprogram-code`（PNG；失败则页上只留搜一搜） |
| 小程序 | 本卷不加小程序功能；官网 / 案例站只给入口 |
| 截图 | 只做**过程留证**（巡检时自动存），不再要求用户上传。`POST …/geo-check/screenshots` 已于 2026-08-30 下线：人工截图既落地不了，又是「看图猜词」进数据的唯一入口 |
| 前端冒烟 | `npm run geo-check:page-smoke`（带桩接口，不联网不写库，16 条断言） |
