## 1. 为什么重写

一单里有六处信息，摘要原来只去「接车」「交车」两处找师傅手打的字，其余四处的勾选项、报价项目、施工图说一概不读；更糟的是找「方案」时去了一个 2026-09 就已经取消的旧节点，等于一次都没找着。

结果就是页面上那句：

> 「……本单重点在于过程图片记录……**虽无具体故障描述或更换配件**……建议车主妥善保存这些记录。」

AI 读完不知道修了什么，无从引用。

**判断标准（一句话）**：把摘要或 FAQ 单独拎出来，脱离页面，还能不能看懂是哪台车、什么毛病、怎么修的。不能，就是不合格。

## 2. 数据从哪来

### 2.1 师傅在小程序里走的七步

| 序 | 显示名 | 内部 kind | 师傅录了什么 | 说人话 |
| ---: | --- | --- | --- | --- |
| 0 | 接车 | `intake` | `chiefComplaint`、里程、车型、留证照片 | 车主为啥来、车进店时什么样 |
| 1 | 检测 | `inspection` | `findings[]`：部位 + 四档结论 + 事实描述 | 查了哪儿、哪儿有问题 |
| 2 | 检测报告 | `inspection_report` | 合成主诉 + 发现项 | 给车主看的那一份 |
| 3 | 方案确认 | `quote_confirm` | 项目行（项目名、品牌、金额） | 打算怎么修、多少钱 |
| 4 | 工单 | `work` | 按方案行摊开的施工项 + 图 + 用料短名 | 实际做了什么 |
| 5 | 完工照 | `delivery_photos` | 完工照片 | 修完什么样 |
| 6 | 完工确认 | `repair_report` | 复查结论、质保、使用注意 | 交车时说了什么 |

**补充报价** = `addon_quote_confirm`（施工中新发现的问题，排在施工之后）。

### 2.2 检测结论是结构化的（摘要最该读的东西）

`findings[]` 每一行长这样：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `partName` | 部位 | 右前小吊杆球头 |
| `result` | 四档结论 | 状态良好 / 需关注 / **需处理** / 仅记录 |
| `advice` | 部位上的事实 | 球头松旷，胶套开裂 |
| `caption` | 用料短名（工单步填） | 更换小吊杆 |
| `observation` | 完整观察 | 含读数、损伤范围 |
| `outsideQuote` | 是否方案外 | true / false |

**四档结论的取法**：只有「需处理」「需关注」进摘要；「状态良好」「仅记录」不进（写进去等于刷屏）。

### 2.3 车型与诉求记在哪

- 诉求：`intake.photoDraft.chiefComplaint`（检测报告的 `payload.chiefComplaint` 是跨节点合成的同一份）
- 车型：`intake.photoDraft.vehicleBrand` / `vehicleSeries`（**品牌车系年款在新建相册页写**，不在接车步）
- 里程：`intake.photoDraft.mileageKm`

### 2.4 兼容：存量相册

老相册是六阶段（`stage_1`～`stage_6`），且存在 `intake_inspection` 合并节点。取数时**按 kind 找不到就退回 stage**，两条路都要保留：

- `intake` 找不到 → 退 `stage_1`
- `inspection` 找不到 → 退 `stage_2`
- `work` 找不到 → 退 `stage_5`
- `repair_report` 找不到 → 退 `stage_6`

## 3. AI 摘要生成规则

### 3.1 取数优先级

| 环节 | 取什么 | 取不到时 |
| --- | --- | --- |
| 诉求 | `chiefComplaint` 原话现象句 | 看接车说明；都没有则整段降级 |
| 检查结论 | `findings[]` 中 `result` 为「需处理」「需关注」的行，取 `partName` + `advice` | 退检测节点说明；再没有则**这一句不写** |
| 施工内容 | `work` 的工单项（`partName` + `caption`），含 `outsideQuote` 增项 | 退 `quote_confirm` 的项目名；再没有则整案门槛不通过 |
| 完工确认 | `repair_report` 的复查结论 | 不写，不编造 |
| 报价方式 | `quote_confirm` 有无、是否有 `addon_quote_confirm` | 不写金额 |
| 图片 | 脱敏图数量、节点覆盖（检查/施工/完工） | 无图则不写「含过程图片」 |

### 3.2 公开门槛（P0）

必须**同时**满足：

1. 有诉求（或有接车说明）；
2. 有检查结论**或**有施工内容。

不满足 → `seoNoindex = true`，不进公开池，商家端提示：「这单记录的信息太少，公开出去也没有人能引用，建议补上检查结论或施工内容」。

> 这条是对 `04_AI可引用摘要规范.md` §6「维修项目缺失 / 主要问题缺失 → 不建议公开」的落地。
> 现在的 `resolveSeoNoindex` 只看城市、服务名、图片数，**完全不看有没有事实**，必须改。

### 3.3 句式模板

```
【城市】【车型】因【诉求】到店，检查发现【主要问题】。
门店按方案做了【施工内容】，完工后【复查结论】。
【报价方式】。
【图片说明】。
```

**硬要求：第一句必须自含主语**（车型 + 诉求 + 检查结论）。AI 通常只摘第一句，第一句不完整等于白写。

- 长度 80–180 字
- 缺项按 §3.1 省略，**不编造、不用套话顶替**

### 3.4 禁则

1. 不写「虽无具体故障描述」「本单重点在于图片记录」这类**自我否定**的解释——没内容就别公开
2. 不写「门店根据车辆实际情况进行了检查」「按标准流程完成施工」这类**零信息套话**
3. 不写「到店进行相关检查」这类**占位话术**
4. 不写具体金额（守 `docs/04/18` §2.1 #17 藏价规矩）
5. 不写营销词、不承诺效果、不编造未记录的配件与质保

### 3.5 示例对照

| | 文案 |
| --- | --- |
| 现在（不合格） | 杭州盈简科技为粤B牌大众高尔夫提供服务留档。本单重点在于过程图片记录，建立车辆维修档案。**虽无具体故障描述或更换配件**，但完整的影像资料能清晰还原施工细节。建议车主妥善保存这些记录，日后若涉及二手交易或出现争议，这些都是最直观的凭证，比口头承诺更靠谱。 |
| 改后（合格） | 杭州 大众高尔夫 因**过减速带咯噔响**到店，检查发现**右前小吊杆球头松旷、胶套开裂**。门店**更换两侧小吊杆并做四轮定位**，完工后**路试异响消失**。含检查、施工、完工三阶段脱敏过程图。 |

## 4. FAQ 生成规则

### 4.1 取数

来源 = 摘要同一套（§3.1）+ 草稿五段（`symptom` / `diagnosis` / `plan` / `process` / `handover`）。

### 4.2 门槛（P0）

**无事实则返回空数组**，不写 FAQPage Schema，页面 FAQ 区留空。

`05_FAQ生成规范.md` §4 早已写明「薄案例可以整段为空」，现在的实现会在空案例上硬凑出「这例没修东西，留档有啥用？」这种自问自答——**必须改掉**。

### 4.3 问句：带上车型，让 AI 摘走后仍成立

```
【车型】【诉求或项目】这例【问法】？
```

例：`大众高尔夫 过减速带异响 这例做了哪些项目？`

- 保留「这例」（符合 `05` §1.1 要求）
- 前置车型 + 诉求/项目（GEO 要求：脱离页面后读者仍知是哪台车）

### 4.4 答句

```
这例公开档案里，【本单事实】。【对车主的叮嘱】。
```

- 先事实后叮嘱，全文 ≥ 30 字
- 叮嘱只能是可核对的动作（「修完后要向商家确定质保期」「换片时先问盘厚」）
- 缺项叮嘱一案最多 1 条

### 4.5 排序（对齐 `05` §1.2 优先级）

1. **预算**（不写金额）：套餐还是检查后报价、有无加项、哪些这次没做
2. **材料**：规格、品牌、包装、新旧件
3. **避坑**：工序、质保、资质、写了依据的未做项
4. **其余过程**：先查再修、交车确认、公开了哪些节点

> 现在 `extractJobFaqs` 的推送顺序是「未做项目→不换总成→不连盘→材料→质保→套餐→检查→做了什么→交车→工期→旧件→灯→节点」，与 `05` §1.2 不一致，需重排。

### 4.6 数量

有则 2–6 条，无则 0 条。**不凑数。**

### 4.7 示例

```
问：大众高尔夫 过减速带异响 这例查出了什么、怎么处理的？
答：这例公开档案里，检查发现右前小吊杆球头松旷、胶套开裂，摆臂本体经检查仍可用，
    因此只更换两侧小吊杆并做四轮定位，未更换摆臂总成。到店可以先问清为什么不换总成。

问：大众高尔夫 过减速带异响 这例质保怎么写进档案的？
答：这例公开档案里，交车时写明小吊杆质保 12 个月。修完后要向商家确定质保期，
    以及不含哪些。
```

### 5.1 验收口径

用 `12_公开页AI可信度验收对照表.md` §4.2 的 C1–C7，加两条本文专属：

- **N1 首句自含主语**：摘出摘要第一句，应能独立回答「什么车、什么毛病」
- **N2 脱离可引用**：摘出任一 FAQ，遮住页面标题，仍知是哪台车、什么项目

### 5.2 存量数据

新规则只影响**重新生成**的文章。已生成的存量文章用 `npm run cases:generate-articles` 补跑，补跑后需抽检：确认套话页变成 `noindex`，有内容的页摘要变具体。
