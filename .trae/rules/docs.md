# 文档与需求变更规则（强制）

## 1. 唯一入口

- 读文档从 `docs/README.md` 进，按索引跳转；不要全库 grep 文档，也不按文件名猜。
- `docs/_归档/` 与状态头为「已废止」的文档只能当历史参考，**不得作为口径依据**。

## 2. 需求变化先写变更单

任何口径变化（新增、删除、改判定、改字段），先在 `docs/changes/YYYYMMDD-短标题.md` 写一张变更单，再动代码。最小结构：

- **变更**：旧口径 → 新口径（一句话能对上）
- **影响**：文档 / 字段 / 接口 / 代码路径
- **取代**：哪些旧文档或旧章节作废（写路径；整篇作废的移入 `docs/_归档/`）
- **验证**：对应测试文件或接口

## 3. 文档状态头

被动过的文档，头部必须有：

```
> 状态：生效 ｜ 已废止（被 docs/changes/xxx.md 取代）
> 生效：YYYY-MM-DD
> 适用：关键常量 / 接口 / 提交号（可选）
```

- 正文**不再追加**「修订：日期 · …」式历史，历史只进变更单。
- 整篇作废：移入 `docs/_归档/`，原位置不留副本。
- 局部作废：在该章节标题下加一行「> 已废止，见 docs/changes/xxx.md」，不要就地改写旧叙述。

## 4. 冲突与真源

口径真源顺序：

```
测试 > 代码常量/接口 > docs/changes 最新 > docs 正文 > _归档
```

文档与代码不一致时以代码为准，并把差异补进当期变更单，**不要用旧文档去「纠正」代码**。

## 5. 提交门槛

- 同一提交内必须包含 `docs/changes/` 变更单；只改代码不改文档视为未完成。
- 提交前执行 `node scripts/check-docs.js`，硬错误必须清零。
- 可选硬拦截：`git config core.hooksPath scripts/git-hooks`（改到 `docs/` 时自动跑体检）。
